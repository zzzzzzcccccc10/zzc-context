# 小恋项目 · 上下文与决策档案（私有）

> 这个仓库不是代码仓库。代码与交付材料在公开仓库 `zzc`（`reviews/` 下按阶段存档）。
> 这里放的是「换一个对话也能恢复项目现状」所需的东西：合作机制、架构、封版与部署状态、已批准/否决的决定、安全边界、最近交接。
>
> 原则：
> - 只存**整理过的决定和事实**，不存原始聊天记录。
> - 每条状态都带日期与证据来源（commit、交付文件、日志）。
> - 敏感信息（服务器地址、密钥、真实聊天内容）不写进来。

## 目录

| 文件 | 作用 |
|---|---|
| `COOPERATION.md` | 三方分工、工作流程、审批权限、验收原则 |
| `PROJECT_STATUS.md` | 各模块真实状态：封版 / 部署 / 施工中 |
| `ARCHITECTURE.md` | 总体架构与关键数据流 |
| `SECURITY_BOUNDARIES.md` | 安全边界、已知风险、红线 |
| `DECISIONS/` | 分阶段决策记录（P0、B0.5、B1、P1-recall-boost…） |
| `HANDOFF.md` | 最近一次交接：SHA、结论、遗留、下一步 |

## 更新规则

1. 阶段状态变化（批准 / 部署 / 封版 / 回滚）→ 更新 `PROJECT_STATUS.md` 和 `HANDOFF.md`。
2. 产生新的「已批准/已否决」决定 → 在 `DECISIONS/` 加一节，写清理由和被否掉的备选。
3. 安全边界变化 → 更新 `SECURITY_BOUNDARIES.md`，并在 `HANDOFF.md` 标注。
4. 每次更新提交信息带日期与阶段，例如 `status: P1-A1 v4 待复审（2026-11-18）`。
