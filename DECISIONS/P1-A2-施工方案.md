## 二、fail-closed 设计（返修重点 1）

### 2.1 两条调用链

**链路 A：主回复管道（`guard` hook，priority −1000000）**

```
try:
    new_text = _clean_segment(text)          # 内部不吞异常
except Exception as e:
    logger.warning(f"[tool_xml_guard] 清洗失败（{type(e).__name__}）req={_rid(event)}")
    event.stop_event()                       # 停止后续发送
    result.chain = []                        # 清空待发送内容
    return
# 正常：写回清洗后的文本
```

**链路 B：`multi_bubble` 拆分前清洗**
- `multi_bubble.on_llm_resp` 调 `finalize_text`；异常时**取消拆分**（现有行为），原文交给管道。
- 管道里 `tool_xml_guard` 再失败 → 走链路 A 的 stop。
- 因此"拆分前清洗失败"本身不发送未清洗内容；最终屏障是链路 A。

### 2.2 硬规则

1. `finalize_text()` **不捕获异常**，异常向上抛。
2. 调用方捕获后**不得返回原文**、不得用未清洗 fallback。
3. 日志只记 `type(e).__name__` + `req`，不记正文。
4. 测试必须证明"没有消息发出"，不是"没有崩溃"。

## 三、区间模型（返修重点 4）

### 3.1 三种区间，类型分开

| 类型 | 来源 | 是否参与 R1 相交判定 |
|---|---|---|
| `CODE` | 围栏、行内代码 | **是** |
| `QUOTE` | 成对引号（同段落） | **是** |
| `SYNTAX` | DSML 标签语法区间（含属性值引号） | **否**（属性解析用，不算保护区） |

### 3.2 四阶段计算（解决循环依赖）

```
阶段 A：_code_regions(text)                       → CODE 区间
阶段 B：在 CODE 区间之外扫描 DSML 标记 + 属性扫描   → SYNTAX 区间
阶段 C：_quote_regions(text, exclude=SYNTAX)      → QUOTE 区间（排除落在语法区间内的引号）
阶段 D：保护集合 = CODE + QUOTE；按第五节顺序清理
```

- 阶段 B 跳过 CODE 区间的原因：代码块里的 DSML 不处理，不需要语法区间。
- 阶段 C 排除 SYNTAX 的原因：`name="a>b"` 的引号属于属性语法，不能算正文引用（v7 案例 #24）。
- R1 与保护区相交判定只用 `CODE + QUOTE`。

## 四、解析器设计

### 4.1 `_scan_attrs(text, start) -> (status, end)`

| 状态 | 含义 | 后续 |
|---|---|---|
| `FOUND_END` | 找到引号外的 `>` | 正常 R2-A / R1 起始标签 |
| `UNTERMINATED_ATTRIBUTE` | 属性值引号未闭合 | R1 → H1 跳过到末尾；R2 → R2-B |
| `MISSING_END` | 无属性引号但也没有 `>` | R1 → 按不完整起始标签保守处理；R2 → R2-B |

区分的意义：`UNTERMINATED_ATTRIBUTE` 说明结构被截断且无法确定边界；`MISSING_END` 可能只是没写完。

### 4.2 `_find_marker(text, pos)`：五形态（含闭合）

```
1. "<" + 双竖线 + DSML + 双竖线 + "/"   → close_double（闭合标签）
2. "<" + 单竖线 + DSML + 单竖线 + "/"   → close_single
3. "<" + 双竖线 + DSML + 双竖线         → open_double
4. "<" + 单竖线 + DSML + 单竖线         → open_single
5. 双竖线 + DSML + 双竖线 / 单竖线 + DSML + 单竖线 → marker_double / marker_single
```

约束：
- 长优先，双竖线先匹配；匹配成功即跳过整个标记。
- 闭合标签必须作为**整体语法单元**：`</｜｜DSML｜｜ tag>`（标签名按 2.2 完整匹配，不允许属性）。
- 未被识别为闭合标签的 `<...` 不进入栈逻辑。

### 4.3 `_match_r1(text, pos) -> MatchResult`

返回对象字段：`kind`、`start`、`end`、`skip_to`（异常时跳过区间终点）。

| kind | 判定 | 行为 | 跳过范围 |
|---|---|---|---|
| `COMPLETE` | 栈完整配对（含正确嵌套） | 删 `[start, end)` | — |
| `UNCLOSED_SINGLE` | 单层一个起始、无任何闭合 | 只删起始标签 `[start, end)` | — |
| `ORPHAN_CLOSE` | 栈空时遇到闭合 | 不删 | — |
| `MISMATCH` | 栈非空、闭合与栈顶不同名 | **不删** | `[start, 该闭合标签末尾)` |
| `NESTED_UNCLOSED` | 存在嵌套且未闭合 / 顺序错乱 | **不删** | `[start, 文本末尾)` |
| `CROSS_PARAGRAPH` | 外层跨段 | 只删外层起始标签 | — |
| `ATTR_UNTERMINATED` | 起始标签属性未闭合 | 不删 | `[start, 文本末尾)`（H1） |

**关键修正**：
- 栈非空错名 → `MISMATCH`（不删），**不归类 R1-d**。
- 嵌套未闭合 → `NESTED_UNCLOSED`（不删），**不套用 C1**；C1 只给真正的单层有起无闭。
- 每种异常都返回 `skip_to`，`_clean_segment` 跳到该位置，不回流 R2/R3。

## 五、清理主循环

```
regions = CODE + QUOTE
i = 0
while i < len(text):
    若 i 在 regions 内：i = 该区间末尾; continue
    m = _find_marker(text, i)
    若 m is None：i += 1; continue
    若 m.start 在 regions 内：i = m.end; continue
    match = _match_r1(...) 或按 R2/R3 处理
    若需要跳过：i = match.skip_to; continue
    否则替换并 i = 替换后位置
```

## 六、半角双引号与转义

- **保持 v7**：半角双引号 `""` 纳入 QUOTE 保护区，不缩小范围。
- **转义规则**：`"` 前面有**奇数个连续反斜杠** → 视为已转义，不参与配对；偶数个 → 参与。
- 测试三类：普通 JSON 字符串、含 `\"` 的 JSON、未闭合双引号（不保护）。
