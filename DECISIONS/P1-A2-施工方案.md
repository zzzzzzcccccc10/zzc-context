## 二、fail-closed 设计

### 2.1 复用 `_stop()`

现有 `ToolXmlGuard._stop(event)` 已实现"先尝试清空 `result.chain`，再独立尝试 `stop_event()`"，两步各自 try，避免 stop_event 抛异常时清链没执行。v3 直接复用，不重新拼装：

```
try:
    new_text = _clean_segment(text)
except Exception as e:
    logger.warning(f"[tool_xml_guard] 清洗失败（{type(e).__name__}）req={_rid(event)}")
    self._stop(event)     # 复用现有方法
    return
```

### 2.2 两条调用链

- **链路 A（主管道 `guard`）**：异常 → `_stop(event)` → 该条消息不发送。
- **链路 B（`multi_bubble` 拆前清洗）**：`finalize_text` 异常 → 取消拆分，原文交给管道；管道再失败 → 链路 A 的 `_stop`。

### 2.3 硬规则

1. `finalize_text()` 不捕获异常。
2. 调用方不得返回原文、不得用未清洗 fallback。
3. 日志只记类型 + req。
4. 测试证明两条链路在清洗持续失败时**发送次数为 0**。

## 三、区间模型

### 3.1 三种区间

| 类型 | 来源 | 参与 R1 相交判定 |
|---|---|---|
| `CODE` | 围栏、行内代码 | 是 |
| `QUOTE` | 成对引号（同段落） | 是 |
| `SYNTAX` | DSML 标签语法区间 | 否 |

### 3.2 四阶段 + 交叠处理（v3 明确）

```
阶段 A：CODE = _code_regions(text)
阶段 B：在 CODE 外扫描 DSML 标记 → SYNTAX 区间
阶段 C：QUOTE = _quote_regions(text)
        对每一对引号：
          若该对引号的两端都落在同一个 SYNTAX 区间内 → 不产生 QUOTE（属性语法引号）
          否则 → 产生 QUOTE（正文引用）
阶段 D：保护集合 = CODE ∪ QUOTE；按第五节清理
```

**交叠原则**：只排除"两端都在 SYNTAX 内"的引号对，**不因为 QUOTE 区间与 SYNTAX 区间相交就丢弃整个外层引用**。

例：`「<｜｜DSML｜｜ calls>示例</｜｜DSML｜｜ calls>」`
- 外层 `「」` 的两端在 SYNTAX 区间**之外** → 产生 QUOTE → 整段保留。

## 四、解析器设计

### 4.1 `_scan_attrs(text, start) -> (status, end)`

| 状态 | 含义 | R1 行为 | R2 行为 |
|---|---|---|---|
| `FOUND_END` | 引号外有 `>` | 正常起始标签 | R2-A |
| `UNTERMINATED_ATTRIBUTE` | 属性值引号未闭合 | H1：不删、跳过到文本末尾 | R2-B |
| `MISSING_END` | 无属性引号也没有 `>` | **不删任何字符、不套 C1、跳过到文本末尾** | R2-B |

`MISSING_END` 明确为：删除范围 0，`skip_to = len(text)`；不删部分标签（如只删 `<` 或只删标签名）。

### 4.2 `_find_marker`：五形态（v3 修正闭合顺序）

```
1. "<" + "/" + 双竖线 + DSML + 双竖线   → close_double
2. "<" + "/" + 单竖线 + DSML + 单竖线   → close_single
3. "<" + 双竖线 + DSML + 双竖线         → open_double
4. "<" + 单竖线 + DSML + 单竖线         → open_single
5. 双竖线 + DSML + 双竖线 / 单竖线 + DSML + 单竖线 → marker_double / marker_single
```

- 闭合标签 = `<` + `/` + 竖线 + `DSML` + 竖线，`/` **紧跟在 `<` 之后**。
- **`close_single` 不进入 R1 栈式配对**：v7 的 R1 只定义双竖线闭合；单竖线只定义 R2/R3。
  - 其内部 `｜DSML｜` 会按 R2/R3 处理，可能留下 `</` 前缀残片。
  - 这是 v7 规则的直接后果，如实记录，不扩大规则；如有需要由主人裁定是否把单竖线闭合纳入 R1。
- 长优先、双竖线先匹配；匹配成功跳过整个标记。

### 4.3 `_match_r1(text, pos) -> MatchResult`

| kind | 判定 | 删除 | skip_to |
|---|---|---|---|
| `COMPLETE` | 栈完整配对 | `[start,end)`（需通过相交检查） | 删除后继续 |
| `UNCLOSED_SINGLE` | 单层起始、无任何闭合 | 只删起始标签 | 删除后继续 |
| `ORPHAN_CLOSE` | 栈空时遇到闭合 | 不删 | **孤立闭合标签末尾** |
| `MISMATCH` | 栈非空、闭合与栈顶不同名 | 不删 | 该闭合标签末尾 |
| `NESTED_UNCLOSED` | 嵌套未闭合 / 顺序错乱 | 不删 | 文本末尾 |
| `CROSS_PARAGRAPH` | 外层跨段 | 只删外层起始标签 | 删除后继续 |
| `ATTR_UNTERMINATED` | 起始标签属性未闭合 | 不删 | 文本末尾 |

- `MISMATCH` 与 `ORPHAN_CLOSE` 的区别：前者栈非空（嵌套错配），后者栈空（孤立闭合）。
- 嵌套未闭合不套 C1；C1 只给 `UNCLOSED_SINGLE`。
- 所有异常 `skip_to` 之后不再交给 R2/R3。

## 五、清理主循环（v3 加相交检查）

```
regions = CODE ∪ QUOTE
i = 0
while i < len(text):
    若 i 在 regions 内：i = 该区间末尾; continue
    m = _find_marker(text, i)
    若 m 为 None：i += 1; continue
    若 m.start 在 regions 内：i = m.end; continue

    match = _match_r1(text, i)
    若 match.kind == COMPLETE:
        若 [match.start, match.end) 与 regions 有重叠：     # R1-f
            不删除；i = match.end; continue
    若 match.kind in (ORPHAN_CLOSE, MISMATCH, NESTED_UNCLOSED, ATTR_UNTERMINATED):
        i = match.skip_to; continue
    若 match.kind == UNCLOSED_SINGLE / CROSS_PARAGRAPH:
        删除起始标签；i = 删除后位置; continue

    否则按 R2/R3 处理（同样先查起点是否在 regions）
```

**R1-f 要点**：相交判断用 `[match.start, match.end)` 与 `CODE∪QUOTE` 的**区间重叠**，不是只查起点。覆盖 v7 #21：起始标记在保护区外、引号/代码在结构内部 → 整段跳过、不回流。
