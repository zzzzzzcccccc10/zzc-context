## 二、fail-closed 设计

### 2.1 复用 `_stop(event, why)`

现有签名：`def _stop(self, event, why: str)`。v4 按实际签名调用：

```
try:
    new_text = _clean_segment(text)
except Exception as e:
    # 不在调用前重复记录；why 交给 _stop 记
    self._stop(event, f"清洗异常（{type(e).__name__}）")
    return
```

- `_stop` 内部：先尝试清空 `result.chain`，再独立尝试 `stop_event()`（两步各自 try）。
- `why` 只含异常类型，不含正文。

### 2.2 两条调用链

- **链路 A（主管道 `guard`）**：异常 → `_stop(event, why)` → 该条消息不发送。
- **链路 B（`multi_bubble` 拆前清洗）**：`finalize_text` 异常 → 取消拆分，原文交给管道；管道再失败 → 链路 A。

### 2.3 硬规则

1. `finalize_text()` 不捕获异常。
2. 调用方不得返回原文、不得用未清洗 fallback。
3. 日志只记类型 + req，不记正文。
4. 测试证明两条链路在清洗持续失败时**发送次数为 0**。

## 三、区间模型

### 3.1 三种区间

| 类型 | 来源 | 参与 R1 相交判定 |
|---|---|---|
| `CODE` | 围栏、行内代码 | 是 |
| `QUOTE` | 成对引号（同段落） | 是 |
| `SYNTAX` | DSML 标签语法区间 | 否 |

### 3.2 SYNTAX 区间边界（v4 明确）

| 标签 | 区间 |
|---|---|
| 起始标签 | 从控制标记起点（`<` 或裸标记首字符）到属性扫描确定的 `>` **之前**（不含 `>`），**包含属性值引号** |
| 闭合标签 | 从 `</` 到 `>`（不含 `>`），作为完整语法区间 |

- 属性值引号（`name="a>b"` 的两个 `"`）落在起始标签的 SYNTAX 区间内 → 不产生 QUOTE。
- 闭合标签整体作为一个 SYNTAX 区间，其内部不产生 QUOTE，也不交给 R2/R3。

### 3.3 四阶段

```
阶段 A：CODE = _code_regions(text)
阶段 B：在 CODE 外扫描 DSML 标记 → SYNTAX 区间（起始 + 闭合）
阶段 C：QUOTE = _quote_regions(text)
        每对引号：两端都在同一 SYNTAX 内 → 不产生 QUOTE；否则产生 QUOTE
阶段 D：保护集合 = CODE ∪ QUOTE；按第五节清理
```

**交叠原则**：只排除"两端都在 SYNTAX 内"的引号对，不丢弃与 SYNTAX 相交的外层引用。

例：`「<｜｜DSML｜｜ calls>示例</｜｜DSML｜｜ calls>」` → 外层 `「」` 两端在 SYNTAX 外 → QUOTE 覆盖整段 → 保留。

## 四、解析器设计

### 4.1 `_scan_attrs(text, start) -> (status, end)`

| 状态 | 含义 | R1 行为 | R2 行为 |
|---|---|---|---|
| `FOUND_END` | 引号外有 `>` | 正常起始标签 | R2-A |
| `UNTERMINATED_ATTRIBUTE` | 属性值引号未闭合 | H1：不删、跳过到文本末尾 | R2-B |
| `MISSING_END` | 无属性引号也没有 `>` | 不删任何字符、不套 C1、跳过到文本末尾 | R2-B |

### 4.2 `_find_marker`：五形态

```
1. "<" + "/" + 双竖线 + DSML + 双竖线   → close_double
2. "<" + "/" + 单竖线 + DSML + 单竖线   → close_single
3. "<" + 双竖线 + DSML + 双竖线         → open_double
4. "<" + 单竖线 + DSML + 单竖线         → open_single
5. 裸标记双/单                          → marker_double / marker_single
```

**单竖线闭合（v4 裁定后的行为）**：
- 不参与 R1 栈式配对（v7 的 R1 只处理双竖线）。
- 但**完整 `close_single` 作为不可拆分的语法单元整体保留**：从 `</` 到 `>` 标记为 `ORPHAN_CLOSE_SINGLE`，不删、不把内部标记交给 R2/R3，避免残留 `</`。
- 不扩展单竖线嵌套配对。

### 4.3 `_match_r1(text, pos) -> MatchResult`

| kind | 判定 | 删除 | skip_to |
|---|---|---|---|
| `COMPLETE` | 栈完整配对 | `[start,end)`（需通过相交检查） | 删除后继续 |
| `UNCLOSED_SINGLE` | 单层起始、无任何闭合 | 只删起始标签 | 删除后继续 |
| `ORPHAN_CLOSE` | 栈空时遇到双竖线闭合 | 不删 | 孤立闭合标签末尾 |
| `ORPHAN_CLOSE_SINGLE` | 单竖线闭合（整体保留） | 不删 | 该闭合标签末尾 |
| `MISMATCH` | 栈非空、闭合与栈顶不同名 | 不删 | 该闭合标签末尾 |
| `NESTED_UNCLOSED` | 嵌套未闭合 / 顺序错乱 | 不删 | 文本末尾 |
| `CROSS_PARAGRAPH` | 外层跨段 | 只删外层起始标签 | 删除后继续 |
| `ATTR_UNTERMINATED` | 起始标签属性未闭合 | 不删 | 文本末尾 |

## 五、清理主循环

```
regions = CODE ∪ QUOTE
i = 0
while i < len(text):
    若 i 在 regions 内：i = 该区间末尾; continue
    m = _find_marker(text, i)
    若 m 为 None：i += 1; continue
    若 m.start 在 regions 内：i = m.end; continue

    match = _match_r1(text, i)
    若 match.kind == COMPLETE:
        若 [match.start, match.end) 与 regions 有重叠：    # R1-f
            不删除；i = match.end; continue
    若 match.kind in (ORPHAN_CLOSE, ORPHAN_CLOSE_SINGLE, MISMATCH,
                      NESTED_UNCLOSED, ATTR_UNTERMINATED):
        i = match.skip_to; continue
    若 match.kind in (UNCLOSED_SINGLE, CROSS_PARAGRAPH):
        删除起始标签；i = 删除后位置; continue

    否则按 R2/R3 处理（同样先查起点是否在 regions）
```
