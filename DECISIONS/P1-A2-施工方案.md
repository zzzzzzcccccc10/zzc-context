## 一、目标

让 `finalize_text()` 按 v7 规范处理裸 DSML 标记：
- 保护区（围栏/行内代码/成对引号）内一律不动；
- 能明确识别的控制结构删干净；
- 边界不明确的一律不猜、不删（宁留标记）；
- 删除后空白逐字保留（只删该删的字符）。

## 二、实现结构（函数级）

### 2.1 新增/替换的组件

| 组件 | 职责 | 对应规范 |
|---|---|---|
| `_regions(text)` | 返回保护区列表（围栏、行内代码、成对引号） | R4、7.1、7.2 |
| `_in_regions(pos, regions)` | 判断位置是否在保护区内 | R4 起点判定 |
| `_scan_attrs(text, start)` | 属性扫描：返回结束符 `>` 位置或 None | 7.3、3.4 |
| `_find_marker(text, pos)` | 长优先匹配四种形态，返回 (start, end, kind) | 2.1 |
| `_full_label(text, pos)` | 白名单完整匹配，返回标签名或 None | 2.2 |
| `_match_r1(text, pos)` | 栈式配对，返回 (start, end) 或 None | R1-a～h |
| `_clean_segment(text)` | 按第四节顺序扫描处理 | 第四节 |

### 2.2 保护区（R4）

1. **围栏**：沿用现有 `_FENCE_OPEN` / `_code_regions`（按行识别、同字符、长度≥、未闭合保护到末尾）。
2. **行内代码**：扫反引号对，`\`` 不闭合；不允许跨行。
3. **成对引号**：`“”`、`‘’`、`「」`、`『』`、`""`（不含 `'`）；
   - 同段落配对：扫描到空行（`\n[ \t\r]*\n`）即停止；
   - 找不到闭合 → 不产生保护区。
4. 合并区间、去重、按起点排序。

### 2.3 属性扫描（7.3 / 3.4）

```
从 start 开始：
  跳过整个字符串里的引号对：
    只在遇到 属性名= 之后的引号时才"开启"（属性名 [A-Za-z_][A-Za-z0-9_\-:]*）
    开启后找同名引号闭合；找不到 → 返回 None（触发 R1-h / R2-B）
  遇到引号外的第一个 > → 返回该位置
  到末尾 → None
```

**语法区间**：从标记起点到 `_scan_attrs` 返回的 `>`（不含）。该区间内不产生引号保护区。

### 2.4 标记匹配（2.1 长优先）

一次扫描中，在每个位置按顺序尝试：

```
1. "<" + 双竖线 + "DSML" + 双竖线   → kind="r1_open"
2. "<" + 单竖线 + "DSML" + 单竖线   → kind="r2_single_open"
3. 双竖线 + "DSML" + 双竖线         → kind="marker_double"
4. 单竖线 + "DSML" + 单竖线         → kind="marker_single"
```

关键约束：双竖线匹配成功后，**位置跳过整个标记**，单竖线规则不得再从中间截取。
实现上用手写扫描（逐字符），不用可能重叠的正则。

### 2.5 R1 栈式配对

```
扫描找到起始标签（需白名单标签 + 属性扫描得到 >）
  → push 到栈
找到闭合标签（< / 双竖线 DSML 双竖线 空白 同名标签 >，不允许属性）
  → 若栈顶同名：配对成功，记录区间
  → 若不同名/栈空：判定为 R1-d（孤立闭合），不删除
段落边界：配对不得跨空行；跨段 → 视为不完整（R1-e）
结束时：
  栈空且全部配对 → 删外层整段
  栈非空 → 有起无闭 → R1-c：只删起始标签，保留正文
  起止不匹配 → R1-a：整段不处理
```

### 2.6 R2 / R3

- 标记后按 2.2 完整匹配白名单标签：
  - 有 `>`（`_scan_attrs` 成功）→ 删到 `>`（R2-A）
  - 无 `>` 或属性未闭合 → 只删标记 + 标签名（R2-B）
- 没有完整标签 → 只删标记（R3）
- **不 strip、不合并空格、不清行尾**（现有 `_tidy_deleted` 保持逐字逻辑）。

### 2.7 处理顺序

```
regions = _regions(text)
i = 0
while i < len(text):
    尝试在 i 处匹配标记（长优先）
    若标记起点在 regions 内 → i 跳过该标记，继续
    否则按 R1/R2/R3 处理：
        R1 需要栈式配对结果；与保护区相交 → 整体跳过并标记区间
        被跳过的区间：跳过到区间末尾，不再处理内部
    i 前进
```

## 三、测试矩阵

### 3.1 规范 31 条正反例

### 3.2 新增边界（施工必须覆盖）

| 类别 | 用例 |
|---|---|
| 保护区 | 围栏内双/单竖线、行内代码、引号内（含跨段不保护、CRLF 空行） |
| 语法区间 | `name="a>b"` 内 `>` 不截断；`name='a>b'`；属性未闭合回退 |
| R1 栈 | 完整嵌套；起止不匹配；有起无闭；孤立闭合；跨段 |
| 单竖线 | `｜DSML｜ calls>` 正常删；`｜｜DSML｜｜` 不被单竖线截取；保护区内不处理 |
| 空白 | 删后三空格/两空格/行尾空格逐一断言；不 strip |
| 幂等 | `finalize_text(finalize_text(x)) == finalize_text(x)` |
| 误删防护 | `他说的 don't`、`价格 </ 3`、普通英文句子、JSON 片段 |
| fail-closed | 处理异常 → 返回原文 + 日志只记类型 |
| CRLF | 围栏闭合、段落空行、换行形式不变 |

## 四、验收标准

1. 全部测试 PASS，退出码 0。
2. 幂等：连续两次清洗结果一致。
3. 不误删：`don't`、`owners'`、`</`、普通英文、JSON 片段原样。
4. 保护区：围栏/行内代码/引号内内容逐字不变。
5. 空白：删除只发生在明确位置，其余字符（含行尾空格、CRLF）不变。
6. 日志：只记异常类型 + req，不记正文。
7. 性能：单轮 `finalize_text` 对 5KB 文本 < 10ms（本地实测）。
8. `multi_bubble` 不改（Git blob 与 v4/v5/v6 相同）。

## 六、风险与边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 引号保护区误保护 | 半角 `""` 在 JSON/代码里很常见，可能保护本应清理的标记 | 接受（保守优先）；测试覆盖 JSON 场景，必要时后续评估 |
| 性能 | 逐字符扫描 | 文本通常 < 2KB；实测 < 10ms；超长文本可加长度上限 |
| 与 `multi_bubble` 逻辑重复 | 两处都清洗 | 共用同一 `finalize_text`，不重复实现 |
| 真机不可控 | 模型可能改写标记 | 不依赖真机触发；以测试 + 隔离行为验证为准 |
