## 二、术语与白名单

### 2.1 控制标记形态（只承认双竖线）

| 形态 | 例子 | 说明 |
|---|---|---|
| 完整结构 | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` | R1 |
| 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ invoke name="x">` | R2 |
| 裸标记单独 | `｜｜DSML｜｜`（后面不是白名单标签） | R3 |
| 残缺 / 截断 | `｜｜DSML｜｜ calls`（无 `>`） | R2-B |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C），**必须是双竖线**。`DSML` 大小写不敏感。

> 单竖线不属本规范形态（源码有既有处理，待裁定）。

### 2.2 白名单标签的完整匹配

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

1. **完整字符串匹配**（大小写不敏感），不得前缀匹配。
2. 合法边界只有四种：空白（空格/Tab）、`>`、`/`、行尾。
3. `callsxyz`、`calls_old`、`tool_calls`、`invoke2` 都不算（按 R3 只删标记）。
4. `antml:invoke` 整串匹配。
5. 标签名后允许空白再跟属性。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记的**匹配起点**落在以下任一区域内。

1. **围栏代码块**：行首（≤3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行；行内 `` \` `` 不视为闭合。
3. **成对引号内**：`“”`、`‘’`、`「」`、`『』`、半角双引号 `""`（不含 ASCII `'`）。

**行为**：起点在保护区内 → 该匹配整个跳过。

**边界规则**：
- 引号必须成对；找不到闭合时不保护。
- **跨行配对（7.1 = B）**：限同一段落；空行 = `\n[ \t\r]*\n`；CRLF 的 `\r\n\r\n` 同样是段落边界。
- 嵌套引号：内外都保护，不得跨段落。
- **属性语法引号不属于 R4 保护区**：见 3.4（v5 新增）。

### 3.4 属性语法引号与正文引用引号的分界（v5 新增，解决 R1-f 冲突）

**定义**：DSML 标签的**语法区间** = 从控制标记起点（`<｜｜DSML｜｜` 或 `｜｜DSML｜｜`）开始，
到按第六节扫描确定的**结束符 `>`**（不含）为止。

**规则**：
1. 语法区间内的引号（例如 `name="a>b"` 中的两个 `"`）是**语法属性引号**，属于 DSML 属性解析，
   **不计入 R4 的自然语言引用保护区**。
2. 语法区间**之外**的成对引号，才按 R4 保护用户内容。
3. 因此 `name="a>b"` 不会让 R1 删除区间与 R4 保护区相交——案例 #24 仍整段删除。
4. 语法区间的判定依赖第六节的属性扫描；扫描失败（属性未闭合）时见 6.6 的独立规则。

### R1：完整结构

**起始标签**：`<` + 双竖线 + `DSML` + 双竖线 + 空白 + **白名单标签** + 可选属性 + `>`。
**闭合标签**：`<` + `/` + 双竖线 + `DSML` + 双竖线 + 空白 + **同名白名单标签** + `>`。
- 起止标签名必须**同名**，大小写不敏感。
- **闭合标签不允许属性**。
- **起始标签的 `>` 按第六节属性扫描识别**。

**删除范围**：从起始 `<` 到闭合结构最后的 `>`，整段删除（受第七节 R1-f 约束）。

**示例**：
- `前缀A <｜｜DSML｜｜ calls>正文</｜｜DSML｜｜ calls> 后缀B` → `前缀A  后缀B`
- `<｜｜DSML｜｜ calls name="a>b">正文</｜｜DSML｜｜ calls>` → 整段删除
  （属性引号是语法引号，不触发 R4 相交，见 3.4）

### R2：裸标记 + 白名单标签（选 B）

**匹配条件**：`｜｜DSML｜｜` 后紧跟（可隔空白）按 2.2 完整匹配的标签名。

**分支 A（有结束符）**：删到结束符 `>`（含），按第六节识别；`>` 之后保留；禁止删到行尾。

**分支 B（无结束符 / 属性引号未闭合）**：只删 ① `｜｜DSML｜｜`；② 紧跟其后的白名单标签名本身。其余逐字保留。

**示例**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A   后缀文字`（三空格）

### R3：裸标记单独出现（选 A）

**匹配条件**：`｜｜DSML｜｜` 后不是按 2.2 完整匹配的标签。

**删除范围**：只删 `｜｜DSML｜｜`。**空白规则**：不合并、不 strip、不清行尾、不改换行。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `

## 四、优先级与处理顺序

```
0. 语法区间判定（第六节属性扫描）
     → 语法区间内的引号不算 R4 保护区（3.4）
1. R4 起点判定
     起点在保护区内 → 匹配跳过，区间标记为「本轮不再处理」
2. R1
     属性未闭合 → 整个候选结构不处理（6.6）；跳过区间 = 起始 < 到文本末尾（6.6.1）
     删除区间与保护区相交 → 见第七节 R1-f（待裁定）；跳过则标记「本轮不再处理」
3. R2
4. R3
被标记「本轮不再处理」的区间，R2/R3 不得再匹配其中的标记。
```

**冲突检查结论**：
1. R2 与 R3 互斥：是否跟完整匹配的白名单标签。
2. R1 先于 R2/R3。
3. R4 起点优先；R1 跳过的区间不回流 R2/R3。
4. 属性语法引号与正文引用引号分离（3.4），R1 与 R4 不再因 `name="a>b"` 冲突。
5. R2-B 禁止猜测；R3 不吞后文。

## 六、`>` 的识别（7.3）

**适用范围**：R2-A 的结束符、R1 起始标签的结束符共用同一套扫描。

**规则**：
1. 从标记（或 `<`）之后扫描，直到"引号外第一个 `>`"。
2. **只有完整属性赋值语法才开启属性值**：`属性名 = "值"` / `属性名 = '值'`；
   属性名 `[A-Za-z_][A-Za-z0-9_\-:]*`，`=` 两侧允许空白。
3. 开启后跳到同名引号闭合处；属性值内 `>` 不参与结束符判断。
4. 普通撇号（`don't`、`owners'`）前面没有 `属性名=`，不开启属性值。
5. 只有引号外的第一个 `>` 才是结束符。

### 6.6 R1 起始标签属性未闭合（v5 新增，独立规则）

**问题**：R2-B 的对象是裸标记 `｜｜DSML｜｜ invoke name="a>b`；R1 的起始标签是 `<｜｜DSML｜｜ calls name="a>b`。
直接套 R2-B 会删掉标记与标签名，留下孤立的 `<` 和属性残片（如 `< name="a>b`），比不处理更糟。

**规则（保守）**：
- 识别：R1 起始标签在扫描到文本末尾仍未找到引号外的 `>`，且存在未闭合的属性值引号。
- 行为：**整个候选结构原样不处理**（`<`、标记、标签名、属性全部保留），记录日志（含 req）。
- **不得**套用 R2-B，也不得单独删除标记或标签名。
- 该候选区间标记为「本轮不再处理」，R2/R3 不得再处理。

### 6.6.1 跳过区间的边界（v6 明确）

R1-h 的跳过区间**从起始 `<` 开始，延伸到当前文本末尾**。

- 该区间内出现的**所有** DSML 标记（包括后续可能成形的裸标记）都不得再交给 R2/R3 处理。
- 理由：属性未闭合意味着无法确定这个标签语法到哪里结束；若只跳过"局部"而让 R2/R3 处理后面的标记，可能把本来属于同一条残缺结构的文本删掉。
- 与 R1-f 的区别：R1-h 是"结构本身不完整"（无法确定边界），R1-f 是"结构完整但与保护区相交"（边界确定，只是冲突）。

**状态**：登记为第七节 **R1-h**，待裁定；裁定前按上述保守行为（整体不处理 + 区间到文本末尾）。
