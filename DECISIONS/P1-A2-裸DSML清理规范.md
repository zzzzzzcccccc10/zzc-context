## 二、术语与白名单

### 2.1 控制标记形态（规范只承认双竖线）

| 形态 | 例子 | 说明 |
|---|---|---|
| 完整结构 | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` | R1 |
| 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ invoke name="x">` | R2 |
| 裸标记单独 | `｜｜DSML｜｜`（后面不是白名单标签） | R3 |
| 残缺 / 截断 | `｜｜DSML｜｜ calls`（无 `>`） | R2-B |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C），**必须是双竖线**（左右各 1 个字符）。
`DSML` 大小写不敏感。

> 单竖线不属本规范形态（源码有既有处理，待裁定）。

### 2.2 白名单标签的完整匹配

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

1. 必须**完整字符串匹配**（大小写不敏感），不得前缀匹配。
2. 合法边界只有四种：空白（空格/Tab）、`>`、`/`、行尾（`\n` 或文本末尾）。
3. `callsxyz`、`calls_old`、`tool_calls`、`invoke2` **都不算**白名单标签（按 R3 只删标记）。
4. `antml:invoke` 按整串匹配，`:` 之后必须是合法边界。
5. 标签名后允许空白再跟属性（`invoke  name="x">`）。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记的**匹配起点**落在以下任一区域内。

1. **围栏代码块**：行首（≤3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行。
   - **反引号转义（v4 恢复）**：行内代码内的 `` \` ``（反斜杠 + 反引号）**不视为闭合**。
3. **成对引号内**：`“”`、`‘’`、`「」`、`『』`、半角双引号 `""`（不含 ASCII `'`）。

**行为**：起点在保护区内 → 该匹配整个跳过。

**边界规则**：
- 引号必须成对；找不到闭合时不保护。
- **跨行配对（7.1 = B）**：限同一段落。
  - **空行定义**：一行只含空格 / Tab / `\r` 即为空行；等价 `\n[ \t\r]*\n`。
  - CRLF：`\r\n\r\n` 是段落边界；`\r` 单独不构成空行。
- 嵌套引号：内外都保护，嵌套配对不得跨段落。

### R1：完整结构

**起始标签**：`<` + 双竖线 + `DSML` + 双竖线 + 空白 + **白名单标签** + 可选属性 + `>`。
**闭合标签**：`<` + `/` + 双竖线 + `DSML` + 双竖线 + 空白 + **同名白名单标签** + `>`。
- 起始与闭合的标签名必须**同名**，匹配大小写不敏感（`calls` 对 `CALLS` 视为同名）。
- **闭合标签不允许属性**（严格 `<…/标签>`，标签名后只允许空白再 `>`）。
- **起始标签的 `>` 也按第六节的属性扫描识别**，不得简单取第一个 `>`。

**删除范围**：从起始 `<` 到闭合结构最后的 `>`，整段删除（受第七节 R1-f 待裁定策略约束）。

**示例**：
- `前缀A <｜｜DSML｜｜ calls>正文</｜｜DSML｜｜ calls> 后缀B` → `前缀A  后缀B`
- `<｜｜DSML｜｜ calls name="a>b">正文</｜｜DSML｜｜ calls>` → 整段删除（起始标签的 `>` 在属性值之外）

### R2：裸标记 + 白名单标签（选 B）

**匹配条件**：`｜｜DSML｜｜` 后紧跟（可隔空白）一个**按 2.2 完整匹配**的标签名。

**分支 A（有结束符）**：删到结束符 `>`（含），结束符按第六节识别；`>` 之后文字保留；禁止删到行尾。

**分支 B（无结束符 / 属性引号未闭合）**：
- 只删 ① `｜｜DSML｜｜`；② 紧跟其后的白名单标签名本身。
- 其余字符（空白、属性、正文）逐字保留。

**示例（v4 修正空格）**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A   后缀文字`（**三个空格**：标记两侧各一 + `calls` 后一）

### R3：裸标记单独出现（选 A）

**匹配条件**：`｜｜DSML｜｜` 后不是按 2.2 完整匹配的标签。

**删除范围**：只删 `｜｜DSML｜｜`。
**空白规则**：不合并空格、不 strip、不清行尾、不改换行。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`（标记两侧各一空格 → 剩两个）
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `

## 四、优先级与处理顺序（v4 补"跳过的区间不再处理"）

```
1. R4 起点判定
     起点在保护区内 → 该匹配跳过，且该区间标记为「本轮不再处理」
2. R1（若启用）
     若删除区间与保护区相交 → 见第七节 R1-f（待裁定）
     若跳过 → 该区间（含区间内所有 DSML 标记）标记为「本轮不再处理」
3. R2
4. R3
任何被标记为「本轮不再处理」的区间，R2/R3 不得再匹配其中的标记。
```

**冲突检查结论**：
1. R2 与 R3 互斥：是否跟**完整匹配**的白名单标签。
2. R1 先于 R2/R3。
3. R4 起点优先；且 **R1 跳过的区间不回流给 R2/R3**（v4 新增，否则 #21 会被部分删除）。
4. R2-B 禁止猜测；R3 不吞后文。
5. R4 引用保护与属性扫描是两套逻辑：ASCII `'` 不保护引用，但 `属性名='值'` 仍要识别。

## 六、`>` 的识别（7.3，v4 改为完整属性赋值语法）

**适用范围**：两个地方共用同一套扫描——R2-A 的结束符、R1 起始标签的结束符。

**规则**：
1. 从标记（或 `<`）之后开始扫描，直到找到"引号外第一个 `>`"。
2. **只有完整的属性赋值语法才开启属性值**：
   - `属性名 = "属性值"`
   - `属性名 = '属性值'`
   - 属性名合法字符：`[A-Za-z_][A-Za-z0-9_\-:]*`，允许 `=` 两侧有空白。
3. 开启后跳到**同名引号**的闭合处；属性值内部的 `>` 不参与结束符判断。
4. **普通撇号不能开启属性值**：`don't`、`owners'` 前面没有 `属性名=`，不构成边界。
5. **属性值引号未闭合**（如 `name="a>b` 后面再没有 `"`）：不得猜测 `>`；按 R2-B 处理（截断结构）。
6. 引号之外的第一个 `>` 才是结束符；到文本末尾都没有 → R2-B。
7. R1 的**闭合标签不允许属性**，所以闭合标签的 `>` 直接取该 `>`（标签名后只允许空白）。

**必须覆盖的测试**：
- `name="a>b">`：跳过属性值内 `>`。
- `name='a>b'>`：单引号属性值。
- `name="a>b`：属性值未闭合 → R2-B。
- `don't`、`owners'` 在扫描区间内也不开启属性值。
- 属性名非法（如 `1name="x"`）不视为属性赋值。
