## 二、术语与白名单

### 2.1 两种标记形态（v7 新增单竖线）

| 形态 | 例子 | 说明 |
|---|---|---|
| 双竖线（主形态） | `<｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ calls` | R1/R2/R3 |
| 单竖线（受限形态） | `<｜DSML｜ calls>`、`｜DSML｜ calls` | R2/R3，**仅当不构成双竖线的一部分时** |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C）。竖线个数决定形态：左右各 2 = 双竖线，左右各 1 = 单竖线。

**匹配顺序（G2 的核心，防止单竖线吃掉双竖线的一部分）**：

```
1. <｜｜DSML｜｜   （双竖线带尖括号）
2. <｜DSML｜       （单竖线带尖括号）
3. ｜｜DSML｜｜    （双竖线裸标记）
4. ｜DSML｜        （单竖线裸标记）
```

同一位置先匹配更长的形态；双竖线匹配成功的位置，单竖线规则**不得**再从其中截取（例如 `｜｜DSML｜｜` 里的中间那段 `｜DSML｜` 不算单竖线标记）。

### 2.2 白名单标签的完整匹配

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

1. **完整字符串匹配**（大小写不敏感），不得前缀匹配。
2. 合法边界只有四种：空白（空格/Tab）、`>`、`/`、行尾。
3. `callsxyz`、`calls_old`、`tool_calls`、`invoke2` 不算（按 R3 只删标记）。
4. `antml:invoke` 整串匹配。
5. 标签名后允许空白再跟属性。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记的匹配起点落在以下任一区域内。

1. **围栏代码块**：行首（≤3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行；行内 `` \` `` 不视为闭合。
3. **成对引号内**：`“”`、`‘’`、`「」`、`『』`、半角双引号 `""`（不含 ASCII `'`）。

**行为**：起点在保护区内 → 整个匹配跳过。

**边界**：引号必须成对；**跨行配对限同一段落**（7.1）；空行 = `\n[ \t\r]*\n`，CRLF 的 `\r\n\r\n` 同样是段落边界；嵌套引号内外都保护，不得跨段。

**R4 对单竖线同样生效**（G2）：保护区内无论双竖线还是单竖线标记都不处理。

### 3.4 属性语法引号不属于 R4 保护区

**语法区间** = 从控制标记起点到按第六节扫描确定的结束符 `>`（不含）。
语法区间内的引号（`name="a>b"` 的引号）归 DSML 属性解析，**不计入 R4 保护区**；区间外的成对引号才保护用户内容。
因此 `name="a>b"` 不会触发 R1-f 相交。

### R1：完整结构（v7 补栈式配对）

**识别**：
- 起始标签：`<` + 双竖线 + `DSML` + 双竖线 + 空白 + 白名单标签 + 可选属性 + `>`。
- 闭合标签：`<` + `/` + 双竖线 + `DSML` + 双竖线 + 空白 + 同名白名单标签 + `>`。
- 起止必须**同名**（大小写不敏感）；**闭合标签不允许属性**。
- **起始标签的 `>` 按第六节属性扫描识别**。

**栈式配对（R1-b 裁定：严格、不猜测）**：
1. 用栈扫描：遇到起始标签入栈，遇到闭合标签时与栈顶比对。
2. 只有**栈完整配对**（每一个起始都有对应闭合、顺序正确、无跨段嵌套）时，才按外层整段删除。
3. **任何异常都不删除**：
   - 起止标签不匹配（R1-a）→ 整段不处理；
   - 闭合在起始之前（R1-d）→ 孤立闭合标签保留；
   - 有起无闭（R1-c）→ 只删起始标签，保留正文；
   - 嵌套未闭合、顺序错乱 → 不猜测配对，不删除。
4. 段落边界约束（R1-e）：配对不得跨段落；外层跨段即视为不完整 → 按 R1-c。

**删除规则汇总**：

| 情形 | 行为 | 依据 |
|---|---|---|
| 栈完整配对 | 外层整段删 | R1-b/B1 |
| 有起无闭 | 删起始标签（到 `>`），保留正文 | R1-c/C1 |
| 起止不匹配 | 整段不处理 | R1-a/A3 |
| 孤立闭合标签 | 当普通文本保留 | R1-d/D1 |
| 外层跨段 | 视为不完整 → 按 R1-c | R1-e/E1 |
| 与保护区相交 | 整体跳过，区间不回流 R2/R3 | R1-f/F1 |
| 起始标签属性未闭合 | 整体不处理到文本末尾 | R1-h/H1 |

### R2：裸标记 + 白名单标签（选 B）

**匹配**：标记（双竖线或单竖线）后紧跟（可隔空白）按 2.2 完整匹配的标签名。

**分支 A（有结束符）**：删到结束符 `>`（含），按第六节识别；`>` 之后保留；禁止删到行尾。

**分支 B（无结束符 / 属性引号未闭合）**：只删 ① 标记；② 紧跟的标签名。其余逐字保留。

**示例**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A   后缀文字`（三空格）

### R3：裸标记单独出现（选 A）

**匹配**：标记后不是按 2.2 完整匹配的标签。

**删除**：只删标记；不合并空格、不 strip、不清行尾、不改换行。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `

## 四、处理顺序

```
0. 形态匹配（长优先：双竖线 → 单竖线；带尖括号 → 裸标记）
1. R4 起点判定 → 保护区内的标记一律不处理
2. R1 栈式配对
     完整 → 整段删；与保护区相交 → 整体跳过（不回流 R2/R3）
     不完整 → 按 R1-c / R1-a / R1-d / R1-h 各自规则
3. R2
4. R3
被跳过的区间，R2/R3 不得再处理其内部标记。
```

## 六、`>` 的识别（7.3）

**适用范围**：R2-A 结束符、R1 起始标签结束符共用。

1. 从标记（或 `<`）之后扫描，找"引号外第一个 `>`"。
2. 只有完整属性赋值语法开启属性值：`属性名 = "值"` / `属性名 = '值'`；属性名 `[A-Za-z_][A-Za-z0-9_\-:]*`。
3. 开启后跳到同名引号闭合处；属性值内 `>` 不参与结束符判断。
4. 普通撇号不开启属性值。
5. 只有引号外的第一个 `>` 才是结束符。

## 七、单竖线形态（R1-g/G2）

- 单竖线标记 `｜DSML｜` 与双竖线同规则处理（R2/R3）。
- **限定形式**：左右各 1 个竖线；`｜｜DSML｜｜` 中的中间片段不算单竖线。
- **R4 优先**：保护区内不处理单竖线。
- **双竖线优先匹配**：见 2.1 匹配顺序。

## 九、v8 修订：第二种闭合形式（2026-11-20 裁定）

保留标准闭合 `</｜｜DSML｜｜ name>`，新增受限闭合形式：

```
<｜｜DSML｜｜ /name>
```

### 9.1 形态要求

1. 必须带尖括号、双竖线；单竖线不享受该形式。
2. 标记后**至少一个空格/Tab**。
3. 紧跟 `/` 和完整白名单标签名；`/` 与标签名之间不允许空白。
4. 标签名后只允许空格/Tab 和 `>`；**不允许属性或任何额外内容**。

### 9.2 栈式配对

该形态作为 R1 闭合标签参与原有严格栈式配对，必须与栈顶同名。
错名仍按 R1-a 处理：不猜测、不删除。R4、R1-f、段落边界（R1-e）、skip_to 不回流规则全部不变。

### 9.3 标准闭合同步收紧

`</｜｜DSML｜｜ name>` 的标签名到 `>` 之间只允许空格/Tab。
带属性或多余文本的闭合不视为合法闭合，按异常处理，不删除正文。

### 9.4 `</<` 叠加

`</<｜｜DSML｜｜ name>` 保持 v8 兼容行为：孤立时整体保留。

## 十、非法新闭合候选的隔离（v11 修订，2026-11-20）

### 10.1 定义

带尖括号、双竖线的起始标记，标记后（可隔空格/Tab）以 `/` 开头，
但没有通过第九节严格校验的，称为「非法新闭合候选」。

例：`<｜｜DSML｜｜ /bad>`、`<｜｜DSML｜｜ /unknown>`、`<｜｜DSML｜｜ /calls name="x">`。

### 10.2 隔离规则

1. 从候选标记起点到候选终点（引号感知扫描到的 `>` 之后；没有 `>` 则到文本末尾）
   整体作为**隔离区间**。
2. 隔离区间不参与 R1/R2/R3，也不让普通 XML 清理进入。
3. 主循环、`_match_r1()` 的栈扫描、普通 XML 清理都必须跳过隔离区间；
   不能只在 R1 内移动局部游标。
4. 候选的标记按「不猜、不删」保留原样（可能残留标记）。不得为了消除标记
   而删除候选内部或候选之后的正文。
5. 候选之后的内容按原规范继续处理。

### 10.3 与 R1 的关系

- R1 完整结构若与隔离区间相交 → 整体跳过（R1-f 精神），不删除正文。
- 删除外层起始标签（R1-c / R1-e）后，重扫时隔离区间仍被跳过；
  候选内部不得重新送入 R1/R2/R3。

### 10.4 `</<` 叠加

保持 v8 兼容，不受本节影响。
