## 二、术语与白名单

### 2.1 控制标记形态（规范只承认双竖线）

| 形态 | 例子 | 说明 |
|---|---|---|
| 完整结构 | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` | R1 |
| 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ invoke name="x">` | R2 |
| 裸标记单独 | `｜｜DSML｜｜`（后面不是白名单标签） | R3 |
| 残缺 / 截断 | `｜｜DSML｜｜ calls`（无 `>`） | R2-B |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C）两种，**但必须是双竖线**（左右各 1 个字符）。
`DSML` 大小写不敏感。

> 单竖线 `｜DSML｜` 不属本规范形态；源码里有 `replace("｜DSML｜","")` 的既有处理，是否纳入规范待单独裁定。

### 2.2 白名单标签的完整匹配规则（v3 新增）

白名单集合（大小写不敏感，逐字相等）：

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

**完整匹配边界**（不得前缀匹配）：

1. 标签名必须是白名单中的**完整字符串**，与后续字符之间必须有**边界**。
2. 合法边界只有四种：空白（空格 / Tab）、`>`、`/`、行尾（`\n` 或文本末尾）。
3. 以下**不算**白名单标签，按 R3 处理（只删标记）：
   - `callsxyz`（`calls` 后紧跟其他字母）
   - `calls_old`（下划线不是合法边界）
   - `tool_calls`（不在白名单；`tool_call` 也匹配不上，因为 `_s` 不是边界）
   - `invoke2`
4. `antml:invoke` 含冒号，按整串匹配；`antml:invoke` 后的 `:` 或其他字符不算边界。
5. 标签名后允许空白再跟属性，例如 `invoke  name="x">`（多个空格也合法）。

新增标签必须单独批准。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记**匹配起点**落在以下任一区域内。

1. **围栏代码块**：行首（最多 3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合围栏保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行。
3. **成对引号内**（7.2 后集合）：`“”`、`‘’`、`「」`、`『』`、半角双引号 `""`。
   - **不含** ASCII `'`（撇号）。中文弯单引号 `‘’`（U+2018/U+2019）与 `'`（U+0027）是两个字符。

**行为**：匹配起点在保护区内 → 该匹配**整个跳过**，R1/R2/R3 均不处理。

**边界规则**：
- 引号必须成对才保护；找不到闭合引号时不保护。
- **跨行配对（7.1 = B）**：允许跨行，但限**同一段落**。
  - **空行的定义（v3 明确）**：一行只含空白字符（空格 / Tab / `\r`）即为空行；段落边界 = 空行。等价于出现 `\n[ \t\r]*\n`。
  - **CRLF**：`\r\n\r\n` 同样构成段落边界；`\r` 不单独构成空行。
  - 遇到段落边界仍未找到闭合引号 → 当前引号视为未闭合，停止向后配对（该引号所在位置之后的标记不受保护）。
- 嵌套引号：内层与外层都保护，但嵌套配对不得跨越段落边界。

### R4 与 R1 删除范围的冲突（v3 新增，保守策略）

R1 的删除范围可能**包含**保护区内容（例如控制结构内部的正文里有行内代码或成对引号）。

**规则**：按"不误删用户内容"优先——
1. 若 R1 的删除区间与任何保护区**相交**（有重叠），则**整个 R1 匹配跳过**（不删除）。
2. 跳过时记录日志（含 req），便于事后统计。
3. 不做"删保护区外的标记、保留保护区内内容"的拼接式删除（那会产生残片，比不删更难排查）。

> 代价：这类情况下控制标记会留在消息里。这是有意的保守选择，**待审查确认**；若认为"控制标记泄漏比误删更严重"，应改为"保护区内容先转义/保留、控制结构照删"，需另行裁定。

### R1：完整结构

**匹配条件（标签写法统一，v3）**：
- 起始：`<` + 双竖线 + `DSML` + 双竖线 + 空白 + `标签` + `>`（可带属性）
- 闭合：`<` + `/` + 双竖线 + `DSML` + 双竖线 + 空白 + `标签` + `>`

即 `<｜｜DSML｜｜ calls …>` 对应 `</｜｜DSML｜｜ calls>`；`/` 紧跟在 `<` 之后。

**删除范围**：从起始 `<` 到闭合结构最后的 `>`，整段删除（受上面的 R4 相交规则约束）。

**示例**：
- `前缀A <｜｜DSML｜｜ calls>正文</｜｜DSML｜｜ calls> 后缀B` → `前缀A  后缀B`

> R1 异常形态见第七节。

### R2：裸标记 + 白名单标签（选 B）

**匹配条件**：`｜｜DSML｜｜` 后紧跟（可隔空白）一个**按 2.2 完整匹配**的白名单标签名。

**分支 A（有结束符 `>`）**：
- 删除范围：从 `｜｜DSML｜｜` 起到结束符 `>`（含），结束符按第六节识别。
- `>` 之后的文字必须保留；禁止删到行尾。

**分支 B（无结束符，截断结构）**：
- 只删两样：① `｜｜DSML｜｜`；② 紧跟其后的**白名单标签名本身**（不含其后空白，空白由保真规则保留）。
- 标签名之后的内容（属性、正文、任何字符）一律保留。

**示例**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A  后缀文字`

### R3：裸标记单独出现（选 A）

**匹配条件**：`｜｜DSML｜｜` 后面**不是**按 2.2 完整匹配的白名单标签。

**删除范围**：只删 `｜｜DSML｜｜`。

**空白规则**：不合并连续空格；不 `strip()`；不清行尾空格；不改变换行（`\n` / `\r\n` 原样）。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `

## 四、优先级与冲突检查

```
R4 保护区判定（匹配起点）
  └─ 起点在保护区内 → 跳过该匹配
R4 相交判定（R1 专用）
  └─ R1 删除区间与保护区相交 → 整个 R1 跳过
R1 完整结构 → 整段删
R2 裸标记 + 白名单标签
  ├─ 有 `>`（按第六节）→ 删到 `>`
  └─ 无 `>` → 只删标记 + 标签名
R3 裸标记单独 → 只删标记
```

**冲突检查结论**：
1. R2 与 R3 互斥：标记后是否跟**完整匹配**的白名单标签是唯一分界。
2. R1 与 R2 不冲突：先 R1 后 R2。
3. R4 起点优先：匹配起点在保护区内一律不执行。
4. R4 与 R1 删除范围相交：R1 整体跳过（第三节规则）。
5. R2-B 禁止猜测；R3 不吞后文。
6. **R4 引用保护与 R2 属性扫描是两套独立逻辑**：ASCII `'` 不再是"自然语言引用"，但属性值里的成对单引号仍要识别（`name='a>b'`）。

## 六、结束符 `>` 的识别（7.3，待落实并复核）

**适用范围（v3 明确）**：扫描区间 = 从 `｜｜DSML｜｜` 标记之后，到"引号外的第一个 `>`"为止。

**规则**：
1. 在扫描区间内，**任何位置**出现的**成对引号**（`"` 或 `'`）都视为属性值边界，跳过其内部内容——不限于 `name=` 之后（属性写法可能有 `value=`、`data=` 等）。
2. 引号必须成对；单边引号不构成边界。
3. 属性值内部的 `>` 不作为结束符。
4. **不得**把自然语言正文中的撇号（`don't`、`owners'`）当属性引号——它们不在"标记之后的扫描区间"内；若区间内出现孤立 `'`，按未成对引号处理（不跳过、也不当作边界）。
5. 找不到属性引号闭合符时，**不得猜测** `>`；按 R2-B 处理。
6. 只有**引号之外**的第一个 `>` 才是 R2-A 的结束符；到文本末尾都没有 → R2-B。

**必须覆盖的测试**：
- `name="a>b">`：跳过属性值内 `>`。
- `name='a>b'>`：单引号属性值。
- `name="a>b`：未闭合，回退 R2-B。
- 正文 `don't`、`owners'` 不影响扫描。
- 扫描区间内出现孤立 `'` 时不被当成引号边界。
