## 二、术语与白名单

### 2.1 控制标记形态（规范只承认双竖线）

| 形态 | 例子 | 说明 |
|---|---|---|
| 完整结构（有尖括号） | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` | R1 处理 |
| 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ invoke name="x">` | R2 处理 |
| 裸标记单独 | `｜｜DSML｜｜`（后面不是白名单标签） | R3 处理 |
| 残缺 / 截断 | `｜｜DSML｜｜ calls`（无 `>`） | R2 的保守分支 |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C）两种，**但必须是双竖线**（左右各 1 个字符）。
`DSML` 大小写不敏感。

> **单竖线形态不属本规范**：源码里存在 `replace("｜DSML｜","")` 这种单竖线处理，属于既有实现行为，
> 不是本规范定义的标记形态。是否把它纳入规范，需单独裁定；本规范不擅自扩大。
> 第五节所有示例统一使用双竖线。

### 2.2 白名单标签（不得擅自扩大）

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

新增标签必须单独批准。标签名后可以跟空白与属性（`name="…"`），但**只有出现结束符 `>` 时**才视为有明确边界。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记完全落在以下任一区域内。

1. **围栏代码块**：行首（最多 3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合围栏保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行。
3. **成对引号内**（7.2 裁定后的集合）：`“”`、`‘’`、`「」`、`『』`、半角双引号 `""`。
   - **不含** ASCII 单引号 `'`（撇号）。
   - 中文弯单引号 `‘’`（U+2018/U+2019）与 ASCII 撇号 `'`（U+0027）是**两个不同字符**，只有前者受保护。

**行为**：该区域内的控制标记**一律不处理**，R1/R2/R3 跳过。

**边界规则**：
- 引号必须**成对出现**才保护；找不到闭合引号时**不保护**。
- **跨行配对（7.1 = B）**：允许跨行，但必须**同一段落**内——遇到空行（连续两个换行）即视为当前引号未闭合，停止向后配对。
- 嵌套引号：内层与外层都保护，但**嵌套配对不得跨越段落边界**。
- 行内代码内的反引号转义（`` \` ``）不视为闭合。

### R1：完整结构（有尖括号、有成对闭合）

**匹配条件**：`<｜｜DSML｜｜ 标签 …>` 后出现对应的 `<｜｜DSML｜｜ /标签>`（同字符、大小写不敏感）。

**删除范围**：从起始 `<` 到闭合结构最后的 `>`，**整段删除**。

**示例**：
- `前缀A <｜｜DSML｜｜ calls>正文</｜｜DSML｜｜ calls> 后缀B` → `前缀A  后缀B`

> R1 的异常形态（起止不匹配、嵌套、有起无闭、闭合顺序异常）**尚未定义**，见第七节清单，交主人裁定。

### R2：裸标记 + 白名单标签（选 B）

**匹配条件**：`｜｜DSML｜｜` 后紧跟（可隔空白）一个白名单标签名。

**分支 A（有结束符 `>`）**：
- 删除范围：从 `｜｜DSML｜｜` 起到**结束符 `>`** 为止（含 `>`）。
- 结束符的识别**不是**简单找第一个 `>`：必须按第六节规则跳过属性引号内的内容。
- 同一行 `>` 之后的文字**必须保留**。
- 禁止删到行尾。

**分支 B（无结束符，截断结构）**：保守处理——
- 只删除两样东西：① `｜｜DSML｜｜` 标记本身；② 紧跟其后的**白名单标签名本身**。
- 标签名之后的内容（属性、正文、任何字符）**一律保留**，不猜测它是控制内容。
- 不因为"看起来像控制结构"就删到行尾或删到空白。

**示例**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`（分支 A）
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A  后缀文字`（分支 B：只删标记与 `calls`）

### R3：裸标记单独出现（选 A）

**匹配条件**：`｜｜DSML｜｜` 后面不是白名单标签（含行尾、标点、正文）。

**删除范围**：只删 `｜｜DSML｜｜` 标记本身。

**空白规则**：
- 不合并连续空格；不 `strip()`；不清行尾空格；不改变换行（`\n` / `\r\n` 原样）。
- 删除后剩几个空格就是几个空格。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `

## 四、优先级与冲突检查

```
R4 保护区判定（最高）
  └─ 在保护区内 → 原样保留，结束
R1 完整结构（先长后短）
  └─ 有闭合结构 → 整段删
R2 裸标记 + 白名单标签
  ├─ 有 `>`（按第六节识别）→ 删到 `>`
  └─ 无 `>` → 只删标记 + 标签名
R3 裸标记单独 → 只删标记
```

**冲突检查结论**：
1. R2 与 R3 互斥：标记后是否紧跟白名单标签是唯一分界。
2. R1 与 R2 不冲突：R1 要求成对闭合结构，R2 处理单个；先 R1 后 R2。
3. R4 覆盖全部：任何 R1–R3 的匹配若落在保护区内一律不执行。
4. **不因清理残片而误删正文**：R2-B 禁止猜测；R3 不吞后文。
5. **不因保护引用而放过真控制结构**：R4 只保护代码/引号内；保护区外照常执行。
6. **R4 引用保护与 R2 属性扫描是两套独立逻辑**（7.2 裁定）：ASCII `'` 不再是"自然语言引用"，但**属性值里的成对单引号仍要识别**（如 `name='a>b'`）。

## 六、结束符 `>` 的识别（7.3，待落实并复核）

删除 R2-A 时，**不能简单地找第一个 `>` 字符**。

**扫描规则**：
1. 从 `｜｜DSML｜｜` 标记之后开始。
2. 只把**属性赋值中成对的引号**当作属性值边界：`name="a>b"`、`name='a>b'`。
3. 属性值内部的 `>` **不作为结构结束符**。
4. **不得**把自然语言正文里任意出现的撇号（`don't`、`owners'`）当成属性引号。
5. 找不到属性引号的闭合符时，**不得猜测** `>` 是有效结束符；按 R2-B 保守处理。
6. 只有**属性引号之外**的第一个 `>` 才是 R2-A 的结束符。

**必须覆盖的测试案例**：
- `name="a>b">`：跳过属性值内部的 `>`。
- `name='a>b'>`：单引号属性值也能正确识别。
- `name="a>b`：未闭合属性引号，回退 R2-B。
- 普通正文中的 `don't`、`owners'` 不得影响属性扫描。
