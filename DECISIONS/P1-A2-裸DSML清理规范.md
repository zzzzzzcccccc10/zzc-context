## 一、裁定结论

| 编号 | 问题 | 主人选择 | 含义 |
|---|---|---|---|
| R2 | 裸标记 + 白名单标签怎么删 | **B** | 只删能明确识别的控制结构（到结束符 `>` 为止），保留同一行后面的正常文字；**禁止删到行尾**；截断结构不得猜测 |
| R4 | 行内代码 / 围栏 / 引号内的字面引用 | **A** | 全部原样保留；R4 优先级高于 R1/R2/R3 |

> 本文是**规则规范**，不是施工许可。A 的代码改动仍需单独审查与批准。

## 二、术语与白名单

### 2.1 控制标记形态

| 形态 | 例子 | 说明 |
|---|---|---|
| 完整结构（有尖括号） | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` | R1 处理 |
| 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls>`、`｜｜DSML｜｜ invoke name="x">` | R2 处理 |
| 裸标记单独 | `｜｜DSML｜｜`（后面不是白名单标签） | R3 处理 |
| 残缺 / 截断 | `｜｜DSML｜｜ calls`（无 `>`） | R2 的保守分支 |

竖线允许全角 `｜`（U+FF5C）与半角 `|`（U+007C）两种；`DSML` 大小写不敏感。

### 2.2 白名单标签（不得擅自扩大）

```
calls、invoke、parameter、system_reminder、image_caption、thinking、
tool_call、tool_response、function_call、antml:invoke
```

新增标签必须单独批准。标签名后可以跟空白与属性（`name="…"`），但**只有出现结束符 `>` 时**才视为有明确边界。

## 三、规则定义

### R4（最高优先级）：保护区原样保留

**匹配条件**：控制标记完全落在以下任一区域内。

1. **围栏代码块**：行首（最多 3 空格缩进）``` 或 ~~~ 开始，到同字符、长度不小于开始、只含空白的独立行结束；未闭合围栏保护到文本末尾。
2. **行内代码**：单反引号包裹（`` `…` ``），不允许跨行。
3. **成对引号内**：`“”`、`‘’`、`「」`、`『』`、`""`、`''` 中任一对之间。

**行为**：该区域内的控制标记**一律不处理**，R1/R2/R3 跳过。

**边界规则（本规范内定，理由随附）**：
- 引号必须**成对出现**才保护；找不到闭合引号时**不保护**（否则一个落单引号会保护全篇）。
- 允许跨行成对引号（长引用常见）；跨行时按"首次出现闭合引号"配对。
- 嵌套引号：内层与外层都保护（同一区域内不做任何处理）。
- 行内代码内的反引号转义（`` \` ``）不视为闭合。

### R1：完整结构（有尖括号、有成对闭合）

**匹配条件**：`<｜｜DSML｜｜ 标签 …>` 后出现对应的 `<｜｜DSML｜｜ /标签>`（同字符、大小写不敏感）。

**删除范围**：从起始 `<` 到闭合结构最后的 `>`，**整段删除**。

**示例**：
- `前缀A <｜｜DSML｜｜ calls>正文</｜｜DSML｜｜ calls> 后缀B` → `前缀A  后缀B`

### R2：裸标记 + 白名单标签（选 B）

**匹配条件**：`｜｜DSML｜｜` 后紧跟（可隔空白）一个白名单标签名。

**分支 A（有结束符 `>`）**：
- 删除范围：从 `｜｜DSML｜｜` 起到**结束符 `>`** 为止（含 `>`）。
- 结束符的识别**不是**简单找第一个 `>`：必须跳过属性引号内的内容，见 7.3。
- 同一行 `>` 之后的文字**必须保留**。
- 禁止删到行尾。

**分支 B（无结束符，截断结构）**：保守处理——
- 只删除两样东西：① `｜｜DSML｜｜` 标记本身；② 紧跟其后的**白名单标签名本身**。
- 标签名之后的内容（属性、正文、任何字符）**一律保留**，不猜测它是控制内容。
- 不因为"看起来像控制结构"就删到行尾或删到空白。

**示例**：
- `前缀A ｜｜DSML｜｜ calls> 后缀文字` → `前缀A  后缀文字`（分支 A：删到 `>`，保留后缀文字与两侧空格）
- `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀文字` → `前缀A  后缀文字`
- `前缀A ｜｜DSML｜｜ calls 后缀文字`（无 `>`）→ `前缀A  后缀文字`（分支 B：只删标记与 `calls`）

### R3：裸标记单独出现（选 A）

**匹配条件**：`｜｜DSML｜｜` 后面不是白名单标签（含行尾、标点、正文）。

**删除范围**：只删 `｜｜DSML｜｜` 标记本身。

**空白规则（选 A 的核心）**：
- 不合并连续空格；不 `strip()`；不清行尾空格；不改变换行（`\n` / `\r\n` 原样）。
- 删除后剩几个空格就是几个空格。

**示例**：
- `前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`（标记两侧各一个空格，删后剩两个）
- `这个标记写作 ｜｜DSML｜｜` → `这个标记写作 `（行尾空格保留，不清理）

## 四、优先级与冲突检查

处理顺序（固定）：

```
R4 保护区判定（最高）
  └─ 在保护区内 → 原样保留，结束
R1 完整结构（先长后短）
  └─ 有闭合结构 → 整段删
R2 裸标记 + 白名单标签
  ├─ 有 `>` → 删到 `>`
  └─ 无 `>` → 只删标记 + 标签名
R3 裸标记单独 → 只删标记
```

**冲突检查结论**：
1. R2 与 R3 互斥：标记后是否紧跟白名单标签，是唯一分界。
2. R1 与 R2 不冲突：R1 要求成对闭合结构，R2 处理单个；先 R1 后 R2。
3. R4 覆盖全部：任何 R1–R3 的匹配若落在保护区内，一律不执行。
4. **不因清理残片而误删正文**：R2 分支 B 明确禁止猜测；R3 明确不吞后文。
5. **不因保护引用而放过真控制结构**：R4 只保护"位于代码/引号内"的标记；不在保护区内的 R1–R3 照常执行。

## 七、待审查确认的边界（需审查方判断，本规范已给出扫描规则）

### 7.1 跨行成对引号

**现状规则**：成对引号即保护，允许跨行（按"首次出现闭合引号"配对）。

**风险**：一处引号错配（例如正文里只出现一个 `“`，后面在远处另有 `”`）可能保护一大段正常文本。

**两个候选，待审查选择**：
- **候选 A（保守）**：只保护**同一行内**的成对引号；跨行一律不保护。
- **候选 B（现行）**：跨行成对也保护，但配对只在**同一段落**内进行（遇到空行即视为未闭合，停止配对）。

### 7.2 半角单引号 `'`

**现状规则**：`''` 成对列入保护区。

**风险**：英文缩写与所有格（`don't`、`it's`、`owners'`）里的撇号会被当成引号，多个撇号可能被错误配对，扩大保护范围。

**三个候选，待审查选择**：
- **候选 A（最保守）**：把半角单引号**移出**保护区，只保护 `“”`、`‘’`、`「」`、`『』` 与半角双引号 `""`。
- **候选 B（折中）**：只有**两侧都不是字母数字**的 `'` 才算引号（例如 `'引用'`），`don't` 里的 `'` 不算。
- **候选 C**：保持现状。

### 7.3 结束符 `>` 的识别

**规范明确（待审查确认，但只有一种扫描方式）**：删除 R2-A 的时候，**不能简单地找第一个 `>` 字符**。

扫描顺序：
1. 从 `｜｜DSML｜｜` 标记之后开始；
2. 遇到成对引号（`"` 或 `'`）时，**跳过引号内的全部内容**（属性值里可能含 `>`，例如 `name="a>b"`）；
3. 只有在**引号之外**遇到的第一个 `>` 才作为结束符；
4. 如果找不到引号外的 `>`，按 **R2-B 截断结构**处理（只删标记与白名单标签名）。

**对测试的要求**：必须覆盖 `name="a>b"` 这类属性内含 `>` 的样本，以及**未闭合引号**的样本（`name="a>b` 无闭合引号时，不得把 `>` 当结束符以外的猜测边界）。

### 7.4 书名号 `《》`

**暂不保护**（保守默认）。书名号通常表标题而非引用；是否纳入保护区待审查确认，本规范不擅自扩大。
