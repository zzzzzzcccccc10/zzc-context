# 决策记录 · B0.5 工具门禁

日期：2026-11-16　状态：**封版**

## 背景

P0 只保证"不直接执行生成代码"，但模型仍能调任意工具。需要限制可调用的工具集合与来源判定。

## 已批准

1. **白名单 10 个工具**：只有这 10 个允许在"非信任上下文"下调用；其余按外部处理。
2. **未知工具名一律按外部**（fail-closed）：不在白名单、不在已知列表的名字，按"会引入外部内容"对待。
3. **工具集 None / 空 / 读取失败 → 按有外部工具**（保守）。
4. 白名单之外的工具不是"禁用"，而是"触发外部来源标记"，影响记忆可见性（见 B1）。

## 已否决

- "按工具所在插件判断可信"（否决：插件跑在本地不代表返回内容可信，例如 `see_desktop` 返回窗口标题、`read_window` 返回截图文字）。
- 允许未知工具默认安全（否决：新插件/第三方工具会绕开边界）。

## 证据

- gate harness：`no_trust` / `bad_trust` / `forged_extra` / `no_event` 全部拒绝，handler 0 次调用。
- 工具分类表：114 个线上注册工具 → 27 外部 / 87 本地，未知一律外部（见公开仓库 `reviews/`）。
