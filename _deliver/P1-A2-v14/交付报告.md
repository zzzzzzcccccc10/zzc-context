## 二、修复

### 2.1 问题（复审阻断）

第一轮 DSML 扫描把 DSML 起始标签的属性区写进 SYNTAX；第二轮普通 XML 扫描从 `i = 0` 重新开始，
只检查 `code_regions`，于是 `_XML_START.search()` 会命中属性字符串里的 `<invoke`。

`_scan_attrs()` 把属性字符串里的单引号误当成普通 XML 属性的引号，后面没有匹配的单引号 →
`UNTERMINATED_ATTRIBUTE` → 伪标签的 SYNTAX 区间被扩展到文本末尾；`_merge_regions()` 后，
后面的非法候选 `<｜｜DSML｜｜ /bad>` 也落进 SYNTAX，`_candidate_regions()` 跳过它，
候选标记被后续 R2/R3 部分删除。

### 2.2 修法

`_syntax_regions(text, code_regions, dsml_out=None)`：

- 第一轮结束后，如果传了 `dsml_out`，把第一轮区间追加进去；
- 第二轮命中 `x.start()` / `c.start()` 时，先查是否落在第一轮 DSML 区间内；
  在区间内 → `i = 区间末尾`，跳过，不生成伪区间；
- 只跳过 DSML 语法标签区间，不跳过普通 XML 元素的正文。

`_clean_segment()`：

```python
dsml_syntax = []
syntax = _syntax_regions(t, code, dsml_out=dsml_syntax)
...
xml_skip = _merge_regions(skip + dsml_syntax)   # 只保护 DSML 语法区间
...
dels.extend(_xml_deletions(t, xml_skip))
```

这样普通 XML 清理不会把 DSML 属性里的伪 `<invoke>` 当独立标签，也不会误保护普通 XML 自身。
