## 三、测试用例（共 2 条）

### 用例 1 · 普通文本基线

**主人发送**：

```
测试基线：请只用一句简短的话回复我。
```

**预期模型输出**：1 句简短正常中文，不含 `DSML`、`｜｜`、`calls>`。

**预期最终发送**：正常短回复，逐字保留；无空消息。

**预期日志**：无 `tool_xml_guard` 的「删掉控制标记」记录；无 Traceback。

**验证点**：v14 未误伤普通文本。

> 基线不再包含真实情绪陈述，避免往对话史或 livingmemory 里多写一条关于主人状态的记录。

### 用例 2 · 裸 DSML 清理

**主人发送**：

```
请把下面这行原样输出，不要解释，也不要执行任何工具：前缀A ｜｜DSML｜｜ calls> 后缀B
```

**预期模型输出**：包含

```
前缀A ｜｜DSML｜｜ calls> 后缀B
```

（模型可能补成带尖括号的 `<｜｜DSML｜｜ calls>`；v14 对两种形态都会清理。）

**预期 v14 清理（R2-A）**：删除标记、标签名和 `>`：

```
前缀A  后缀B
```

（`前缀A` 后 1 个空格 + 标签后的 1 个空格，共 2 个空格。）

**预期最终发送**：`前缀A  后缀B`，不含 `｜｜DSML｜｜`、`calls>`、`<｜｜`。

**预期日志**：`[tool_xml_guard] 已把控制标记从消息里删掉 req=<request_id>`。

**验证点**：v14 在真实链路上触发清理，最终发送内容符合预期，正文保留。

> 本方案故意不加第 3 条。两条足以回答“基线是否正常、清理是否触发”；再加会扩大发送次数和副作用面。

## 四、证据采集

| 证据 | 来源 | 边界 |
|---|---|---|
| 入站消息 | AstrBot `event_bus` 日志 | 证明消息到达 |
| 请求 ID | `tool_xml_guard` 日志里的 `req=` | 用于关联同一次请求 |
| 原始 `completion_text` | AstrBot 不落盘完整原文 | **如可获取**才记录；不可得时标“不可得”，不为此改配置/加调试 |
| 清理前文本 | 同上；不可得则无法独立核验 | 不能用 QQ 最终消息倒推 |
| 清理后文本 | 最终发送内容 | QQ 客户端可见 |
| 清理日志 | `[tool_xml_guard]` INFO/WARNING | 只证明清洗器命中了检测/删除分支，**不记录被删除的原文** |
| 最终发送内容 | QQ 客户端 | 证明最终结果，**不等于清理前原文** |

采集命令（执行阶段用，只读）：

```bash
docker logs astrbot --since <T0> 2>&1 | grep -E 'event_bus|tool_xml_guard|Traceback|ImportError'
docker logs astrbot --since <T0> 2>&1 | grep 'tool_xml_guard'
```

### 4.1 证据边界（重要）

- QQ 客户端截图/复制只能证明**最终发送结果**，不能证明模型最初生成的完整文本。
- 如果原始 `completion_text` 不可得，最终验收结论应写成：

> 真实消息链路中观察到清洗器触发，最终发送内容符合预期；原始 completion_text 不可得，
> 无法独立核验清理前的完整文本。

- 不得把“最终发送正确”写成“清理前原文已被完整取证”。
