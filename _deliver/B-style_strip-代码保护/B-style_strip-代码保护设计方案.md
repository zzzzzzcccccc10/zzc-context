## 一、背景与目标

P1-A1 PENDING 2 已归因闭合：2026-11-19 那轮代码块变形由 `style_strip` 的 `squash_blank()` + `restyle()` 造成（`on_decorating` priority=90）。原始 completion 69 字符、格式完好；最终发送 58 字符、缩进丢失、英文逗号全角化、空行被删。

B 的目标：让 `style_strip` 在保持“短消息口语化”现有行为的同时，**识别并逐字保护代码内容**，不让 `,→，`、双空格压缩、行首空白清零、空行删除作用于代码。

B 与 PENDING 2 是不同验收对象：PENDING 2 只回答“那轮是谁改坏的”，B 回答“修好之后行为是否达标”。B 上线不能反过来充当 PENDING 2 的证据。

## 二、现状（只读核对）

线上 `astrbot_plugin_style_strip/main.py`（SHA `bb2e9984…`）：

- **没有任何代码检测**（`main.py` 头部注释说“不动代码块”，实现里没有）。

## 三、保护范围（建议）

必须覆盖三类，缺一不可：

1. **围栏代码**：``` 与 ~~~，含 CRLF、未闭合（保护到末尾）、四反引号、关闭行只允许空白；
2. **无围栏多行缩进代码**：连续 ≥2 行、以 2/4 空格或 Tab 缩进、且不是普通中文列表/引用；这是 2026-11-19 真实失败形态，不能只保护围栏；
3. **行内代码**：单反引号 `` `code` ``（含双反引号转义）。

受保护区域要求**逐字节不变**：标点、缩进、空行、尾随空格、换行符都不动。围栏外仍走现有 restyle。

## 四、设计

### 4.1 新增纯函数 `_code_regions(text) -> list[(start, end)]`

- 扫描围栏（同 tool_xml_guard v6 `_code_regions` 的思路，含 CRLF `\r?$`）；
- 扫描行内代码（单/双反引号，跳过围栏内）；
- 扫描无围栏缩进块：连续 ≥2 行满足 `^(?: {2,}|\t)`，且不与围栏/行内重叠；块结束于第一个非缩进行或空行后的非缩进行；
- 返回的区间互不重叠、按 start 排序。

### 4.2 分段处理

```python
def protected_restyle(text, max_len):
    out = []
    last = 0
    for s, e in _code_regions(text):
        out.append(restyle_noncode(text[last:s], max_len))  # 现有逻辑
        out.append(text[s:e])                                # 逐字保留
        last = e
    out.append(restyle_noncode(text[last:], max_len))
    return "".join(out)
```

- `squash_blank` 与 `fix_quotes` 同样只在非保护段执行；
- 注意：现有 `restyle` 是逐行处理，分段后要保证行边界不丢；保护区间包含整行时，前后段按原换行拼接。

### 4.3 与 max_len 的关系

- 现有 `max_len` 截断只作用于非代码段；代码段不计入“口语化截断”，避免把代码截断成残片；
- 若整条消息几乎全是代码，保护后剩余非代码段极短，仍可正常返回。

### 4.4 幂等与失败回退

- 保护函数对已保护文本再次调用应幂等（第二次保护区间不变）；
- 扫描异常时 **fail-open**（宁可少保护也不丢正文）还是 **fail-closed**（整条不处理）？建议 fail-open 但记录 warning，避免一条消息因扫描器 bug 被吞；这与 tool_xml_guard 的 fail-closed 不同，需主人裁定。
