- **日期**：2026-11-22

## 〇、v27 返修点

1. **`recvmsg()==0` 不再单独判 EOF**：SOCK_SEQPACKET 允许零长度消息；结合 `poll/ppoll` 的 `POLLHUP` 区分“零长度 packet”与“真正 EOF”；零长度 packet 按协议错误 → 保持锁、人工、不写 `not_sent`；只有 `POLLHUP` + 队列排空才判无可取得 pidfd。
2. **pidfd 关联协议可执行化**：supervisor 从**同一 CLI 进程身份**取得 `pidfd + cli_pid + starttime`（同一父进程、未 wait、不拼接不同时刻）；主进程核对消息与元数据；`/proc` 读取只是 supervisor 侧父子关系下的读，不是“pidfd 查询”；明确退出/复用/读失败/关联失败的处理；关联失败关 fd、保持锁、人工，不回退 PID 发信号。
3. 补零长度 packet、正常 EOF、队列消息后 EOF、拼接身份、消息/元数据不一致、pidfd 已退出等负向测试。

## 一、威胁模型与生命周期

### 1.1 威胁模型

**保护目标**：防止项目内部脚本/普通本地用户绕过顶层事务，制造并发部署或绕过启动核验。

**明确不防御**：拥有 `root`、Docker socket 写权限、或等效系统管理权限的主体；其可直接操作 Docker/cgroup；“禁止迁出/外部迁入”是程序约束，不是内核强制。

### 1.2 边界图

```text
C 外（持锁 fd L）：
  主进程 deploy.sh        （持 L；subreaper；只保留主进程端）
  supervisor              （持 L；只保留 supervisor 端；只迁入目标 CLI，不迁出）

C 内（Docker 操作）：
  Docker CLI              （继承 L；属于 C）
  CLI 受控后代            （继承 L；属于 C）

临时状态（迁移前，C 外）：
  CLI 子进程（阻塞 pipe；未 execve；不持有任何 socket 端点）
```

| 进程 | 在 C 内 | 持 L | socket 端点 | 退出条件 |
|---|---|---|---|---|
| 主进程 | 否 | 是 | 仅主进程端 | 事务结束、supervisor 退出 |
| supervisor | 否 | 是 | 仅 supervisor 端 | C 空、结果持久化后 |
| CLI 子进程（迁移前） | 否 | 是 | 不持有任何 socket 端点 | 迁移成功→C 内或终止 |
| Docker CLI（迁移后） | 是 | 是 | 无 | CLI 退出 |
| CLI 后代 | 是 | 是（默认） | 无 | 各自退出 |

### 1.3 互斥保证等级（方案 B）

- **保证**：主进程或 supervisor 至少一个存活时，锁 fd 由其持有，新事务无法取得；
- **不保证**：主进程与 supervisor 同时崩溃，且 CLI 关闭/替换了继承的 L → 锁可能提前释放；已知残余；
- 目标、验收、风险同步按此等级表述。

## 二、现状缺陷（已证实）

1. `p3_deploy_stepA.sh` 的 `BACKUP_MISMATCH` 分支裸 `sudo docker start astrbot`；
2. 备份失败、复制失败、`mv` 失败等分支也有裸 `docker start`；
3. 预期 SHA 硬编码，且误写为 v6（`c4497e04…`），实际 v14（`2f180cf0…`）；
4. “启动完整性核验”与“权限安全基线”未分开；
5. 无统一启动日志。

## 三、目标（按保证等级）

1. 所有部署动作只经唯一顶层事务；
2. **至少一个监督进程存活时**，全局锁覆盖完整事务；
3. 启动前核验 SHA、属主、权限；
4. 日志与锁目录使用安全目录 fd，日志文件本身做身份核验；
5. 启动意图、调用开始、命令结果、记录结果四层分开；
6. 崩溃窗口中的状态不被错误解释；
7. 不自动重试；未知结果停止自动操作；
8. 竞态未根治，依赖权限基线；
9. **不宣称**“主进程+supervisor 同时崩溃且 CLI 关闭 L”时仍全局互斥。

## 四、设计

### 4.1 配置来源与保护

#### 4.1.1 唯一来源与初始信任根

`deploy.env` 是唯一来源；不保留脚本顶部常量、不读 shell 环境变量覆盖。

**初始信任根**：

1. `deploy.env` 必须 `root:root`、mode `0640`、非 symlink；
2. 从 `/` 到直接父目录逐级 `lstat`：每级 `root` 属主、非 symlink、不含 world/group write；
3. 任一级不满足 → 失败，**不读取配置内容**；
4. 通过后才读取 `TRUSTED_OWNERS`、`PRIVILEGED_GROUPS`；
5. 不得用配置内白名单证明配置自身路径可信。

**解析**：

- `KEY=VALUE` 一行一对；忽略空行/整行 `#`；
- 白名单键：`TARGET_CANDIDATE_SHA`、`TARGET_V14_SHA`、`EXPECTED_OWNER`、`EXPECTED_MODE`、`TRUSTED_OWNERS`、`PRIVILEGED_GROUPS`；
- 未知/重复/缺键 → 失败；不允许引号/空格/续行/变量展开/`export`；
- SHA `^[0-9a-f]{64}$`；OWNER `root:root`；MODE `^(?:[0-7]{3}|0[0-7]{3})$`；
- `TRUSTED_OWNERS`：`name:uid:gid` 逗号分隔，含 `root:0:0`；
- `PRIVILEGED_GROUPS`：组名逗号分隔，至少 `sudo,wheel,adm`；
- 解析失败 → 不启动、记录、报告。

#### 4.1.2 路径、父目录与属主

1. 绝对路径；
2. 配置路径按 4.1.1（仅 root）；
3. 其它路径允许：`root:0:0`；或白名单内且 passwd `name/uid/gid` 一致、系统账号（`100<=uid<=999` 或显式标注）、`nologin`/`false`、主 GID 与附加组均不在 `PRIVILEGED_GROUPS`；组来源可读；否则失败；
4. 任一级 world-writable → 不启动；
5. group-writable：主 GID 成员 + `getent group` 附加成员，存在非白名单 → 失败；组信息不完整 → 失败；
6. 文件 root、mode ≤0640、非 symlink；
7. 不宣称防篡改。

#### 4.1.3 读取与使用竞态

- 读取后记录 `inode/mtime/SHA`，使用前再核验；
- 不能根治；依赖权限基线。

#### 4.1.4 交叉核对

- `TARGET_V14_SHA` = 备份实际 SHA = 部署准备报告基线；
- `TARGET_CANDIDATE_SHA` = 候选 snapshot SHA；
- 不一致 → 中止。

### 4.2 唯一顶层事务与入口边界

```text
deploy.sh <action> [target]        # 唯一项目入口
  deploy_transaction(action, target):
    acquire_global_lock()          # 失败 → 零改动、退出
    set_subreaper()                # 失败 → 记录，崩溃回收降级
    try:
      ... 备份 / 替换 / 恢复 / stop / start_verified / resolution ...
    finally:
      release_attempt_lock()
      close(L)                     # 仅当 C 空、supervisor 退出、阻塞子进程已确认
```

- 项目内部：所有项目自有脚本只经 `deploy.sh`；`lib/` 禁止独立执行；`start_verified` 不导出；
- 系统级：sudoers、Docker socket 权限、ACL 决定外部主体能否直接调用 Docker；**不通过 sudo 传递 fd**；
- 未实现系统级控制时，明确：**不保证拥有 Docker 权限的外部主体无法绕过 `deploy.sh`**；
- 负向测试：内部辅助脚本、内部调用链、系统外部直接 Docker（第三类不能仅靠脚本测试证明）。

#### 4.2.1 `start_verified`（内部）与启动事件

```text
start_verified(target):
  expected_sha = TARGETS[target]
  读取磁盘 main.py 的 SHA/属主/权限
  核验三项
  追加 precheck（pass/fail）
  fail → 不启动（不写 start_invoked）
  持久化 start_invoked
  持久化 start_call_begin
  创建并验证 cgroup C（叶节点）
    失败 → start_not_sent(cgroup_create_failed/cgroup_verify_failed) → resolution(not_sent,no)
  建立 socketpair（SOCK_CLOEXEC）
  主进程 fork 前：清除 supervisor 端 CLOEXEC
  spawn supervisor（fork，不 exec）
  主进程 fork 后：close(supervisor 端副本)；只保留主进程端
  supervisor fork CLI（阻塞 pipe；CLI 关闭 socket 两端 + 写端）
    fork 失败 → start_not_sent(cli_spawn_failed) → resolution
  supervisor fork 后：close(继承的主进程端)；只保留 supervisor 端
  supervisor 写元数据（cli_pid/starttime；root 0600）
    失败 → 终止 CLI + waitpid → start_not_sent(cli_metadata_failed) → resolution
  supervisor pidfd_open + sendmsg(SCM_RIGHTS)
    pidfd_open 失败 → supervisor 终止/回收 → start_not_sent(cli_pidfd_open_failed)
    sendmsg 失败 → supervisor 终止/回收 → start_not_sent(cli_pidfd_send_failed)
  主进程 recvmsg（MSG_CMSG_CLOEXEC）→ 协议校验 → 持 pidfd → ACK
    recvmsg 前/中 supervisor 崩溃 → 见 4.5.7 状态②
  主进程 ACK → supervisor 迁移 CLI 到 C
    迁移失败 → 终止 + 确认 → start_not_sent(cli_cgroup_enter_failed)
  放行 execve；exec 失败 → start_not_sent(cli_exec_failed)
  C 空 → 回收 → 写 start_result → resolution
```

- `start_invoked`：意图；`start_call_begin`：即将调用；都不是“命令已发出”；
- 明确未发送时写 `start_not_sent`；
- 崩溃规则：有 `start_result` → 用结果；有 `start_not_sent` → `not_sent`；只有 invoked/call_begin → `result_unknown`；
- **`result_unknown` 停止自动操作**；重试需独立人工授权事务。

#### 4.2.2 三维状态与对外映射

| 维度 | 取值 |
|---|---|
| `attempt_result` | `exit_0` / `exit_nonzero` / `not_sent` / `result_unknown` / `unrecorded` |
| `command_sent` | `yes` / `no` / `unknown`（仅事后） |
| `container_state` | `running` / `stopped` / `unknown` |
| `disk_verification` | `match` / `mismatch` / `check_failed` |

| container_state | disk_verification | 对外状态 |
|---|---|---|
| running | match | `RUNNING_DISK_MATCH` |
| running | mismatch | `RUNNING_DISK_MISMATCH` |
| running | check_failed | `RUNNING_DISK_UNVERIFIED` |
| stopped | 任意 | `STOPPED_UNVERIFIED` |
| unknown | 任意 | `STATE_UNKNOWN_UNVERIFIED` |

- `RUNNING_DISK_MATCH` 不代表已加载目标代码；
- 只读记录、保留现场、报告；不自动 stop/restart/回滚。

#### 4.2.3 UNRECORDED 边界

- `start_result` 只表示实际成功持久化的结果：`exit_0`/`exit_nonzero`/`result_unknown`；
- 写入失败 → 进程内 `attempt_result=unrecorded`；
- 后续 resolution 可带 `attempt_result=unrecorded`；
- resolution 也失败 → 保留现场与已有日志，不声称完整；
- 四个事实分开：启动意图、调用开始、命令结果、记录是否成功。

### 4.3 分支矩阵（全部经顶层事务，无自动重试）

| 分支 | 事务内动作 |
|---|---|
| 正常部署 | 备份 → 替换 → `start_verified(candidate)` |
| 备份失败 | 不启动；报告；可信 v14 恢复后才 `start_verified(v14)` |
| 备份校验不一致 | 不自动启动、不自动回滚；可信 v14 恢复后才 `start_verified(v14)`；否则停止 |
| 临时文件复制/校验失败 | 删临时文件；确认原文件可信后 `start_verified(v14)`；否则停止 |
| `mv` 失败 | 恢复备份并核验；通过后 `start_verified(recovered-v14)`；失败停止 |
| 回滚 | 恢复备份并核验；通过后 `start_verified(recovered-v14)`；失败停止 |
| 启动结果未知/非零 | 停止自动操作；不自动重试；报告主人；重试需独立人工授权事务 |
| 验证失败（测试 FAIL） | 不自动启动/回滚；报告，由主人决定 |

### 4.4 restart 语义

```text
deploy_transaction("restart", target):
  ...（全局锁已持有）...
  docker stop（supervisor/cgroup 管理，同 4.5.7）
  检查容器实际状态
  start_verified(target)
```

禁止裸 `docker restart`。

### 4.5 启动日志（JSONL）

路径：`/opt/astrbot/shared/记忆/部署日志/start-attempt-<attempt_id>.jsonl`。

#### 4.5.1 日志目录与日志文件 fd 核验

**目录**：从 `/` 逐级 `openat` + `O_NOFOLLOW` + `fstat`；保持 dirfd 链；创建/正式化/追加只用 dirfd。

**创建**：`openat(logdir_fd, "....tmp", O_CREAT|O_EXCL|O_NOFOLLOW, 0600)`；`fstat` 核验 regular/root/0600；记录 `dev/ino`。

**正式化**：`linkat`/`renameat2(RENAME_NOREPLACE)`；`fstatat` 核验目录项；与临时文件 `dev/ino` 一致。

**追加**：`openat(logdir_fd, name, O_RDWR|O_APPEND|O_NOFOLLOW)`；`fstat` 核验 regular/属主/权限；`fstatat` 比较 `dev/ino`；不一致失败。

#### 4.5.2 事件 Schema（闭合）

**通用规则**：所有字段值为 JSON 字符串；`additionalProperties=false`；未知字段拒绝。

**字段类型**：

| 字段 | JSON 类型 | 格式/枚举 |
|---|---|---|
| `event` | string | 枚举 |
| `attempt_id` | string | `^[a-f0-9]{32}$` |
| `time` | string | `YYYY-MM-DDTHH:MM:SSZ`，日历有效 |
| `target` | string | candidate/v14/recovered-v14 |
| `result` | string | precheck: pass/fail；start_result: exit_0/exit_nonzero/result_unknown |
| `reason` | string | call_declined/cgroup_create_failed/cgroup_verify_failed/supervisor_spawn_failed/cli_spawn_failed/cli_metadata_failed/cli_pidfd_open_failed/cli_pidfd_send_failed/cli_ack_failed/cli_cgroup_enter_failed/cli_exec_failed/operator_cancel/precondition_changed |
| `attempt_result` | string | exit_0/exit_nonzero/not_sent/result_unknown/unrecorded |
| `command_sent` | string | yes/no/unknown |
| `container_state` | string | running/stopped/unknown |
| `disk_verification` | string | match/mismatch/check_failed |
| `source` | string | normal/recovery（resolution 可选） |
| `expected_sha`/`actual_sha` | string | `^[0-9a-f]{64}$` |
| `owner` | string | `^[a-z_][a-z0-9_-]{0,31}:[a-z_][a-z0-9_-]{0,31}$` |
| `mode` | string | `^0?[0-7]{3}$` |
| `action` | string | added_line_terminator |

**逐事件允许字段（闭合）**：

| 事件 | 允许字段（无其它） | 必需 |
|---|---|---|
| attempt_created | event, attempt_id, time, target | 全部 |
| precheck | event, attempt_id, time, result, expected_sha?, actual_sha?, owner?, mode? | event, attempt_id, time, result |
| start_invoked | event, attempt_id, time | 全部 |
| start_not_sent | event, attempt_id, time, reason | 全部 |
| start_call_begin | event, attempt_id, time | 全部 |
| start_result | event, attempt_id, time, result, command_sent | 全部 |
| resolution | event, attempt_id, time, attempt_result, command_sent, container_state, disk_verification, source? | 除 source 外全部 |
| recovery | event, attempt_id, time, action | 全部 |

**状态机**：

```text
attempt_created → precheck
  precheck=fail → 结束（终止）
  precheck=pass → start_invoked → start_call_begin
    → start_not_sent（cgroup/supervisor/CLI 失败，确定未发送）→ resolution（终止）
    → start_result → resolution（终止）
recovery：仅非终止事件缺换行时追加；最多一次
```

**交叉约束**：

- `precheck=fail` 不产生 `start_invoked`/`resolution`；
- `start_not_sent` 允许在 `start_call_begin` 之后；后必须 `resolution`；
- `start_not_sent.reason` ∈ `cgroup_create_failed/cgroup_verify_failed/supervisor_spawn_failed/cli_spawn_failed/cli_metadata_failed/cli_pidfd_open_failed/cli_pidfd_send_failed/cli_ack_failed/cli_cgroup_enter_failed/cli_exec_failed/call_declined/operator_cancel/precondition_changed`；
- `start_result.command_sent`：`exit_0`/`exit_nonzero` → `yes`；`result_unknown` → `unknown`；
- `resolution.command_sent`：`exit_0`/`exit_nonzero` → `yes`；`not_sent` → `no`；`result_unknown`/`unrecorded` → `unknown`；
- `resolution.source=recovery` 仅用于 supervisor 崩溃恢复；不伪造 `start_result`；
- `container_state`/`disk_verification` 独立；
- `recovery` 不改变业务状态。

#### 4.5.3 严格 JSON 校验

对象、拒绝重复键/`NaN`/`Infinity`、按 4.5.2 校验；非法行按 4.5.4。

#### 4.5.4 JSON 合法性处理（含终止事件）

| 情况 | 处理 |
|---|---|
| 合法 + 有换行 | 可追加 |
| 合法 + 无换行，终止事件 | 只补 `\n` + `fsync`；不追加 `recovery` |
| 合法 + 无换行，非终止事件 | 补 `\n` + `fsync` → `recovery` + `fsync`；最多一次 |
| 非法 + 无/有换行 | 停止追加、只读取证、不启动 |
| 中间行非法 | 停止追加、只读取证、不启动 |
| 连续非法/无法定位 | 停止追加、只读取证、不启动 |

#### 4.5.5 首次创建与追加（含 fork/发布/迁移失败）

**锁顺序**：全局锁 → attempt 锁；释放 attempt → 全局。

**A. 首次创建（precheck=pass）**：同 v21 步骤 1–12。

**B. 首次创建（precheck=fail）**：同 v21。

**C. 失败矩阵（含 fork/元数据/pidfd/ACK 四态/迁移）**

| 失败步骤 | 可能状态 | 继续？ | 启动？ | 现场 |
|---|---|---|---|---|
| 临时文件创建失败 | 无文件 | 否 | 否 | 报告 |
| 临时文件 `fstat` 失败 | 身份未证 | 否 | 否 | 保留，只读取证 |
| 事件写入失败 | 临时文件残缺 | 否 | 否 | 保留临时文件 |
| `start_call_begin` 写入失败 | invoked 存在、无 call_begin | 否 | 否 | 保留，只读取证 |
| 临时文件 `fsync` 失败 | 临时文件存在 | 否 | 否 | 保留 |
| 正式文件创建失败 | 临时文件存在、目标无 | 否 | 否 | 保留临时文件 |
| 正式化 `fstatat` 失败 | 目录项未证 | 否 | 否 | 保留，只读取证 |
| 正式化 `dev/ino` 不一致 | 身份不匹配 | 否 | 否 | 保留，只读取证 |
| 临时文件删除失败 | 正式文件存在、临时残留 | 否 | 否 | 保留残留，报告 |
| 目录 `fsync` 失败 | 正式文件可能已存在 | 否 | 否 | 标记 `state_uncertain` |
| **cgroup 创建失败** | 无 C | 否 | 否 | `start_not_sent(cgroup_create_failed)` |
| **cgroup 验证失败** | C 不可用 | 否 | 否 | `start_not_sent(cgroup_verify_failed)` |
| **supervisor spawn 失败** | 无 supervisor | 否 | 否 | `start_not_sent(supervisor_spawn_failed)` |
| **CLI fork 失败** | 无 CLI 子进程 | 否 | 否 | `start_not_sent(cli_spawn_failed)` |
| **元数据写入失败** | CLI 未 exec | 否 | 否 | 终止+wait → `start_not_sent(cli_metadata_failed)` |
| **元数据失败清理中 supervisor 崩溃** | CLI 可能残留；主进程无 pid | 否 | 否 | 保持锁、人工；不写 not_sent |
| **pidfd_open 失败（supervisor 存活）** | CLI 未 exec | 否 | 否 | supervisor 终止/回收 → `start_not_sent(cli_pidfd_open_failed)` |
| **sendmsg 失败（supervisor 存活）** | CLI 未 exec | 否 | 否 | supervisor 终止/回收 → `start_not_sent(cli_pidfd_send_failed)` |
| **ACK 前崩溃四态** | 见 4.5.7 | 否 | 否 | 逐态处理 |
| **CLI 进入 C 失败** | CLI 未 exec | 否 | 否 | 终止+确认 → `start_not_sent(cli_cgroup_enter_failed)` |
| **CLI exec 失败** | CLI 未执行 | 否 | 否 | `start_not_sent(cli_exec_failed)` |

**D. 追加（含身份核验）**：同 v21。

#### 4.5.7 监督进程、cgroup 与 Docker 子进程

**威胁模型边界**：保护项目内部脚本/普通本地用户；不防御 root、Docker socket、等效权限主体；“禁止迁出/外部迁入”是程序约束。

**cgroup C**：叶节点；属主 root、mode `0700`；supervisor 只迁入目标 CLI、不迁出。

**supervisor 启动与 socketpair 端点**：

1. `socketpair(AF_UNIX, SOCK_SEQPACKET|SOCK_CLOEXEC)`：两端初始 `CLOEXEC=true`；
2. 主进程 fork 前：对 supervisor 端 `fcntl(F_SETFD, 0)` 清除 `CLOEXEC`；主进程端保持 `true`；
3. `fork` supervisor（不 exec）；
4. 主进程 fork 后立即 `close(supervisor 端副本)`；只保留主进程端；
5. supervisor fork CLI 后立即 `close(继承的主进程端)`；只保留 supervisor 端；
6. CLI fork 后立即关闭 socket 两端；不持有；
7. CLI 关闭 pipe 写端；只保留 pipe 读端 + L；
8. CLI execve 前读放行字节；读完后关闭 pipe 读端；execve 后无 socket/pipe；
9. supervisor 崩溃：其 supervisor 端关闭 → 主进程端 `recvmsg` 返回消息/EOF；
10. 若主进程仍持有 supervisor 端副本，EOF 不可达 → 必须按第 4 步关闭。

**SCM_RIGHTS 接收协议**：

- `recvmsg` 使用 `MSG_CMSG_CLOEXEC`；
- 检查 `msg_flags`：`MSG_CTRUNC`/`MSG_TRUNC` → 关闭 fd、失败、保持锁/人工；
- 控制消息只接受 `SOL_SOCKET`/`SCM_RIGHTS`；其他类型 → 关闭 fd、失败；
- 恰好 1 个 fd；多余 fd 关闭；0 个 → 失败；
- 数据固定结构 `{cli_pid:u32, starttime:u64}`；长度不符 → 关闭 fd、失败；
- 异常 fd 清理：除验证通过的 pidfd 外全部关闭。

**pidfd 与身份字段的关联（v27 可执行定义）**：

**supervisor 侧（发送方）**：

1. fork CLI 后，父进程未 `wait`，PID 不会被复用；
2. 在**同一时刻**从 `/proc/<cli_pid>/stat` 读取 starttime（这是 supervisor 作为父进程对子进程的读取，不是 pidfd 查询）；
3. `pidfd_open(cli_pid)` 得到 pidfd；
4. **立即再次**读取同一 `/proc/<cli_pid>/stat` 的 starttime，与第 2 步比较；不一致 → 视为身份不稳定 → 终止/回收、`start_not_sent(cli_pidfd_open_failed)`；
5. 将 `{cli_pid, starttime}` 与 pidfd 通过**同一条** `sendmsg` 发送；不得拼接不同进程/不同时刻的数据；
6. 若 `pidfd_open` 后进程已退出：pidfd 仍引用已退出进程（不指向复用者）；starttime 读取可能失败 → 按失败处理。

**主进程侧（接收方）**：

1. `recvmsg` 收到消息 + pidfd；
2. 核对消息 `cli_pid/starttime` 与已发布元数据（supervisor 写、root 0600）一致；
3. 核对消息中的 `starttime` 与元数据一致；不一致 → 关闭 fd、保持锁、人工；
4. **不通过 `/proc` 重新查询 pidfd 来“证明”身份**；关联依据是“supervisor 在同一父进程关系下、同一时刻取 pid/starttime 并随 pidfd 一起发送”；
5. pidfd 是内核对象，主进程持有它即引用该进程；即使进程已退出，pidfd 仍指向原进程（不指向复用者）；
6. 主进程可 `poll(pidfd)` 判断是否已退出；已退出 → 不发送信号，按退出处理；
7. **关联失败/消息与元数据不一致** → 关闭收到的 fd、保持锁、人工；不回退 PID 发信号。

**进程退出/PID 复用/读取失败**：

- supervisor 侧读取 starttime 失败 → 终止/回收、`cli_pidfd_open_failed`；
- 主进程侧消息/元数据不一致 → 关 fd、保持锁、人工；
- pidfd 已退出 → 不发送信号，按退出处理（回收由父进程/subreaper）；
- PID 复用：不使用“事后 pidfd_open(PID)”恢复身份；不在主进程侧用 PID 重新打开。

**ACK 前四态（v27 修正）**：

| 状态 | 主进程持可靠 pidfd | socket 队列 | 终止/回收 | not_sent | 锁 |
|---|---|---|---|---|---|
| ① sendmsg 前 supervisor 崩溃 | 无 | 无消息 | 无可靠终止者；CLI EOF `_exit`；不杀；无法确认 | 不写 | 保持锁、人工 |
| ② sendmsg 成功、主进程尚未 recvmsg | 尚未持有 | 可能有消息/零长度 packet | **先确认 supervisor 退出 + 排空队列**：`poll` 检查 `POLLHUP`；循环 `recvmsg(MSG_DONTWAIT)`；`>0` 消息→校验；`==0` → 若 `POLLHUP` 且无更多数据 → 真正 EOF/队列空；若**无** `POLLHUP` → 零长度 packet → **协议错误**、保持锁、人工；`EAGAIN` → 等待，不判无 pidfd；超时未确认 → 保持锁、人工 | 取得并确认退出后 `cli_ack_failed`；否则不写 | 确认后释放；否则保持 |
| ③ 已 recvmsg 持 pidfd、ACK 未完成 | 有（已验证） | 已取走 | supervisor 存活 → supervisor 终止 + waitpid；supervisor 退出且 reparent → 主进程终止 + waitid；不确定 → 保持锁、人工 | 确认后 `cli_ack_failed` | 确认后释放 |
| ④ 已取得 pidfd、ACK 发送失败 | 有（已验证） | 已取走 | 同③ | 确认后 `cli_ack_failed` | 确认后释放 |

**状态②的 `recvmsg()==0` 处理（v27 关键）**：

1. `SOCK_SEQPACKET` 允许**零长度消息**；`recvmsg()==0` **不能单独证明 EOF**；
2. 必须结合 `poll/ppoll`：
   - `POLLHUP` 置位且后续无更多可读数据 → 对端关闭、队列排空 → 判无 pidfd；
   - 无 `POLLHUP` 且 `recvmsg()==0` → **零长度 packet** → 协议格式错误 → 保持锁、人工、**不写 not_sent**；
3. 零长度 packet 不按“无 pidfd”处理；停止继续读取，保留现场；
4. 队列中“消息 → EOF”顺序：先读消息，再遇 `POLLHUP` + 空队列才判 EOF；
5. `EAGAIN`：无数据；`poll` 检查 `POLLHUP`；有 HUP 且无数据 → 队列空；无 HUP → 等待；
6. 超时未确认 → 保持锁、人工（不是 not_sent）。

**supervisor 存活时的 pidfd 失败**：

| 失败点 | pidfd | 终止 | 回收 | not_sent |
|---|---|---|---|---|
| pidfd_open 失败 | 无 | supervisor：close pipe 写端→CLI EOF；必要时 kill(cli_pid)（父进程未 wait，PID 未复用） | supervisor waitpid | 确认后 `cli_pidfd_open_failed` |
| sendmsg 失败 | 有 | supervisor pidfd 终止 | supervisor waitpid | 确认后 `cli_pidfd_send_failed` |
| ACK 失败/超时 | 有 | supervisor pidfd 终止 | supervisor waitpid | 确认后 `cli_ack_failed` |

**fork 到发布之间的崩溃窗口**：

- fork 后、元数据前崩溃：主进程不知 pid；CLI EOF `_exit`；无法确认 → 保持锁、人工；不杀；
- 元数据后、pidfd 前崩溃：只读取证；不杀；保持锁、人工；
- sendmsg 后、recvmsg 前崩溃：见状态②；先确认退出 + 排空队列（区分零长度/EOF）；
- recvmsg 后、ACK 前崩溃：见状态③；
- 所有窗口：确认退出前不释放锁。

**确认退出 vs 回收**：

- 主进程设 `PR_SET_CHILD_SUBREAPER`；
- 正常：supervisor 父进程 `waitpid`；
- supervisor 崩溃：CLI reparent 到 subreaper 主进程；`waitid` 回收；
- 元数据未发布时主进程不知道 pid；subreaper 只能收尸，不能识别/确认；不把其他被托管进程误认成 CLI；
- subreaper 失败 → 只能只读观察，不能回收 → 保持锁、人工。

**pipe/socket 规则**：

- supervisor 保留 pipe 写端；CLI fork 后立即关闭写端；
- 只有 supervisor 显式写放行字节（`0x01`）才 execve；
- EOF、异常字节、协议错误 → CLI `_exit(127)`；
- socketpair：主进程端 `CLOEXEC=true`；supervisor 端 fork 前清除 `CLOEXEC`；主进程 fork 后关闭 supervisor 端副本；supervisor fork CLI 后关闭主进程端；CLI 关闭两端。

**锁 fd 继承边界**：

- L 必须来自 supervisor fork 时的继承 fd（同一 open file description）；
- exec 前后不得关闭/替换 L；程序约束 + 隔离测试；
- `/proc/<cli_pid>/fd` 只验证 fd 存在与 inode 一致，不证明是同一 flock 对象；
- 继承链由 fork 路径保证；`/proc` 为辅助证据；
- CLI 若关闭/替换 L → 记录、报告；主进程+supervisor 同时崩溃时为已知残余。

**结果与释放顺序（唯一）**：

1. C 空；
2. 回收 CLI/子进程（`waitpid`/`waitid`）；
3. 确认 C 外阻塞子进程已退出（正常 pidfd 路径；回退不用于终止）；
4. 写并持久化 `start_result`；
5. 写并持久化 `resolution`；
6. 日志失败 → `unrecorded`/`result_unknown`，保留现场；
7. supervisor 关 L；
8. supervisor 退出；
9. 主进程确认后关 L；
10. 不提前释放锁。

**信号**：主进程 SIGINT/SIGTERM → 转事务中断；supervisor 向 C 内进程 SIGTERM，超时 SIGKILL；清理中再次信号 → 保留现场。

**互斥保证等级**：至少一个监督进程存活 → 锁持有；两者同时崩溃且 CLI 关闭 L → 不保证；已知残余。

### 4.8 竞态

- 0777/0666 下检查到 Docker 加载之间文件可能被替换；
- 配置读取→使用竞态；日志/锁目录可被替换；
- `flock` 不阻止外部写入者；
- 不能宣称竞态消除；权限基线是根治前提。

## 五、现实约束

当前 0777 环境可能无法通过配置/日志/锁目录检查；cgroup v2 可能不可用；设计通过后也不能直接施工/部署；先完成权限基线评估与整改；不得为让脚本跑起来放宽 fail-closed。

## 六、风险

1. 竞态未根治（依赖权限基线）；
2. 启动字节一致 ≠ 权限安全；
3. 日志/锁目录可能不满足前置条件，届时 fail-closed 不启动；
4. cgroup 不可用/权限不足 → fail-closed；
5. 系统级 Docker 权限无法由脚本保证；
6. 互斥残余：主进程+supervisor 同时崩溃且 CLI 关闭 L → 锁可能提前释放；已降级；
7. 身份回退不用于终止：supervisor 崩溃且无 pidfd 时，只能保持锁/人工。
