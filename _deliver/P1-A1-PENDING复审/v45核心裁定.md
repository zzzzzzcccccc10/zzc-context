## 一、hold 状态机（最终，逐条件互斥）

### 1.1 判定顺序（固定，不可交换）

```
步骤 0：W3 重开+尾修复；计算 spawn_closed（见 §四）；
        有界收尸（waitpid 五分支）；得 live/observed/spawn_state。
步骤 1：若 live≠[] 或 observed≠true（有活体/不可观测）：
  1a. WAL 可写 且 takeover(3)+halt(4) 成功 → P2 T-HALT（22）
  1b. 否则 → hold-live（持 L/M、心跳、SIGKILL→signal9；无退出码）
  1c. P3/P4a/P1 一律禁止（不得因 HALT/latch 可写释放 L/M）。
步骤 2：若无活体且 observed=true：
  2a. WAL 可写：takeover(3)→token→latch→attempt_hold 全成功 → P1（22）
      2a'. attempt_hold 失败 → P1-H（latch-only 22，basis=latch）
  2b. WAL 不可用：token+latch 成功 → P3（22，basis=latch）
      2b'. latch 失败 → P4b（hold-live）
      2b''. HALT 写失败（latch 成功）→ P3a（同 P3 形态，无 HALT，22，basis=latch）
  2c. WAL/HALT 均不可用：latch 成功 → P4a（22，basis=latch）；latch 失败 → P4b
```

### 1.2 路径表（唯一结果）

| 路径 | 条件（互斥） | WAL 事件 | 文件 | L/M | 退出 | recover basis |
|---|---|---|---|---|---|---|
| P1 | 无活体+observed=true+WAL 可写+attempt_hold 成功 | takeover(3)→token→latch→attempt_hold(epoch3) | token+latch | 持→释放 | 22 | attempt_hold |
| P1-H | 无活体+observed=true+WAL 可写+latch 成功+attempt_hold 失败 | takeover(3)（attempt_hold 半行留待下次尾修复） | token+latch | 持→释放 | 22 | latch |
| P2 | 有活体/observed≠true+WAL 可写+takeover(3)+halt(4) 成功 | takeover(3)→halt(4)→W4→takeover(4→5)→W4R attempt_hold(epoch5) | HALT+token+latch | 持→释放 | 22 | attempt_hold；W4R 失败→见 §二 |
| P3 | 无活体+observed=true+WAL 不可用+token+latch 成功+HALT 成功 | 无 | HALT(wal_persisted=false)+token+latch | 持→释放 | 22 | latch |
| P3a | 同 P3 但 HALT 写失败 | 无 | token+latch（无 HALT） | 持→释放 | 22 | latch |
| P4a | 无活体+observed=true+WAL/HALT 均不可用+latch 成功 | 无 | token+latch | 持→释放 | 22 | latch |
| **P4b / hold-live** | 有活体/observed≠true 且 P2 不可行；或 latch 不可持久 | 无新增（已写 takeover/halt 保留、不补不删） | token+HALT(false)（可写时）或仅内存 | 持（不释放） | 无受控退出；心跳 1s；SIGKILL→signal9；**next run 23** | 23 人工 |
| T2-02b | 无活体+WAL 持续 EIO+latch 持续 EIO+HALT 正常 | 无 | HALT(false)+token，无有效 latch | 持（不释放） | 无退出（心跳）；SIGKILL 收尾 | 23 人工（或确认 token 后 basis=hold_token→0，见 §三） |

- 铁律：有活体/不可观测→只 P2 或 P4b；P3/P4a 仅无活体 observed=true。
- latch 成功定义：create+write+fsync 文件+fsync 目录+目录项复核；任一失败即“不可持久”→P4b。
- hold-live 的 SIGKILL 是内核信号终止（无退出码）；23 是下一次 run 的拒绝码，不是被杀进程的退出码。
- P2 失败（takeover/halt 失败）→P4b；P2 的 attempt_hold 失败（W4R 失败）→§二。

## 二、W4R 失败（S1/S2/S3）

### 2.1 子状态（恢复时按 WAL 观察分类；不按运行期内存）

| 子态 | WAL 末完整行 | 半行 | HALT 字段 | 首次退出 | recover basis |
|---|---|---|---|---|---|
| W4R-S1 | halt(4) seq=q epoch4；无 takeover5/attempt_hold | 无 | (4,4,true,q) | 重新观测：有活体/不可观测→hold-live；否则 22 latch-only | latch |
| W4R-S2a | takeover(4→5) seq=q+1 epoch5；无 attempt_hold；HALT 已 5/5 | 无 | (5,5,true,q) | 同上 | latch |
| W4R-S2b | takeover(4→5) 已持久；HALT 仍 4/4（4→5 改写未发生） | 无 | (4,4,true,q) | 同上 | latch |
| W4R-S3a | halt(4)；takeover5 半行 | 有（尾部） | (4,4,true,q) | 首次不截断 | 下次 recover 尾修复→S1 |
| W4R-S3b | takeover5 完整写但 fsync EIO（恢复时同 S2） | 无 | (4,4,true,q) | 首次按 S2 | latch |
| W4R-S4 | attempt_hold 已持久 | 无 | (5,5,true,q) | 崩溃无退出；错误返回路径 22 | attempt_hold |

- 恢复顺序：全前缀重放→has_attempt_hold→S4；否则 has_takeover5→S2a/S2b；否则 halt(4)→S1；半行→S3a。
- 不补写：不写 takeover5、不写 attempt_hold、不截断（首次）；仅 recover 可截尾半行。
- 不重写：resolution 文件 O_EXCL；同 token 只清理；异 token 23。
- **resolution 载体（裁定）**：新增 `run/<id>/resolution.json`（0600、O_EXCL、单行 ≤4KiB、fsync 文件+目录），字段
  `{v:1,attempt_id,basis,authority_seq,anchor,token_sha256,observed,spawn_state,resolved_at}`；
  WAL 可写且末 epoch=4 时，可同时写 `operator_resolution` 事件（双写、以文件为清理依据）；末 epoch=5 时**只写文件**（不新增 epoch6、不写 WAL）；`anchor=wal|none` 为字段，`authority_seq==0 ⇔ anchor=none`，且不含本条。
- **resolved 不落 HALT**：`resolved` 是派生谓词（resolution.json 存在 或 WAL operator_resolution 存在）；HALT 闭集不变。
- 首次退出：S1/S2/S3 先重新观测；有活体/不可观测→hold-live（持 L/M）；无活体 observed=true→22 latch-only（释放 L/M）。
- recover 前置：必须先证明 attempt 的 launcher/CLI/live_children 全死（A 域链）；任一活/不可确认→23/30 零 WAL 写。

## 三、PID 发布与崩溃窗口（fork2→cli_spawned 前杀 supervisor）

### 3.1 权威来源

| 对象 | 来源 | 持久化 |
|---|---|---|
| supervisor | main fork1 返回+内存；W1 不写 | recover 取 WAL `spawned` 封套 pid/pstart/boot_id；无 spawned→23 不接管 |
| launcher/CLI | **W2 事件 `cli_spawned{cli_pid,cli_pstart,boot_id}`**（fork2 返回后、任何 gate/release 前 fsync） | WAL；main W3 后读取校验 |
| CLI 收养后 | 同一 cli_pid/pstart（execve 不变） | pidfd_open+fdinfo Pid/NSpid+/proc stat starttime+waitid(P_PIDFD) |

- 正常启动时序补：`spawned→cli_spawn_begin→fork2→cli_spawned→metadata_published→pidfd_sent→…`。
- `cli_spawn_begin` 不带 pid；`cli_spawned` 是唯一发布事件；封套 pid 是 supervisor，不得混用。

### 3.2 崩溃窗口（begin 有、cli_spawned 无/无效/半行）

- 唯一处理：
  1. `spawn_closed=false`、`observed=partial`（无条件，即使 ECHILD）、`cli_state=unknown`；**禁止 not_spawned**。
  2. 有界 drain（T_REAP）：`>0` 未知 pid→unidentified_reaped；`0`→unidentified_live；ECHILD→停；不向未知 pid 发信号。
  3. WAL 可写且 takeover(3)+halt(4) 成功→P2（22）；否则 hold-live；**禁 P1/P3/P4a/not_sent**。
  4. attempt_hold 增 `spawn_state:"open"`、`cli_pid:null`、`cli_pstart:null`、`reason:"cli_spawn_unpublished"`。
  5. 恢复：observed=partial∧spawn_state=open→23 人工，零 WAL 写；不自动 resolution/清 latch。
- observed=true 合取项新增 `spawn_closed`（`spawned` 存在；begin 存在⇒恰一条合法 cli_spawned）。
- pidfd 事件：POLLIN 唯一可依赖（zombie/终止）；POLLHUP 仅 Linux≥6.9 辅助；POLLERR 现行内核不产生（出现=fail-closed）；POLLNVAL=fd 非法（内部 30）；EINTR 重试；禁止 SA_NOCLDWAIT/SIG_IGN；SIGCHLD SIG_DFL；main 单线程；subreaper 不继承。

## 四、时间与 A0 门禁

- `T_HANDSHAKE_TOTAL=20s`（spawn_begin 起）；阶段 5s 仅上限。
- `T_CLI_WAIT=125s` 从 release_byte 成功起；`T_SUP_EXIT_FRAMED=126s` 从**完整合法 HOLD_REQ 帧+EOF**起（含 125s+1s）；`T_SUP_EXIT=5s` 从 P EOF 且无完整帧起；`T_REAP=5s`（TERM/KILL 起，1s 计入）；`T_EXEC_FRAME=5s`；`T_ABORT_WAIT=5s`；完整帧无 EOF→1s 协议违规→TERM/KILL；P 开无帧无 EOF→5s 协议违规→TERM/KILL；watchdog 180s（halt-live 例外）。
- A0 门禁：U-01/U-02 未冻结→A0 全单元（T0B-01..16、E16a–f、D0–D9、F-SEAL、installer 直调）BLOCKED；T0B-03/05/16 另需 F-SEAL；BLOCKED 不计分、不填 0/N/A。
