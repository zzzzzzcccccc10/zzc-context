## 二、四人一致确认的阻断

### 一致 1：启动链信任未闭合（A 主发现，D 交叉）

- **安装根**：`/usr/local` 在 Debian 可为 `root:staff 02775`（`/etc/staff-group-for-usr-local`），按 v38 严格祖先检查会每次 exit 10；若放宽则 staff 组可替换目录项，`lstat` 自身轮不到执行。安装/升级流程只有一句“独立 root 流程”，无步骤/原子性/回滚/测试。
- **状态根**：WAL/lock/sidecar/latch/log 的路径/属主/模式未定义，可能仍在 `/opt/astrbot`（0777）或 `/tmp`，普通用户可伪造 WAL/sidecar、删 latch，击穿证据与 hold。
- **退出码**：v38 删除 v37 全局表（0/2/10/11/20/21/22/23/24/30），矩阵仍引用 11/20/22/23；`hold+exit 22` 与“hold 不退出”冲突。
- **导入兜底**：`__main__` 之前的失败（缺入口、损坏入口、zip CRC、解释器启动失败）无法映射 exit 10；B02 被 wrapper SHA 遮蔽，测不到导入守卫。
- **deploy.sh**：无 shebang/stat 绝对路径/`$()` 限制与 VERSION 格式冲突；B01 字面命令不可执行（0644 无 shebang）；`--selfcheck` 与子命令不一致。
- **实验授权**：T0b/安装类测试不在 A1/A2 任一授权内；A1/A2 在三个文件中不一致（E14/E15 归属）。

### 一致 2：进程与 FD 契约未落地（B 主发现，D 交叉）

- **四状态 fd 清单**：全文未定义；表按名称列举而非进程×时点；main/supervisor 清单无写者/落点；白名单缺 0/1/2 与 supervisor 白名单。
- **R08 矛盾**：execve 调用时点实际仍持 `sidecar_w`/`error_ew`，矩阵断言 `{0,1,2,L}` 错误；应拆 R08a（launcher 自证）与 R08b（canary 外部观测）。
- **CLOEXEC**：v37 的“除 L 外全部非继承”在 v38 丢失；L 未显式 inheritable，sidecar_w/error_ew 可能泄漏进 CLI。
- **fork 失败**：`spawn_begin` 后 fork 失败与“main 最后一条写事件”冲突，重放无派生；F03 判据无合同。
- **单一终态**：`resolution` 写者条款自相矛盾；`operator_resolution` 与 `resolution` 唯一性未定义。
- **hold**：SIGUSR1 无 token 载荷、abort 是否取 L 未定、holder=supervisor 时 main 仍持 L、解除后 main 去向未定义 → 死结。
- **error pipe**：v37 的“写端唯一、0B/8B 判别、1–7B/>8B hold”丢失。
- **fd 证据**：`fd_snapshot` 未进入 `sidecar_merged`/事件枚举，无法独立还原。

### 一致 3：状态机与证据重放仍有矛盾（C 主发现，B/D 交叉）

- **migrate 相位**：§3.2 写 gate_authorized 在迁移后，§4.5 却要求 migrate evidence `gate=authorized`；三处互斥。
- **release 冲突**：§4.1“gate_authorized 且 sidecar 无 cli_release_received ⇒ hold”压掉 §4.4 的 release 失败派生 → 永久 hold。
- **派生前置**：sidecar exec_failed 派生未要求“已证终止/已回收”，在“有活体 ⇒ hold”之前执行 → 错误 not_sent。
- **重放顺序**：resolution/operator_resolution 采用前未校验；evidence-only/空 sidecar/恢复写者接管场景缺失。
- **生命周期**：v37 的跨事务门禁/latch 清除在 v38 被删；abandoned 只判“无活体”，无收束。
- **gate 载荷**：gate_authorized 不内联判定观测，重放无法独立验证。
- **退出码/result_unknown**：`result_unknown` 无承载事件；71/72/74→reason 映射缺失。

### 一致 4：测试矩阵不可交付（D 主发现，A/C 交叉）
