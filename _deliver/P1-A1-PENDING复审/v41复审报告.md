## 二、六项阻断

### P0-1 W3 重开 WAL 的追加位置未闭合

- v41 §3.3：W3 重开（O_RDWR + 尾部半行截断）→ `writer_takeover`；未规定截断后写位置在文件末尾。
- Linux `open()` 新 fd 偏移默认在开头；只有 `O_APPEND` 或显式 `lseek` 到末尾才保证追加；否则 `writer_takeover` 可能覆盖旧 WAL。
- 核心裁定 §4 提到 O_APPEND，但未把 W3 完整 flags 与截断操作组合。
- 必须冻结：W3 完整 openat flags；尾部半行定位/截断/fsync 顺序；截断后下一次 write 追加；`writer_takeover` 前后文件长度与 seq 校验。

### P0-2 audit dirfd 关闭/重开不一致

- G4/§4 一处要求用继承的 audit dirfd，另一处规定 fork1 子关闭后重开；§3.3 又写先关闭再重开。
- 继承 dirfd 已关闭后，supervisor 通过什么可信路径重开？重新打开 `/var/lib/astrbot-deploy/audit` 时必须验证祖先链、audit dev/ino 与 W1 锚点、目录替换/重定向、WAL 身份与预期长度。
- fstat 称“五元”却列 regular/nlink1/uid/0600/dev-ino/size，未统一定义字段组合与预期值。
- 应给“W1 锚点 → W2/W3 重开校验表”。

### P0-3 hold/HOLD_REQ/收尸/WAL 写权仍有多套时序

- 三处顺序不一致：差异裁定 §二.3（写 hold_request→关 release→发 HOLD_REQ→收尸）；核心裁定 §二流程图（收尸→关 log_fd→发 HOLD_REQ）；设计 §3.4（发 HOLD_REQ→收尸→关 log_fd→退出）。
- G2 失败路径未完整进设计（协议失败→main 超时关 P/SIGKILL/waitpid）。
- **W4 未定义**：§3.1 标 main 为 W1/W3/W4，但 G1–G10 只定义 W1–W3；HALT 下 abort 通知 main 写 operator_resolution 属 W3 还是 W4、writer/epoch/前置/接管条件未冻结。
- token 持久化顺序未写：latch 后、hold.token 前崩溃如何 recover orphan latch；token 先于 latch 出现如何清理；缺崩溃点状态表。

### P0-4 D0–D9 引用与实际状态表未对齐

- 核心裁定仅 10 个主状态摘要，无子状态；D5x → 41 未在 D0–D9 定义；E16e 引用 D6b/D7b 但无磁盘状态/恢复动作；设计/实验引用 C §2.6，但 v41 正式包无该文件。
- E16e 映射 S4→D6b/D8、S5→D7/D7b、S6→D7/D7b 无对应判据。
- 应给完整映射：journal phase × canonical × staged × old/prev × install.json → 动作 → 退出码 → 恢复后唯一状态；D5x/D6b/D7b 正式定义或删除引用。

### P0-5 矩阵前置/夹具不可独立复现

- P1–P14 引用 v40 矩阵/裁定 §四，不能当 v41 正式定义；F-* 引用“裁定 §四”，但该节是边界说明，无构造/验证/清理。
- F-SEAL 无完整封装/重封装/校验流程。
- T2-02 WAL fsync EIO 未区分一次性/持续故障，却要求后续 hold_request/attempt_hold 成功落盘。
- T3-02 未授权 BLOCKED 却填退出码 0（未执行不应填成功码）。

### P1-6 error pipe / sidecar 状态枚举缺逐项定义

- error pipe 称“五态”，实列 NONE/FRAME/SHORT/OVER/BAD/TIMEOUT/READ_ERR 七种；需区分终态与错误原因两层。
- sidecar SC0–SC6 与 absent/未合并/已合并/空/冲突/截断/替换无一一映射，未定义每种状态允许参与哪些推导。
- exec 判定 E/F 应定义为具体可验证证据。
- 建议合并一张证据状态表（error pipe/exec_frame/SC0–SC6/N1–N7）。
