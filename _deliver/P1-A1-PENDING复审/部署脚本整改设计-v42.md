## 一、写权模型（J1/J3/J4）

| 代 | writer | epoch | 起始标记 | 终止 | 事件集 |
|---|---|---|---|---|---|
| W1 | main | 1 | `attempt_created` | `spawn_begin`（最后一条）或 fork1 失败终态 | attempt_created…spawn_begin；失败加 spawn_failure/terminal/resolution |
| W2 | supervisor | 2 | `spawned` | terminal+resolution 或 `hold_request` | spawned…terminal/resolution；hold 路径最后一条 hold_request |
| W3 | main/recover | 3 | `writer_takeover(prev_epoch 1|2→3)` | close 前 | 补终态/not_sent_verified/attempt_hold |
| W4 | main | 4 | `halt`（3→4 唯一） | W4 出口 | 仅 halt/abort_requested/operator_resolution |
| W4R | main | 5 | `writer_takeover(prev_epoch=4→5, reason=halt_released)` | attempt_hold 后 close | attempt_hold |

- 单写者不变量：任一时刻至多一个 WAL 写 fd；1→2 由 spawned、3→4 由 halt、W3/W4R 由 takeover 标记（J1/J3/J4）。
- hold_request 后 supervisor 零 WAL 写（A-10）；不写 live_children。
- 死亡证明三态（G3）：pidfd POLLIN/ESRCH、/proc 不存在、starttime 不符=已退出；存活→23；无法确认→30；waitid ECHILD 不作证明。

## 二、hold / 收尸 / token（J3/J5）

### 2.1 supervisor 时序

```
hold_request{reason,last_seq} fsync
→ close(release_w)（不写 0x52）
→ 发 HOLD_REQ(type=5) 立即；失败 close(P) 继续
→ 收尸：¬exec_begin → SIGKILL launcher + waitpid(T_REAP=5s)
        有 exec 证据 → waitpid 至 T_CLI_WAIT=125s；仍活 → 记录内存 live，不回写
→ close(log_fd) → close(P) → _exit(0)
```

### 2.2 main 时序

```
收 HOLD_REQ / P EOF / supervisor pidfd POLLIN
→ 停 ACK/FIN
→ waitpid(supervisor)：无帧 T_SUP_EXIT=5s；有帧 T_SUP_EXIT_FRAMED=126s
→ 超时：close(P) → SIGTERM → 1s → SIGKILL → waitpid(T_REAP=5s)
→ W3 重开（J1/J2）→ writer_takeover fsync
→ 尾判定：hold_request→hold；terminal→不重复；矛盾→30
→ token 32B CSPRNG → run/<id>/hold.token 0600 明文+fsync → stderr 一行
→ latch O_EXCL 0600（取 ino）+fsync 文件/目录
→ attempt_hold{latch_ino,reason,live_children,token_sha256,cli_state} fsync
→ close(log_fd) → close(M) → close(L) → JSON 22 → exit 22
```

### 2.3 W4/W4R

- 形态：T-HALT（takeover 后写 halt(4)+HALT）、P-HALT（supervisor 未证死禁写 WAL，仅 HALT；死后补 takeover(3)+halt(4)）、F-HALT（WAL 不可写、HALT 可写）、M-HALT（均不可写，内存态+心跳）。
- 事件：W4 只写 halt/abort_requested/operator_resolution；不写业务事件；不释放 L/M；不自行 exit；心跳不含 token。
- 出口①：latch 成功 → writer_takeover(4→5) → W4R 写 attempt_hold → close log_fd → unlink HALT → close M/L → 22。
- 出口②：合法 intent → abort_requested → operator_resolution → A-14 清理 → 0。
- 出口③：SIGKILL → 残留 HALT/latch/token → 23。

### 2.4 token 崩溃点（J5）

| 崩溃点 | 状态 | 恢复 |
|---|---|---|
| latch 前 | 无 latch | 正常 |
| token 后、latch 前 | orphan token | 保留 token；有 intent/confirm→basis=hold_token→0；无凭据→23 |
| latch 后、attempt_hold 前 | latch（可含 token_sha256） | 有 token/intent→basis=latch→0；无凭据→23 |
| attempt_hold 后 | 完整 hold | 正常 recover/abort |
| resolution 后删 latch 前 | resolution+latch/token | 幂等清理，不重写；23 |
| token 写失败后 latch | token_sha256=null | 双故障：23 人工；不清理 token |

## 三、FD / WAL 重开 / 追加（J1/J2）

### 3.1 锚点

W1 `attempt_created`：`state_dir{dev,ino}`、`audit_dir{dev,ino}`、`wal{name,dev,ino,uid,gid,mode=0600,size=0}`、`boot_id`、`attempt_id`；创建后 `fsync(audit_fd)`；`spawn_begin.wal_off`。

### 3.2 从 `/` 逐级 openat（J2）

| 步骤 | 操作 | 校验 | 失败 |
|---|---|---|---|
| 1 | `open("/", O_RDONLY\|O_DIRECTORY\|O_NOFOLLOW\|O_CLOEXEC)` | 每级 fstat：dir、uid/gid=0、`mode&0022==0` | hold/halt |
| 2 | 逐级 `openat(prev, comp, 同 flags)` 到 state root | 末级 `dev/ino==state_dir`、0700 | hold/halt |
| 3 | `openat(state_fd,"audit",O_RDONLY\|O_DIRECTORY\|O_NOFOLLOW\|O_CLOEXEC)` | `dev/ino==audit_dir`、0700 | hold/halt |
| 4 | `openat(audit_fd, WAL, W2:O_WRONLY\|O_APPEND；W3/W4:O_RDWR\|O_APPEND；+O_CLOEXEC\|O_NOFOLLOW)` | 无 O_CREAT/O_TRUNC；regular、nlink==1、uid/gid=0、0600、`dev/ino==wal` | hold/halt |
| 5 | fstat size | W2==wal_off；W3≥wal_off | hold/halt |
| 6 | `/proc/self/fd` 计数 | state/audit/WAL 各恰 1 | NW |
| 7 | 关闭前 fstatat | dev-ino==WAL fd | STOP/NW |

### 3.3 W3 尾修复与追加（J1）

1. 从 `min(8192,size)` 尾向 `pread`；窗口无 `\n` 则倍增，直到起点 0 或 256 KiB；`complete_end=起点+idx+1`；到文件头仍无→0；`complete_end<wal_off`/超限→NV（不截断，30）。
2. 只读校验最后完整行；不合法→NV。
3. 重放裁决；不可写→关闭 fd，不截断不写。
4. 可写且半行：`ftruncate(complete_end)`→`fsync`→`fstat size==complete_end`；失败 STOP。
5. 写 `writer_takeover`（seq=last_seq+1）：n==len、fsync、size==complete_end+len。
6. 后续事件：写前 `fstat size==expected`；写 n==len；fsync；写后==expected+len。
7. 关闭前 fstatat 复核；WAL 不可写时 latch-only 22 或 halt。

### 3.4 FD 矩阵（launcher/CLI）

| FD | execve 前 launcher | CLOEXEC | exec 后 CLI |
|---|---|---|---|
| 0/1/2 | 打开（1/2 重定向） | false | 保留 |
| sidecar_w | 打开 | true | 关闭 |
| error_ew | 打开 | true | 关闭 |
| L/M/P/S/log/dirfd/pipe/pidfd | 不存在/关闭 | true | 关闭 |

- launcher 步骤：关闭批次 → 快照 0 `{0,1,2,release_r,sidecar_w,error_ew}`（71）→ 读 release → close(release_r) → 快照 A `{0,1,2,sidecar_w,error_ew}`（74）→ 写 exec_begin（无缓冲+fsync）→ execve。
- 快照 B `{0,1,2}`；泄漏→fd_leak_post_exec + unknown/hold。

## 四、协议与时间预算

- 36B 帧（大端）；pidfd 1 fd、done/ack/fin 0 fd；HOLD_REQ type=5、0 fd、reason_code/last_seq/challenge、supervisor→main、至多一帧。
- SCM_RIGHTS：控制缓冲 + MSG_CMSG_CLOEXEC；fd 按帧累计；CTRUNC 关闭；单帧最多 4。
- 发送：一帧一次 sendmsg；禁 0 长度；MSG_NOSIGNAL；0<n<36 不重试。
- EOF：请求≥1+返回 0+帧边界；半帧 0=截断；POLLRDHUP 不直接判 EOF。
- OOB：不设 SO_OOBINLINE 为启动条件；禁 MSG_OOB/SIOCATMARK。
- **时间预算（勘误）**：`T_HANDSHAKE_TOTAL=20s`；阶段 cap 5s；`T_SUP_EXIT=5s`；`T_SUP_EXIT_FRAMED=126s`；`T_CLI_WAIT=125s`；`T_REAP=5s`；`T_EXEC_FRAME=5s`；`T_ABORT_WAIT=5s`；TERM→KILL 1s；watchdog=FAIL；E12 校准不改 cap。

### 4.1 error pipe（J8）

| 态 | 层 | 判定 | 结论 |
|---|---|---|---|
| NONE | 终态 | 0B+EOF | 无帧（≠成功） |
| FRAME | 终态 | 8B、EXC1、errno 1..4095 | exec 失败 |
| SHORT | 错误原因 | 1–7B 后 EOF | hold |
| OVER | 错误原因 | ≥9B | hold |
| BAD | 错误原因 | 8B magic/errno 非法 | hold |
| TIMEOUT | 错误原因 | 5s 无 EOF | hold |
| READ_ERR | 错误原因 | read 其他错误 | hold |

- 仅 launcher 写、仅 W2 读并写 `exec_frame`+fsync；W3 不重读；迟到帧不改判。
