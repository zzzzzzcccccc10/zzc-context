## 一、六项优先修订（K1–K6）

| # | 修订 | 冻结结论 |
|---|---|---|
| K1 | **F-HALT/W4R epoch 持久化矛盾** | epoch 只能由 WAL 事件推进（spawned→2、takeover→3/5、halt→4）；HALT 文件仅镜像 `epoch/halt_seq` 作恢复提示，不作写权依据。**W4R 仅在 T-HALT（halt(4) 已持久化）允许**；F-HALT/M-HALT（WAL 不可写）下 latch 成功只进入 **latch-only hold 22**：不写 takeover(5)、不写 attempt_hold、更新 HALT 文件（可写时）后释放 L/M；recover 以 basis=latch 判定。 |
| K2 | **main 收养子进程与 live_children 证据** | supervisor 死后 launcher/CLI 由 main（subreaper）收养；main 写 attempt_hold 时 `live_children[]` 必须来自自身观测（`/proc/<pid>`+starttime、`/proc/<pid>/task/<pid>/children`、pidfd poll、waitpid(-1,WNOHANG)）；不得使用 supervisor 内存结果；不可观测 → `cli_state=unknown`、`live_children=[]` 且标注 `observed=false`，不得伪造。仍活 → 进入 halt（T-HALT）。 |
| K3 | **orphan token 授权** | token 后 latch 前（orphan token）：保留 token；recover 可凭 `hold.token` + 操作者 `--confirm`（token 匹配、文件内容 attempt_id/holder pid/pstart/nonce 匹配）写 `operator_resolution{basis=hold_token}`；无 confirm/不匹配 → 23。abort 对 orphan token：写 `abort.intent` → recover；token 不得自动清理（保留至 resolution）。 |
| K4 | **FRAME 必须 EOF** | error pipe 读到恰好 8B 后必须继续 poll/read 确认 EOF；8B 且随后 EOF → FRAME；8B 后仍有字节 → OVER/BAD → hold。`exec_frame{result:frame, nbytes:8, eof:true}` 才可作为 F。 |
| K5 | **T3-02/T2-02/T3-18/NOT-SENT** | T3-02 未授权=BLOCKED/N/A（不填 0）；T2-02 拆 a（一次性→22）/b（持续→halt-live N/A），W1 向量撤销；T3-18 三向量 A=23、B=23、C=30（不拆，逐向量唯一）；NOT-SENT 两条 basis：`n1n7`（¬E+N1–N7）与 `frame_proven`（E∧F，execve 失败=未执行）；N5 仍要求无 exec_begin，但 frame_proven 不受 N5 约束（E 存在）。 |
| K6 | **继承历史规范** | v41/v42 中未在 v43 重写的条款继续有效（见 §二）；P1–P14、F-*、case 以 v43 文件为当前完整定义，不得引用 v41/v40 替代。 |
