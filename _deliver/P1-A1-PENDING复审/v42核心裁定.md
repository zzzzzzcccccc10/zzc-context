## 二、W3 WAL 追加与 audit dirfd（J1/J2）

### 2.1 W1 锚点

W1 在 `attempt_created` 记录：`state_dir{dev,ino}`、`audit_dir{dev,ino}`、`wal{name,dev,ino,uid,gid,mode=0600,size=0}`、`boot_id`、`attempt_id`；创建 WAL 后 `fsync(audit_fd)`（目录项持久化）；`spawn_begin` 记录 `wal_off`（写后 size）。

### 2.2 W2/W3 重开校验表

| 步骤 | 操作 | 校验 | 失败 |
|---|---|---|---|
| 1 | `open("/", O_RDONLY\|O_DIRECTORY\|O_NOFOLLOW\|O_CLOEXEC)` | 每级 fstat：dir、uid/gid=0、`mode&0022==0` | hold/halt |
| 2 | 逐级 `openat(prev, comp, 同 flags)` 到 state root | 同上；末级 `dev/ino==state_dir`；0700 | hold/halt |
| 3 | `openat(state_fd, "audit", O_RDONLY\|O_DIRECTORY\|O_NOFOLLOW\|O_CLOEXEC)` | `dev/ino==audit_dir`；0700 | hold/halt |
| 4 | `openat(audit_fd, "attempt-<id>.jsonl", O_WRONLY|O_APPEND\|O_CLOEXEC\|O_NOFOLLOW)`（W2）/`O_RDWR|O_APPEND`（W3/W4） | 无 O_CREAT；regular、nlink==1、uid/gid=0、0600、`dev/ino==wal` | hold/halt |
| 5 | fstat size | W2：`==wal_off`；W3：`>=wal_off` | hold/halt |

### 2.3 W3 尾部修复与追加（J1 勘误）

1. 从 `min(8192,size)` 起从尾 `pread`；窗口内无 `\n` 则窗口倍增，直到起点 0 或达 **256 KiB**；找到→`complete_end=起点+idx+1`；到文件头仍无→`complete_end=0`；`complete_end<wal_off` 或窗口超限→NV（不截断，30）。
2. 只读校验最后完整行（JSON/seq/绑定）；不合法→NV。
3. 取重放裁决；**不可写→关闭 fd，不截断、不写**。
4. 可写且 `complete_end<size`：`ftruncate(fd,complete_end)`→`fsync`→`fstat size==complete_end`；失败→STOP→latch-only 22 或 halt。
5. 写 `writer_takeover`（seq=last_seq+1）：`os.write` 要求 n==len；`fsync`；`fstat size==complete_end+len`。
6. 后续每个事件：写前 `fstat size==expected`；写 `n==len`；`fsync`；写后 `==expected+len`；`expected+=len`、seq+1。
7. 关闭前 `fstatat(audit_fd,name,AT_SYMLINK_NOFOLLOW)` dev-ino==WAL fd；不符→STOP/NW。

### 2.4 不变量

- 追加位置只由 O_APPEND 保证；禁止仅 O_RDWR 假定末尾、禁止 lseek 无 O_APPEND、禁止 O_TRUNC。
- 截断只允许尾部半行；中间行不合法不修复。
- 重开失败：latch 可写→22 latch-only；否则 halt。
- 单写者：W1→W2→W3→W4→W4R；fork→close 窗口残余。

## 三、hold / W4 / W4R / token（J3/J4/J5）

### 3.1 唯一时序（token→latch）

```text
[supervisor]
hold_request{reason,last_seq} fsync
→ close(release_w)
→ send HOLD_REQ(type=5) 立即
→ 收尸：¬exec_begin → SIGKILL launcher + waitpid(T_REAP)
         有 exec 证据 → waitpid 至 T_CLI_WAIT=125s；仍活 → 记 live_children（不回写 WAL）
→ close(log_fd) → close(P) → _exit(0)
[main]
收 HOLD_REQ / P EOF / supervisor pidfd POLLIN
→ 停 ACK/FIN
→ waitpid(supervisor)：无帧 T_SUP_EXIT=5s；有帧 T_SUP_EXIT_FRAMED=126s
→ 超时：close(P) → SIGTERM → 1s → SIGKILL → waitpid(T_REAP=5s)
→ W3 重开（J1/J2）→ writer_takeover fsync
→ 读 WAL 尾：hold_request→hold；terminal→不重复；矛盾→30
→ token 生成 32B CSPRNG → hold.token 0600 明文+fsync → stderr 一行
→ latch O_EXCL 0600（取 ino）+fsync 文件/目录
→ attempt_hold{latch_ino,reason,live_children,token_sha256,cli_state} fsync
→ close(log_fd) → close(M) → close(L) → JSON 22 → exit 22
```

时间预算：`T_HANDSHAKE_TOTAL=20s`；阶段 cap 5s；`T_SUP_EXIT=5s`；`T_SUP_EXIT_FRAMED=126s`；`T_CLI_WAIT=125s`；`T_REAP=5s`；`T_EXEC_FRAME=5s`；`T_ABORT_WAIT=5s`；TERM→KILL 1s；E12 校准不改 cap。

### 3.2 W4 / W4R（HALT）

- **四种形态**：T-HALT（已 takeover，写 `halt(4)`+HALT 文件）；P-HALT（supervisor 未证死，**禁写 WAL**，仅 HALT 文件；死后补 takeover(3)+halt(4)）；F-HALT（WAL 不可写、HALT 文件可写）；M-HALT（WAL 与 HALT 均不可写，内存态+心跳）。
- **W4（main/epoch=4）**：只写 `halt`/`abort_requested`/`operator_resolution`；不写业务事件；不释放 L/M；不自行 exit；心跳不含 token。
- **出口①**：latch 成功 → `writer_takeover(prev_epoch=4→5, reason=halt_released)` → **W4R（main/epoch=5）写 `attempt_hold`** → close log_fd → unlink HALT → close M/L → 22。
- **出口②**：合法 abort.intent → `abort_requested` → `operator_resolution` → 按 A-14 顺序清理 → close M/L → 0。
- **出口③**：SIGKILL → 残留 HALT/latch/token → 下一事务 23。
- halt(4) 必须落盘（M-HALT 除外，以 HALT 文件/内存态；P-HALT 死亡证明后补写）。

### 3.3 token 崩溃点（J5 勘误）

| 崩溃点 | 状态 | 恢复 |
|---|---|---|
| latch 前 | 无 latch | 下一事务正常 |
| token 后、latch 前 | orphan token，无 latch | **保留 token**；有 intent/confirm → operator_resolution{basis=hold_token} → 0；无凭据 → 23 |
| latch 后、attempt_hold 前 | latch（可能含 token_sha256），无 attempt_hold | 有 token/intent → basis=latch → 0；无凭据 → 23 |
| attempt_hold 后 | 完整 hold | 正常 recover/abort |
| resolution 后、删 latch 前 | resolution + latch/token | 仅幂等清理，不重写；23 |
| token 写失败后 latch | `token_sha256=null` | 双故障：23 人工；不清理 token |
| orphan token（长期） | token 无 latch | 保留至 resolution；不自动清理 |

## 五、证据状态表（J8）

### 5.1 error pipe

| 类 | 层 | 判定 | 结论 |
|---|---|---|---|
| NONE | 终态 | 0B+EOF | 无帧（≠成功） |
| FRAME | 终态 | 8B、magic EXC1、errno 1..4095 | exec 失败 |
| SHORT | 错误原因 | 1–7B 后 EOF | hold |
| OVER | 错误原因 | ≥9B | hold |
| BAD | 错误原因 | 8B 但 magic/errno 非法 | hold |
| TIMEOUT | 错误原因 | T_EXEC_FRAME=5s 无 EOF | hold，禁 not_sent |
| READ_ERR | 错误原因 | read 其他错误 | hold |

### 5.2 sidecar SC0–SC6

| 态 | 实际情形 | 允许推导 |
|---|---|---|
| SC0 | 文件不存在 | 仅 DR1–DR5；有 cli_spawn_begin → 矛盾 hold |
| SC1 | 0B/仅 created | not_sent 可（¬E） |
| SC2 | 完整前缀（含 created，尾部半行丢弃） | not_sent 可（¬E） |
| SC3 | 自退 terminal（exec_failed/aborted/halt） | aborted∧¬E→not_sent；exec_failed→FAILED；halt→hold |
| SC4 | 损坏（非法 JSON/seq/绑定/非 regular） | hold |
| SC5 | 与 WAL/帧冲突 | hold |
| SC6 | 写者仍活 | hold_live |

### 5.3 N1–N7 与 E/F

- N1 sidecar 态可判（SC0–SC2/SC3-aborted）；N2 绑定一致；N3 收尸+cgroup 空+无未识别子进程；N4 授权态确定；N5 无 exec_begin（P1 构建已验证）；N6 无成功/失败证据（0B 或 unobserved）；N7 not_sent_verified 已持久化。
- E=合并后 sidecar 的 `exec_begin`；F=8B 帧或 sidecar `exec_failed`；`E∧F`→FAILED；`E` 无 F→UNKNOWN；`¬E`+N1–N7→NOT_SENT。
