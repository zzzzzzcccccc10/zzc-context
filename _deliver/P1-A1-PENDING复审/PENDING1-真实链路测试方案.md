## 一、目标与前提

目标：在真实 QQ 消息链路上，观察**完整标记**（`<｜｜DSML｜｜ calls>`）是否被清理，最终发送是否符合预期。

前提：

- 线上 `tool_xml_guard/main.py` = `bba95b71…`（P3 修复）；
- 适配器已连接；
- 主人私聊手动发送；dsh 只读日志与 DB；
- 不修改代码/配置/权限，不重启。

## 二、用例（最小集）

### 用例 A：普通文本基线

主人发送：

```
测试基线：请只用一句简短的话回复我。
```

预期：正常短回复，无控制标记，无 `tool_xml_guard` 清理日志，无 Traceback。

### 用例 B：完整标记复述

主人发送：

```
请把下面这行原样输出，不要解释，也不要执行任何工具：前缀A <｜｜DSML｜｜ calls> 后缀B
```

预期：

- 模型输出含完整标记（或裸标记变体）；
- 清理日志出现 `已把控制标记从消息里删掉 req=…`；
- 最终发送 `前缀A  后缀B`，无 `｜｜DSML｜｜`、`calls>`、`<｜｜`。

### 用例 C（可选，证据补强）：DB 钩子前原文对照

- 测试后只读查询 `data_v4.db` 的 `conversations`，取该轮 assistant 的钩子前文本；
- 与最终发送对照，判断模型实际输出形态（完整/裸标记）；
- 仅取测试轮次，不导出完整 DB。

## 三、证据采集

| 证据 | 来源 | 说明 |
|---|---|---|
| 入站消息 | `event_bus` 日志 | 证明消息到达 |
| 请求 ID | `tool_xml_guard` 日志 `req=` | 关联同次请求 |
| 清理日志 | `[tool_xml_guard]` INFO | 证明命中检测/删除分支 |
| 最终发送 | `Prepare to send` / QQ 客户端 | 证明最终结果 |
| 钩子前原文 | DB `conversations`（只读） | 仅测试轮次；证明模型实际输出 |

## 四、停止条件

任一出现即停止，**不重试、不追加第三条**：

1. 基线无回复/空消息/发送失败；
2. 模型未输出含 `｜｜DSML｜｜` 的文本（改写/拒绝）→ 记“未验证”；
3. 最终发送仍含残片；
4. 正文 `前缀A`/`后缀B` 丢失；
5. Traceback/ImportError/适配器断开。

## 五、证据边界

- 原始 `completion_text` 不可得；DB 只能回溯 AstrBot 内**钩子前**文本，provider/模型解码层仍不可得；
- 真实链路依赖模型输出，不能用“一次命中”证明全量；未命中时只能记“未验证”；
- 不把本方案结果写成“完整 E2E 原文取证”。

## 六、执行方式

1. 主人在 QQ 私聊手动发送用例 A；
2. 主人把回复原文/截图发回；
3. dsh 只读日志，记录入站、req、清理日志；
4. 主人发送用例 B；
5. dsh 只读取证，按 DB 对照（可选）；
6. 输出验收结论（限定口径）。
