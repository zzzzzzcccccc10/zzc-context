## 一、冻结裁定总表（H1–H12）

| # | 裁定 | 要点 |
|---|---|---|
| H1 | **L 只由 main 持有** | supervisor/launcher/CLI 不保留 L；L `CLOEXEC=true`，fork1 子进程在首条关闭继承副本；CLI 不继承 L |
| H2 | **hold 写者 = main** | 只有 main 能写 `attempt_hold`；supervisor 发现需 hold 时通过协议通知 main 或退出，由 main 收尸后写 |
| H3 | **hold 退出模型** | main 写 latch（先，O_EXCL 取 ino）→ 写 attempt_hold（含 latch_ino）fsync → 终止/回收 launcher（或证明未 exec）→ 释放 L/M → exit 22；**删除 SIGUSR1 唤醒 holder** |
| H4 | **operator 解除** | `abort --confirm` 写 token 文件（O_EXCL 0600，不取 L）→ 通知 main（存活则 SIGUSR1 给 main）或 `recover --repair`（main 已死，取 L）→ 校验 token/latch → 写 operator_resolution fsync → 删 latch + fsync(dir) → 释放 L → 退出；幂等：同 token operator_resolution 已存在则只清 latch |
| H5 | **WAL 写权三相位** | W1 main（attempt_created…spawn_begin）；W2 supervisor（spawned 起…terminal+resolution）；W3 main 恢复（waitpid 证 supervisor 终止后，takeover 起） |
| H6 | **fork1 顺序** | spawn_begin fsync → fork1；子首条 close(P)；父成功 close(S)+close(log_fd)（写权移交），失败保留 log_fd 写 spawn_failure |
| H7 | **fork2 顺序** | supervisor 写 cli_spawn_begin fsync → fork2；子首条 close(S)/close(release_w)/close(error_er)/close(log_fd)/close(M)/close(dirfd)；父关 release_r/error_ew/sidecar_w 副本 |
| H8 | **spawned 先于 fork2** | `spawned` fsync 必须先于 fork2；`¬spawned ⇒ 未 fork2`，派生 not_sent 需同时 ¬cli_spawn_begin ∧ ¬cli_spawned ∧ sidecar 不存在 |
| H9 | **写者唯一性** | 任一时刻至多一个 WAL 写者；fork→close 窗口声明残余；WAL 用裸 `os.write`（无 Python 缓冲）；封套含 writer/epoch |
| H10 | **L/M/Seq 分离** | L 全局（main 独占）；M attempt（main 独占，用于写权/收束）；Seq 每次 append 独立 flock；三者独立 |
| H11 | **CLI 不持锁** | CLI 不继承 L/M；互斥保证降级为“main 存活期间持 L”，main 崩溃即锁释放（已知残余，由 WAL/latch 判定） |
| H12 | **T-NOT-SENT 前提** | exec_begin 必须无缓冲 write + execve 前 fsync；不满足不得以 ¬exec_begin 推断未执行，只能 hold/unknown |

## 二、hold/锁模型（冻结）

### 2.1 状态与不变量

- hold 是非终态；写 `attempt_hold{reason,holder=main,holder_pid,holder_starttime,token_sha256,cli_state,live_children,latch_ino}` + latch 文件。
- hold 后状态机禁止 gate_authorized/release/exec；不得倒回 not_sent。
- hold 前必须已终止/回收 launcher，或证明 `¬exec_begin` 且 release 未写；记录 `live_children[]`。
- latch：`latch/manual-latch-<id>.json`（O_EXCL 0600，内容 attempt_id/token_sha256/reason/created）；先建 latch 取 ino，再写 attempt_hold。
- latch 写不进 → hold_and_halt（main 不退出、持 L、stderr 循环）；SIGKILL 后无 latch 保护，属残余。

### 2.2 解除

- abort：只读状态根、读 WAL attempt_hold、pidfd_open(main)+starttime 校验；写 token 文件（O_EXCL 0600，含 attempt_id/token/main pid/pstart/nonce）；不取 L；SIGUSR1 通知 main（无载荷）。
- main 被唤醒：校验 token/latch/身份 → 写 `operator_resolution{operator,attempt_result,reason,authority_seq=hold_seq,token_sha256,latch,holder,decided_at}` fsync → 删 latch fsync(dir) → 释放 L/M → 退出。
- main 已死：`recover --repair` 取 L → 写 `writer_takeover` → 校验 token → 写 operator_resolution（若不存在）→ 删 latch → 释放 L。
- 幂等：recover 先查同 attempt+token_sha256 的 operator_resolution；已存在则只清 latch，不重写。
- operator 结论限制：未 gate 可 not_sent/aborted；已授权未 release 可 not_sent；已 release 无 exec 证据只能 result_unknown；有 exec 证据只能一致结论。

### 2.3 锁与残余

- L 只 main 持有；supervisor/launcher/CLI 不继承（fork 后首条关闭副本；L `CLOEXEC=true`）。
- M 只 main 持有；supervisor/launcher 不继承。
- Seq 每次 append 独立 fd `flock(EX)`，不跨 fork。
- 残余：main 崩溃即 L 释放；下一事务按 WAL/latch 判定；已知残余写入风险章。

## 三、两次 fork 顺序（冻结）

```text
main: acquire L → acquire M → 建/核验日志/sidecar/unresolved → 写 attempt_created…spawn_begin（每行 fsync）
 → fork1 supervisor
   子 supervisor 首条：close(P)、close(L 副本)、close(M 副本)、close(日志 fd 副本[若继承])
   父 main 成功：close(S)、close(log_fd)（写权移交）
   父 main 失败：保留 log_fd → 写 spawn_failure/not_sent/resolution
 → supervisor 重开 log_fd → 写 spawned(fsync) → 建 release/error pipe → 写 cli_spawn_begin(fsync)
 → fork2 launcher
   子 launcher 首条：close(S)、close(release_w)、close(error_er)、close(log_fd)、close(M)、close(dirfd)
   父 supervisor：close(release_r)、close(error_ew)、close(sidecar_w 副本)；保留 S、log_fd
 → pidfd_open + 元数据发布 → 发 pidfd 帧 → done 帧
 → 等 ACK/FIN/EOF → gate → 迁移 → release → 观测 exec → wait → 合并 sidecar → terminal+resolution → 退出
 → main waitpid 后：重开 log_fd（若需补 resolution）→ writer_takeover → 补/清理 → 释放 L
```

- 端点：P 仅 main（fork1 子关闭）；S 仅 supervisor（fork1 父关闭）；launcher 不继承 P/S（fork2 子首条 close(S)）。
- `spawned` 必须 fsync 先于 fork2；`cli_spawn_begin` 先于 fork2。
- 写权：fork1 成功父 close(log_fd)，子重开；fork1 失败父保留；fork2 子关 log_fd；supervisor 写至 terminal+resolution。
- 快照 A（execve 前）：`{0,1,2,L?,sidecar_w,error_ew}`——但 H1 规定 launcher 不持 L，故快照 A 实际为 `{0,1,2,sidecar_w,error_ew}`；若保留 L 则违反 H1。裁定：**launcher 不持 L**，快照 A 不含 L；文档同步。
- 快照 B（exec 后）：`{0,1,2}`（CLI 不持 L/M/socket），1/2 指向 run 日志/ /dev/null。
- 写者唯一：任一时刻一个写者；fork→close 窗口残余。

## 四、WAL 写权转移（冻结）

| 相位 | 写者 | 起止 | 前置 |
|---|---|---|---|
| W1 | main | attempt_created…spawn_begin | 持 L/M；log_fd 打开 |
| W2 | supervisor | spawned…terminal+resolution | fork1 成功；重开 log_fd；spawned fsync 先于 fork2 |
| W3 | main | writer_takeover…补 resolution/清理 | waitpid 证 supervisor 终止；重开 log_fd |

- 不变量：至多一个写者；WAL 裸 `os.write`；封套 `writer/epoch`；Seq 追加锁。
- 失败：fork1 失败 → main 保留 log_fd 写 spawn_failure/not_sent/resolution；fork2 失败 → supervisor 写 cli_spawn_failure/not_sent/resolution，main 只 finalize。
- 写权转移点：fork1 成功后父 close(log_fd) 即移交；父失败不移交。
- W3 仅在 supervisor 已证终止且 WAL 无 terminal+resolution 时启用；先 `writer_takeover`，再补；若已有 terminal+resolution 则不写，只清理。
- 禁：main 在 supervisor 存活时写业务事件；supervisor 写 resolution 后 main 重写；双 writer 并发。
