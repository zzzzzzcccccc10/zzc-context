## 一、冻结决定（G1–G10）

| # | 决定 |
|---|---|
| G1 | **hold 顺序改为“收尸后写”**：supervisor 发现需 hold → 写 `hold_request`（W2 最后一条业务事件）→ 停止放行 → 终止/回收 launcher → close log_fd → 退出；main waitpid 证 supervisor 终止 → W3 takeover → 写 latch + attempt_hold → 释放 L/M → exit 22。**删除“main 先写 attempt_hold 再终止 supervisor”** |
| G2 | **hold 请求协议**：新增 36B 帧 type=5 `HOLD_REQ`（challenge 同规则、0 fd、载荷 reason/last_seq），supervisor 发送后不再写业务事件；main 收到或 P EOF 后按 waitpid 处理；协议失败则 main 超时后关闭 P 并等待 supervisor 退出（超时 SIGKILL + waitpid） |
| G3 | **非子进程死亡证明**：recover 取 L 后不得以“取到 L”判 supervisor 死亡；必须满足：pidfd poll(POLLIN) 或 ESRCH，或 `/proc/<pid>` 不存在，或 starttime 不符；**无法确认 → 释放 L、exit 30/23，不接管**。旧 supervisor 存活 → 不接管（23/30） |
| G4 | **W2/W3 重开 log_fd 规则**：用继承的 audit dirfd `openat("attempt-<id>.jsonl", O_WRONLY\|O_APPEND\|O_CLOEXEC\|O_NOFOLLOW)`；fstat dev/ino 与 W1 记录的 WAL 锚点一致；不一致 → 停止写、hold；首条事件 seq = 前驱 seq+1；W3 同规则，重开后先写 writer_takeover |
| G5 | **error pipe 正式合同**：supervisor `pipe2(O_CLOEXEC)`；fork2 子关 error_er、保留 error_ew；父关 error_ew、保留 error_er；launcher execve 失败写恰好 8B `EXC1+u32 BE errno`，成功/其他失败不写；exec 成功由 CLOEXEC 关 error_ew → 0B EOF；读规则：0B=无帧、8B=失败、1–7B/>8B=hold、EINTR 重试、超时 hold；launcher 未写帧而异常退出 → 0B EOF 由 exit code 判别；supervisor 崩溃 → main 收尸后按 sidecar/exit code 判 |
| G6 | **安装 D0–D9 落盘**：完整状态表（journal×canonical×staged×install.json→唯一动作/结果）写入设计正文；E16e 按 D0–D9 逐项映射；首装/升级/交换前/交换后 journal 前/selfcheck/rollback/恢复再崩溃全覆盖 |
| G7 | **矩阵修正**：T1-13 方向修正（¬exec_begin 不得判 exec 失败；有 exec_begin+8B→FAILED；有 exec_begin 无证据→UNKNOWN）；数字统一 101 case / N1–N7 / evidence 12 行；T2-03/T2-20/T4-04 拆分；前置条件表 P1–P14 定义；T0B-03 夹具重新封装 SHA/VERSION/install.json；T3-01 执行器接口版本化 |

| G9 | **M 锁路径**：`run/<attempt_id>/attempt.lock`（0600，O_NOFOLLOW，flock EX）；创建于 attempt_created 前；释放于 log_fd 关闭后、L 之前；W3/recover 同规则 |

## 二、hold/WAL 写权时序（冻结）

```text
[W2] supervisor 发现需 hold（无法持久化/不可判定/sidecar 冲突）
  → 写 hold_request{reason,last_seq} fsync
  → 停止放行（close release_w，不写 0x52）
  → 终止/回收 launcher（若已 exec 无法终止则记录 live_children，等待收尸）
  → close log_fd
  → 通过 P 发送 HOLD_REQ 帧（type=5）；失败则关闭 P
  → 退出（waitpid 由 main 收）
[main] 收到 HOLD_REQ 或 P EOF + waitpid(supervisor) 成功
  → 重开 log_fd（G4）
  → 写 writer_takeover（W3）fsync
  → 写 latch（O_EXCL 0600，取 ino，fsync 文件+目录）
  → 写 attempt_hold{latch_ino,reason,live_children,token_sha256,cli_state} fsync
  → close log_fd
  → 释放 M → 释放 L
  → 写 stdout JSON（22）→ exit 22
```

- supervisor 存活期间 main 不写 attempt_hold（H2 满足：main 只在 W3 写）。
- supervisor 已死且未写 hold_request → main 收尸后按 C 的 DR/evidence 判定是否 hold；需 hold 则同上（latch+hold）。
- `hold_request` 只是“请求”，不改变终态；其存在不构成 hold 证据，必须 attempt_hold 落盘。
- 若 main 在 W3 写 hold 时崩溃：latch 已写、attempt_hold 可能未写 → 下一调用见 latch → 23；recover 按 orphan latch 规则（C-109）修复。

## 三、非子进程死亡证明（冻结）

recover（新进程）判定旧 supervisor 状态：

| supervisor 状态 | 判定证据 | 动作 |
|---|---|---|
| 存活 | pidfd poll 无 POLLIN 且 `/proc/<pid>` 存在且 starttime 匹配 | 不接管；释放 L/M；exit 23（或 30） |
| 已退出 | pidfd poll(POLLIN) 或 ESRCH；或 `/proc/<pid>` 不存在；或 starttime 不符（PID 复用） | 可 W3；写 writer_takeover 后继续 |
| 无法确认 | pidfd 不可用/`/proc` 不可读/身份字段缺失 | fail-closed：释放 L/M；exit 30；不写 WAL |

- 不得用 `waitid(P_PIDFD)` 等待非子进程；`waitid` 返回 ECHILD 不构成死亡证明。
- `abandoned` 判定叠加：L 可取 + supervisor 已死证明 + cgroup 空/无记录 pid 存活；否则 hold/unknown。
- 旧 main 崩溃 + 旧 supervisor 存活：recover 不得接管，只能 23/30 报告；等 supervisor 退出后重试。

## 四、W2/W3 重开 log_fd（冻结）

- 目录 fd：main 在 W1 打开 `audit/` 的 `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC`，fork1 子关闭；supervisor 重新打开 audit dirfd（或继承后关闭副本再重开，规则一致）。
- 文件：`openat(audit_dirfd, "attempt-<id>.jsonl", O_WRONLY|O_APPEND|O_CLOEXEC|O_NOFOLLOW, 0600)`；fstat 校验 regular、nlink==1、dev/ino 与 `attempt_created` 锚点一致；不一致 → 不写、hold/halt。
- 写：单行裸 `os.write` + fsync；seq 从 `last_seq+1` 严格递增；W2 首条 `spawned`，W3 首条 `writer_takeover`。
- 关闭：W2 写完 terminal+resolution 后 close；W3 写完补/清理后 close；main 最终 close L 前不得有写 fd。

## 五、error pipe 合同（冻结）

| 项 | 合同 |
|---|---|
| 创建 | supervisor 在 fork2 前 `pipe2(O_CLOEXEC)`；记录两端 dev/ino 于 `cli_spawn_begin` |
| 端点 | fork2 子：关 error_er，保留 error_ew；父：关 error_ew，保留 error_er |
| 写 | 仅 launcher 在 execve 失败时写恰好 8B（`EXC1`+u32 BE errno）；其他失败/成功不写；短写不重试（视为持久化失败 72） |
| 读 | supervisor 在 release 写后读：0B+EOF=无帧；8B=失败帧；1–7B then EOF=截断→hold；>8B/magic 错=协议错误→hold；EINTR 重试；超时（deadline）→hold |
| EOF | exec 成功时 CLOEXEC 关 error_ew → 0B EOF；launcher 异常退出未写帧 → 0B EOF，由 exit code 判别（exec_begin 存在时一律 CLI 码） |
| 崩溃 | supervisor 崩溃 → main 收尸后按 sidecar/exit code/error pipe 已读结果判定；error pipe 未读 → 不可作为成功/失败证据，只能 unknown/hold |
| 与 sidecar 关系 | sidecar `cli_exec_failed` 与 8B 帧互为交叉；冲突 hold；0B 不等于成功 |
