## 一、spawn_closed 与 cli_spawn_failure

- `spawn_closed=true`：`spawned` 存在 ∧（`cli_spawn_begin` 不存在 ∨ 恰一条合法 `cli_spawned` ∨ 恰一条合法 `cli_spawn_failure{stage:"fork2",errno}`）。
- `cli_spawn_failure` 是 fork2 失败的合法终止：launcher 从未存在；observed 可 true；允许 not_sent(`cli_launcher_spawn_failed`) 20。
- begin∧¬spawned∧¬cli_spawn_failure → spawn_closed=false、observed 至多 partial；唯一处理=崩溃窗口（P2 或 hold-live；禁 not_sent）。
- 半行 spawn 事件被尾修复截断后视为无该事件；不得补写。
- `cli_spawn_failure` 与 `cli_spawned` 并存→invalid/HOLD。

## 二、时间线（T2-21 修正）

- `t0`=完整合法 36B HOLD_REQ 帧收齐；`t_eof`=随后 EOF（≥t0）。
- 合法帧+EOF：`T_SUP_EXIT_FRAMED=126s` 从 `t_eof` 起（含 125s+1s）。
- 仅 EOF 无帧/截断：`T_SUP_EXIT=5s` 从 `t_eof` 起。
- 完整帧但 EOF 未到：`T_EOF_WAIT=1s` 从 t0 起；超时=协议违规→TERM/KILL（T_REAP=5s）。
- P 开、无帧、无 EOF：从 supervisor 死亡证明/收尸起点起 5s 协议违规→TERM/KILL；不得等 watchdog。
- T2-21a：EOF 后 supervisor 不退出→t_eof+126 TERM、+127 KILL、T_REAP+131；T2-21a2：EOF 后 126s 内退出→无 TERM、正常 finalize；两分支互斥；T2-21c：EOF 无帧→+5 TERM、+6 KILL。

## 三、W4R 失败与 hold-live 优先级（T3-22 修正）

- W4R 失败（S1/S2a/S2b/S3a/S3b；S4 不属于 W4R 失败）后必须**重新观测**：
  - `live≠[]` 或 `observed≠true` → P4b hold-live（持 L/M、心跳、SIGKILL→signal9；next 23）；不得 22。
  - 仅 `live=[] ∧ observed=true`（活体已回收、spawn_closed）→ 22 latch-only。
- 五子态各两出口：`-live`（hold-live）、`-dead`（22 latch-only）；S4（attempt_hold 已持久）单列三阶段：S4-live→hold-live（无退出码）；S4-first（无活体 observed=true、首次错误返回、未写 resolution）→22，basis=attempt_hold；S4-recover（同现场后续 recover，A 域死亡证明通过）→写 resolution（epoch5 文件）+audit+清理→0。
- 不补 takeover5/attempt_hold；S3a 首次不截断，下次 recover 尾修复→S1。
- 恢复 basis：S1/S2a/S2b/S3a/S3b=latch；S4=attempt_hold；recover 前置 A 域证明 launcher/CLI/live_children 全死；observed=partial∧spawn_state=open→23 人工。

## 四、resolution 双写原子性

- **前置**：recover 先通过 A 域死亡证明（launcher/CLI/live_children 全死）；有活体/不可观测→hold-live，不得进入 resolution 决策表；文件存在不能覆盖 hold-live。

- 载体：`run/<id>/resolution.json`（0600、O_EXCL、单行 ≤4KiB、fsync file+dir）+ WAL `operator_resolution`（仅 WAL 可写且末 epoch=4）+ 审计 `run/<id>/resolution.audit.json`（0600、O_EXCL、单行：`{v,attempt_id,resolution_sha256,wal_audit:"present|missing",audit_record:"written",created}`，fsync file+dir）。**只有成功写入才写 `audit_record:"written"`；写入失败不向文件写 write_failed，只 stdout/stderr 记 `audit_record_write_failed`；残留校验失败→unknown，不读权威、不参与 resolved、不阻塞 0。**
- 写序：①文件→②WAL→③清理；文件权威、WAL 审计。
- **缺失恢复唯一六行表**（前置 A 域死亡证明；有活体/不可观测→hold-live，不进入）：
  1 文件有效→0（不重建）；2 损坏/字段不符→30；3 文件缺+WAL epoch4 operator_resolution 完整且身份一致→重建→0；4 文件缺+epoch5 无 WAL 事件→30；5 文件缺+无完成证明→30；6 文件缺+WAL 事件身份/字段不一致→30。非 epoch4/事件不完整/身份缺失一律 30、零清理、保留现场。
- **重建身份必需字段**（缺任一→30）：WAL `attempt_created` 的 attempt_id/boot_id/state-audit-WAL-run 四组 dev-ino；`operator_resolution`（epoch4）的 basis/authority_seq/anchor/token_sha256/**resolved_at**；`attempt_hold` 的 latch_ino/token_sha256/observed/spawn_state；`halt`（若存在）的 halt_seq。token/latch/HALT 文件若存在则 token_sha256/latch_ino/attempt_id 必须一致；正常清理删 token/latch 后只依赖 WAL 字段，缺任一→30，不得用“文件应存在”补足。重建文件字段：v/attempt_id/basis/authority_seq/anchor/token_sha256/observed/spawn_state/resolved_at；resolved_at 复制 WAL 值，不得用当前时间。attempt_hold 缺整条→30；halt 存在缺 halt_seq→30。
- 审计残留：短写/半行/fsync 未确认→unknown；O_EXCL 占用不覆盖，best-effort 归档 `resolution.audit.failed`（不覆盖已存在目标，RENAME_NOREPLACE 或 link+unlink；失败保留原文件+unknown）；后续 recover 见 `.failed` 只记录 unknown、不读权威、不覆盖/不删除。
- **audit 交叉证据唯一规则（WAL-only）**：`present` 当且仅当 audit 内容校验通过 **且** WAL 存在 `operator_resolution`（epoch4、完整、身份一致）；**不得用 resolution.json 作为独立交叉证据**（仅比 resolution_sha256）；无 WAL epoch4→unknown。写入时 fsync EIO→当次 unknown；重启后重新验证（方案 B），可转为 present。
- 文件成功/WAL 失败：以文件为准，不重写 WAL，记 `wal_audit_missing`；文件失败：不写 WAL，30/23；文件已存在：同 token 幂等清理、异 token 23；**文件缺失一律服从 §4 六行表**（仅 epoch4 operator_resolution 完整且身份一致可重建；其余 30、零 WAL 写、零清理、保留现场）；两者不一致→30 保现场。
- 清理顺序：intent→HALT→token→latch；**resolution.json 不删**（完成态标记，随 run/<id> 归档）；WAL 事件不删；每步 fsync 目录；ENOENT 容忍；同 token 重入只续清理。
- 防重复：文件 O_EXCL；WAL 事件最多一条；同 token 幂等、异 token 23。

## 五、P3a/P4a/P1-H/token 失败

- P3a：WAL 不可写；HALT open/create 成功，但 write/fsync 实际失败（`halt_fsync=EIO`）→22 latch-only、无 HALT、basis=latch。
- P4a：WAL 不可写；HALT open/create 或预检失败（`halt_dir=EACCES`，未尝试写）→22 latch-only、无 HALT、basis=latch。
- 互斥：P3a 有“打开成功+写/fsync 失败”证据；P4a 有“打开/预检失败”证据；同一现场只落一条。
- P1-H：attempt_hold 未完整/半行→22 latch-only、basis=latch、WAL 末 takeover(3)、半行留待下次；attempt_hold 完整写+fsync EIO→重启重放完整→按 S4、basis=attempt_hold（不得机械 latch-only）。
- token 失败（形态：create 失败/短写/完整写+fsync EIO/目录 fsync 失败/半行）：token_untrusted、token_sha256=null；latch 成功→23、latch 保留、不写 resolution；latch 失败→hold-live（P4b）；不删 token。
