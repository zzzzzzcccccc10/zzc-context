## 二、四个队友独立一致确认的阻断

### 一致 1：启动链不可信（A 主发现，D 交叉）

- A：`/opt/astrbot` 及下级 0777、`main.py` 0666；若 helper 放该目录，普通用户可同时替换 `deploy.pyz` 与 `VERSION`，SHA 校验形同虚设；`deploy.sh` 未固定绝对 `/usr/bin/python3`（v37 退化为裸 `python3`）、未校验自身/祖先链、未定义校验失败退出码；T0 定义自相矛盾（§2.1 要求实测 vs §7.1 纯静态）；zipapp 构建不可复现（mtime 影响字节、`SOURCE_DATE_EPOCH` 在 3.12 zipapp 不生效）；导入失败 exit 1 落在封闭退出码集合之外；zip 内相对导入不可用；`-p` 可绕过唯一入口。
- D：T0 无进入/退出判据、无必跑用例、未覆盖 `deploy.pyz` 内模块；T4 根权限未写。
- **共识**：机制方向（zipapp 可加载）成立，但**启动合同未闭合**，需 v38 固定安装路径/权限/启动器/SHA 语义/selfcheck。

### 一致 2：launcher 端点继承仍不可证（B 主发现，A/D 呼应）

- B：v37 机制修复方向正确（supervisor fork launcher 前 close P、child close S），但：fork→close 窗口内 launcher 仍持有 S（CLOEXEC 只对 exec 生效）；main/supervisor 的完整 fd 清单与 child close 补集未定义；`A` 锁表述自相矛盾（§4.3 close(A) vs §4.4 不跨 fork 持有）；sidecar_w 由 main/supervisor/launcher 三方持有，唯一写者只在文字上；`fd 断言`白名单未定义；“exec 前无 socket”应改为“execve 调用时点”，并给观测。
- D：正向对照无法观测“exec 前无 socket”，T3 缺 fd 快照观测。
- **共识**：v35 的 P 泄漏、v36 的 S 泄漏机制已修；但“端点唯一持有/exec 时点无 socket”尚未形成可执行合同。

### 一致 3：L1 gate 与 exec 成功判定未闭合（B 主发现，C/D 交叉）

- B：L1 只写“校验 done/ACK/FIN/EOF/端点/身份/cgroup”，未形式化：ACK/FIN 顺序、challenge 相同且非 0、FIN 后无额外字节、done_sent_ok 是否前置、ACK/FIN 身份语义、主进程 ACK 前校验；**具体误判反例**：execve 失败后 launcher 正常返回 → exit 0 → 被 T-EXEC-SUCCESS 采信（正文未强制 `_exit(非0)`）。
- C：T-NOT-SENT 缺“sidecar 已定型/合并校验通过”与“cgroup 身份锚点”；`eof_ok` 命名易被误当成功。
- D：正向对照不可执行（canary 拿不到 release、`command_sent` 期望与 §5.3 矛盾、`running/match` 无 seam、release 恰一次无观测）。
- **共识**：方向正确，但 gate 判定式、exec 证据优先级、launcher 退出码强制、正向对照可执行性均需 v38 重写。

### 一致 4：Evidence/WAL 与重放矛盾（C 主发现，B/D 交叉）

- C 的 8 项阻断：
  1. `cli_migrate_failure` 要求 `gate=closed`，但 v37 迁移在 gate_authorized 之后 → 证据非法；
  2. `release_failure` 要求 `authorized + release_byte=failed`，与“authorized ⇒ not_written/unknown”互斥；
  3. §5.1“gate_authorized 且 sidecar 无 cli_release_received → 不写 not_sent”与 §5.4 派生 not_sent 冲突，且 item 5 bullet 顺序可能先用未合并 sidecar 派生（错误 not_sent 入口）；
  4. 重放阶梯缺 `resolution` 优先级；
  5. evidence-only（gate=closed/release=not_written/cli_exec=not_executed/reaped=true）无派生规则 → 回到 unknown（v35 F3 回归）；
  6. `spawned` 由 main 在 supervisor 存活后写，破坏单写者与 seq 严格 +1；
  7. 事件枚举漏 `sidecar_merged/abort_requested/recovery`；
  8. sidecar 只合并摘要不内联事实，“唯一权威”名不副实；launcher 存活期间 supervisor 被杀 → 未合并 → 永久 hold。
- B：sidecar_w 三方持有；done 失败收尾未要求先 reap launcher。
- D：完整矩阵未交付（引用不存在的“队友 D 合同 §二”）。
- **共识**：v37 把表落成文字但引入新矛盾；v38 需重写权威关系/派生/事件枚举/重放顺序。

### 一致 5：hold/锁/退出码与实验授权不足（B/D 主发现）

- B：hold 的“最后一个持有者死亡”不可判定；`recover` 需全局锁与 hold 持锁死结；exit 23 返回主体未定义；hold 后禁止 release 未写死；SIGPIPE 处置依赖 CPython 默认、E05 在 Python 探针下不可复现。
- D：E01 只读与 E02–E14 主动授权边界不清（E14 也只读）；E01 可跑目标宿主也可跑 VM；E12 阈值/分位/负载未定义；清理顺序错误；VM 隔离哨兵不足（docker.sock/mountinfo/VM 身份/镜像 hash/网络）；OOB 引用 E05 错位；E 与 T3 判据未映射。
- **共识**：hold/退出码/实验授权需 v38 闭合。

## 五、v38 修订方向（Lead 汇总）

1. **启动链**：固定 `/usr/local/sbin/astrbot-deploy` + `/usr/local/libexec/astrbot-deploy/`（root:root、pyz 0644 无 shebang、dir 0755）；deploy.sh 绝对路径 `python3`/`sha256sum`，lstat 自身+祖先链，失败零改动 exit 10；定义 VERSION 生成/校验/失败码；selfcheck 覆盖模块/`sys.path[0]`/flags/内核特性/docker 路径，失败映射 10；修正 T0 为 T0a 静态 + T0b 实测；删“可复现”或写 mtime 归一。
2. **端点/fd**：四状态完整 fd 清单、fork 前快照、child 按“清单−白名单”关闭、断言写 sidecar `fd_snapshot`；把“exec 前”改“execve 调用时点”；区分 L/M/Seq；sidecar_w 仅 launcher 保留。
3. **gate/exec**：形式化 `gate_ok(...)`（ACK→FIN→EOF、challenge 同且非 0、FIN 后无字节、身份/元数据/cgroup）；launcher 退出码强制（含 catch-all `_exit(127)`、T0 AST 扫描）；T 规则优先级、冲突 hold；正向对照改为可执行断言（释放由 sidecar/退出码证明，canary 只证明 exec）。
4. **Evidence**：修复 migrate/release 字段与 gate 约束；统一 §5.1/§5.4 冲突；重放加 `resolution` 与 evidence-only 派生；`spawned` 由 supervisor 写或加握手；事件枚举补全；sidecar 合并内联事实或锚定哈希链；合并时机改为 launcher 定型即合并。
5. **hold/实验**：定义 hold 解除协议与 abandoned 判定（flock 探针）；exit 23 主体；SIGPIPE 处置；实验 E01 只读与 E02–E14 拆分授权、E14 归只读、OOB 独立项、E12 阈值、清理/隔离哨兵/VM 身份。
6. **测试**：落盘完整矩阵（case/层/前置/操作/观测/预期/失败判据/条款映射）；补变异测试；正向对照含四层事件与 sidecar 顺序。
