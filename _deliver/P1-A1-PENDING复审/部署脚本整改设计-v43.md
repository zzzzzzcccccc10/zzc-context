## 一、写权与 epoch 持久化（K1）

### 1.1 五代写者

| 代 | writer | epoch | 起始标记 | 终止 | 备注 |
|---|---|---|---|---|---|
| W1 | main | 1 | attempt_created | spawn_begin 或 fork1 失败终态 | 持 L/M |
| W2 | supervisor | 2 | spawned | terminal+resolution 或 hold_request | 无 L/M |
| W3 | main/recover | 3 | writer_takeover(prev 1/2→3) | close 前 | 收尸后 |
| W4 | main | 4 | halt（3→4 唯一） | W4 出口 | 只写 halt/abort_requested/operator_resolution |
| W4R | main | 5 | writer_takeover(prev=4→5, halt_released) | attempt_hold 后 close | **仅 T-HALT** |

### 1.2 epoch 持久化规则（K1）

- epoch **只由 WAL 事件推进**：`spawned`→2、`writer_takeover`→3/5、`halt`→4；同一 attempt 内 epoch 单调不减。
- HALT 文件只镜像 `{attempt_id, epoch, halt_seq, holder_pid, holder_pstart, boot_id, reason}`，**不作写权依据**；恢复以 WAL 为准，WAL 不可写时以 HALT 文件标注“未持久化”。
- **W4R 仅当 `halt(4)` 已 fsync 落盘（T-HALT）才允许**；F-HALT/M-HALT（WAL 不可写）下：
  - latch 成功 → **latch-only hold 22**：不写 takeover(5)、不写 attempt_hold；HALT 文件可写时更新 `epoch=4/5?`（仅提示）、保留 latch/token、释放 L/M、exit 22。
  - recover 以 basis=latch 处理；不得要求 attempt_hold 存在。
- 崩溃点：F-HALT 下 halt(4) 未落盘 → 下一事务见 latch/HALT → 23；recover 读 HALT 文件（`wal_persisted=false`）以 latch/token 判 23 或 0，不写 W4R 事件。

### 1.3 单写者不变量

任一时刻至多一个 WAL 写 fd；1→2 由 spawned、3→4 由 halt、W3/W4R 由 takeover 标记；fork→close 窗口残余；supervisor 在 hold_request 后零 WAL 写。

## 二、hold / W4 / W4R / HALT（K1/K2/K3）

### 2.1 四种 HALT 形态

| 形态 | 条件 | WAL 写 | HALT 文件 | 出口 |
|---|---|---|---|---|
| T-HALT | 已 takeover（epoch 3） | 可写 halt(4) | 可写 | W4R 或 abort |
| P-HALT | supervisor 未证死 | **禁写** | 可写 | 死后补 takeover(3)+halt(4)→T-HALT |
| F-HALT | WAL 不可写、HALT 可写 | 否 | 可写 | latch-only 22 或 abort（resolution 写失败→留 HALT） |
| M-HALT | WAL/HALT 均不可写 | 否 | 否（内存态） | 心跳；SIGKILL→23 |

### 2.2 唯一时序

```
[supervisor]
hold_request{reason,last_seq} fsync
→ close(release_w)
→ send HOLD_REQ(type=5) 立即；失败 close(P)
→ 收尸：¬exec_begin → SIGKILL launcher + waitpid(T_REAP=5s)
        有 exec 证据 → waitpid 至 T_CLI_WAIT=125s；仍活 → 记内存 live
→ close(log_fd) → close(P) → _exit(0)
[main]
收 HOLD_REQ / P EOF / pidfd POLLIN
→ 停 ACK/FIN
→ waitpid(supervisor)：无帧 T_SUP_EXIT=5s；有帧 T_SUP_EXIT_FRAMED=126s
→ 超时：close(P) → SIGTERM → 1s → SIGKILL → waitpid(T_REAP=5s)
→ W3 重开（J1/J2）→ writer_takeover fsync
→ 尾判定：hold_request→hold；terminal→不重复；矛盾→30
→ token 32B CSPRNG → hold.token 0600 明文+fsync → stderr 一行
→ latch O_EXCL 0600（取 ino）+fsync 文件/目录
→ attempt_hold{latch_ino,reason,live_children,token_sha256,cli_state} fsync
→ close(log_fd) → close(M) → close(L) → JSON 22 → exit 22
```

### 2.3 收养与 live_children 证据（K2）

- supervisor 死亡后，launcher/CLI 由 main（subreaper）收养；main 用：
  - `waitpid(-1, WNOHANG)` 循环至 ECHILD；
  - `/proc/<pid>` 存在 + `/proc/<pid>/stat` starttime 匹配；
  - `/proc/<pid>/task/<pid>/children` 枚举；
  - `pidfd_open` + `poll(POLLIN)` 判死。
- `live_children[]` 只写 main 自身观测结果（pid+pstart+state）；不可观测 → `[]` + `observed=false` + `cli_state=unknown`；**不得使用 supervisor 内存结果，不得伪造 exit code**。
- 收尸边界：supervisor 存活时 main 不 waitpid launcher；ECHILD 视为 reparent 未完成，100ms 重试至 T_REAP；exec 可能则等 T_CLI_WAIT，仍活 → halt。
- attempt_hold 的 `live_children` 是写时快照；写入后仍继续回收；不因非空判“收束失败”。

### 2.4 W4/W4R

- W4（epoch 4）：只写 halt/abort_requested/operator_resolution；不写业务事件；不释放 L/M；不自行 exit；心跳不含 token。
- 出口①（仅 T-HALT）：latch 成功 → writer_takeover(4→5) → W4R 写 attempt_hold → close log_fd → unlink HALT → close M/L → 22。
- 出口①′（F/M-HALT）：latch 成功 → latch-only hold 22（不写 WAL）。
- 出口②：合法 intent → abort_requested → operator_resolution → 清理（resolution→intent→HALT→token→latch 最后）→ close M/L → 0；F-HALT 下 resolution 写失败 → 留 HALT/23。
- 出口③：SIGKILL → 残留 → 23。

### 2.5 token 崩溃点（K3）

| 崩溃点 | 状态 | 恢复 |
|---|---|---|
| latch 前 | 无 latch | 正常 |
| token 后、latch 前 | orphan token | 保留；recover 凭 token+confirm（内容匹配）→ basis=hold_token→0；无凭据→23 |
| latch 后、attempt_hold 前 | latch（可含 token_sha256） | 有 token/intent→basis=latch→0；无凭据→23 |
| attempt_hold 后 | 完整 hold | 正常 recover/abort |
| resolution 后删 latch 前 | resolution+latch/token | 幂等清理，不重写；23 |
| token 写失败后 latch | token_sha256=null | 双故障：23 人工；不清理 token |
| orphan token 长期 | token 无 latch | 保留至 resolution；不自动清理 |

- **orphan token 授权**：token 文件必须含 attempt_id/holder_pid/holder_pstart/nonce；recover 校验 token sha256 与文件内容、与 HALT/latch 一致；无 confirm → 23；不得自动删 token。

## 三、WAL 重开/追加（继承 J1/J2）

- 锚点：`attempt_created{state_dir,audit_dir,wal{name,dev,ino,mode,size=0}}` + `fsync(audit_fd)`；`spawn_begin.wal_off`。
- 从 `/` 逐级 `open(O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC)` + 每级 fstat（dir/root:root/非组写）；state→audit→WAL 三级 dev-ino；W2 `O_WRONLY|O_APPEND`、W3/W4 `O_RDWR|O_APPEND`、无 O_CREAT/O_TRUNC；fstat regular/nlink1/uid0/0600/size。
- W3 尾修复：尾向 pread 倍增窗口至 256 KiB；只读定位→最后行校验→裁决→可写才 `ftruncate`+fsync→写 takeover（n==len）+fsync+size；每次写前 size==expected、写后==expected+len；关闭前 fstatat 复核。
- 失败：latch 可写→22 latch-only；否则 halt。

## 四、协议与 error pipe（K4）

- 36B 帧；HOLD_REQ type=5 0 fd；SCM_RIGHTS 控制缓冲 + MSG_CMSG_CLOEXEC；发送一帧一次、禁 0 长度、MSG_NOSIGNAL；EOF 判定请求≥1+0+帧边界。
- **FRAME 必须 EOF（K4）**：读到 8B 后继续 poll/read：
  - 8B+EOF → FRAME（`exec_frame{frame,nbytes:8,eof:true}`）→ F=1；
  - 8B 后仍有字节 → OVER（或 BAD）→ hold；
  - 1–7B+EOF → SHORT→hold；≥9B → OVER→hold；magic/errno 非法→BAD→hold；5s 无 EOF→TIMEOUT→hold；read 错误→READ_ERR→hold。
- 仅 launcher 写 8B（短写不重试→72）；仅 W2 读并写 exec_frame+fsync；W3 不重读；迟到帧不改判。
- 时间：`T_HANDSHAKE_TOTAL=20s`；阶段 5s；`T_SUP_EXIT=5s`；`T_SUP_EXIT_FRAMED=126s`；`T_CLI_WAIT=125s`；`T_REAP=5s`；`T_EXEC_FRAME=5s`；`T_ABORT_WAIT=5s`。

### 5.4 NOT-SENT 两条 basis（K5）

- **basis=n1n7**：`¬E` + N1–N7 全过；`not_sent_verified{error_pipe: none|unobserved, basis:n1n7}`。
- **basis=frame_proven**：`E∧F`（FRAME 且 EOF）→ exec 层 FAILED → outcome `not_sent(cli_exec_failed)`；`not_sent_verified{basis:frame_proven, errno}`；**不受 N5 约束**（E 存在）；N1–N4/N6/N7 仍需满足（sidecar 可判、绑定、收尸、授权、无成功证据、证据已持久化）。
- `F` 但无 `E`（矛盾）→ hold；`E` 无 F → UNKNOWN；两者冲突 → hold。

### 5.5 release R0–R5（完整合同）

| 态 | 判据 | 允许结论 | 证据要求 |
|---|---|---|---|
| R0 未授权 | ¬gate_authorized | not_sent(abort_before_gate) | 无 release_byte；sidecar 无接收 |
| R1 已授权未写 | gate∧¬release_byte∧¬release_failure∧无接收 | launcher 自退 70→not_sent(gate_closed)；否则 hold | sidecar 无 cli_release_received |
| R2 写失败 | gate∧evidence(release_failure,authorized,failed)∧¬release_byte | not_sent(cli_release_write_failed) | release_failure 已 fsync |
| R3 已写 | gate∧唯一 release_byte{written} | ¬E 时 not_sent(abort_after_release) | release_byte 唯一；sidecar 接收一致 |
| R4 接收未记录 | gate∧¬release_byte∧sidecar 接收 | **hold(release_commit_window)** | 不得 not_sent |
| R5 不可观测 | gate∧¬release_byte∧¬release_failure∧supervisor 死于窗口∧launcher 非自退 70 | **hold(release_commit_window)** | 不得 not_sent |

- 恰一次：每 attempt 至多一个 release_byte；重复→invalid/HOLD；写失败不写 release_byte。
- release_byte 表示“授权已交付”，不是“launcher 已读”；R4/R5 只能 hold。

## 六、正常启动（无 hold）完整时序

```
main 启动 → selfcheck → 只读扫 latch/未裁决（命中 23）→ 取 L → 取 M → 建/核验状态根
→ W1：attempt_created…spawn_begin（逐行 fsync）→ fork1
→ 子 supervisor 关 P/L/M/log 副本 → 重开 state/audit/WAL → 写 spawned（fsync，先于 fork2）
→ 建 release/error pipe → 写 cli_spawn_begin → fork2
→ 子 launcher 关 S/release_w/error_er/log/M/dirfd → 快照 0 → 读 release → 快照 A 写 exec_begin → execve
→ supervisor gate → cgroup_migrated(closed) → gate_authorized → release_byte
→ 读 error pipe（FRAME 必须 EOF）→ waitpid → 合并 sidecar → terminal+resolution
→ main waitpid → 收尸 → close WAL/M/L → stdout JSON → exit 0/20/21/24/30
```

- 正常成功：exit 0（resolution=exit_0+command_sent=yes+running+match）。
- 失败映射：not_sent 20；unknown 21；command_failed 24；内部 30；锁忙 11；前置 10。

## 七、安装器合同

- 入口：`python3 -I -S -B <source>/lib/deploy.py installer <install|upgrade|verify|rollback>`；root-only；不经过 wrapper（wrapper 拒绝 installer）。
- 动词：install（首装）、upgrade、verify（只读）、installer-rollback（安装树回滚）；包 `deploy-<semver>.tar.gz` + 带外 `--package-sha256`；四文件、逐成员校验、逐文件 fsync/chmod/fsync、compile 门、payload==SHA256SUMS==VERSION 交叉。
- **L 分段**：Phase1 持 L（解包/换名/journal）、Phase2 **放 L**（selfcheck）、Phase3 再持 L（提交/回滚）；driver.lock D 全程持有；Phase2 绝不持 L。

- journal：`op/phase/gen/package_sha256/old/new/swap_mode/stage_path/old_path/retire_path/prev_slot`；写序 pending→prepared→staged→swapped→verified→committed；提交点=install.json 原子替换。
