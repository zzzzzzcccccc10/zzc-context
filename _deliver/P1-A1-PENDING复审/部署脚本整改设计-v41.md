## 〇、相对 v40 的修正（冻结点）

1. **hold 顺序**：supervisor 写 `hold_request` → 关 release_w → 发 HOLD_REQ（type=5）→ 收尸/交给 main → close log_fd → 退出；main waitpid 后 W3 重开 → 写 latch → 写 attempt_hold → 释放 L/M → exit 22。删除“main 先写 attempt_hold 再终止 supervisor”。
2. **WAL 写权**：W1 main（attempt_created…spawn_begin）→ fork1 成功父 close(log_fd)、子重开（audit dirfd + 五元 fstat）→ W2 supervisor（spawned…terminal+resolution）→ W3 main/recover（waitpid/死亡证明后 takeover）。新增 `writer_takeover` 必须先于 W3 业务事件。
3. **非子进程死亡证明**：pidfd poll(POLLIN)/ESRCH/`/proc` 不存在/starttime 不符 → 已退出；存活 → 23；无法确认 → 30；`waitid` ECHILD 不作证明；recover 不 kill 非子进程。
4. **error pipe**：创建/端点/五态（NONE/FRAME/SHORT/OVER/BAD/TIMEOUT/READ_ERR）/`T_EXEC_FRAME=5s`/`exec_frame` 事件/写失败 72/归属矩阵（仅 launcher 写、仅 W2 读）。
5. **exec 判定**：`¬exec_begin` 不得判 exec 失败；FAILED 需 `E∧F`；UNKNOWN 为 `E` 无失败证据；SUCCESS 需 `E∧exit0∧¬F∧无泄漏`；launcher 码解释守卫收窄。
6. **release 六态**：R0–R5；R4/R5 hold；R1 可证未投递可 not_sent；R2/R3 依证据。
7. **安装 D0–D9**：完整表（19 行含子行）+ journal 必含字段 + 首装/升级路径差异 + 恢复再崩溃重入 + E16e 映射。
8. **矩阵**：101 族/104 子例、N1–N7、evidence 12 行、T1-13 四向量、T2-03a/b、T2-20a/b、T4-04a/b、P1–P14、F-SEAL、t3/run v1。

## 三、进程与 FD 生命周期（契约 B）

### 3.1 拓扑与锁

```text
main（持 L、M；subreaper；W1/W3/W4；唯一 JSON 写者）
└─ supervisor（无 L/M；W2 写者；协议对端）
   └─ launcher（无 L/M/socket；读 release、写 sidecar、execve）
      └─ CLI（仅 {0,1,2}；1/2 指向 run/<id>/cli.log 或 /dev/null）
```

- L/M 只 main；CLI 不持锁；main 崩溃即锁释放（残余，由 WAL/latch 判定）。
- `abort/status` 不取 L/M；`recover --repair` 取 L→M；23 判定先于取 L。
- M 路径 `run/<attempt_id>/attempt.lock` 0600；释放于 log_fd 关闭后、L 之前。

### 3.2 FD 矩阵与 CLOEXEC

| FD | execve 前 launcher | CLOEXEC | exec 后 CLI |
|---|---|---|---|
| 0/1/2 | 打开（1/2 重定向） | **false** | 保留 |
| sidecar_w | 打开 | **true** | 关闭 |
| error_ew | 打开 | **true** | 关闭（0B EOF 依赖） |
| L/M/P/S/log/dirfd/pipe/pidfd | 不存在或关闭 | true | 关闭/不存在 |
| 其他非白名单 | 关闭 | true | 关闭 |

- launcher 步骤：关闭批次（S/release_w/error_er/log/M/dirfd）→ 快照 0 `{0,1,2,release_r,sidecar_w,error_ew}`（71）→ 读 release → 写 cli_release_received → close(release_r) → 快照 A `{0,1,2,sidecar_w,error_ew}`（74）→ 写 exec_begin（无缓冲+fsync）→ execve。
- 快照 A/B 用 `/proc/self/fd` 枚举 + fstat + F_GETFD；快照 B `{0,1,2}`（1/2 身份一致）；泄漏 → `fd_leak_post_exec` + unknown/hold，永不 not_sent。
- error pipe：supervisor `pipe2(O_CLOEXEC)`；子关 error_er 留 error_ew；父关 error_ew 留 error_er；仅 launcher 写 8B `EXC1+u32 errno`；读五态（NONE/FRAME/SHORT/OVER/BAD/TIMEOUT/READ_ERR）；`T_EXEC_FRAME=5s` 独立；读后写 `exec_frame` + fsync。

### 3.3 两次 fork 与 WAL 写权

- fork1：`spawn_begin` fsync → fork；子首条 close(P/L/M/log 副本)、关 audit dirfd 后重开；父成功 close(S)+close(log_fd)（移交）+close(sidecar_w)，失败保留 log_fd 写 spawn_failure。
- fork1 后 supervisor 重开 audit dirfd + openat WAL（O_APPEND，无 O_CREAT）+ 五元 fstat（regular/nlink1/uid/0600/dev-ino/size）→ 写 `spawned` seq=spawn_begin+1 fsync。
- fork2：`spawned` fsync 先于 fork2；supervisor 写 `cli_spawn_begin` fsync → fork；子关 S/release_w/error_er/log/M/dirfd；父关 release_r/error_ew/sidecar_w 副本。
- fork2 失败：supervisor 写 cli_spawn_failure/not_sent/resolution；main 只 finalize。
- W2：supervisor 写至 terminal+resolution；W3：main waitpid/死亡证明后重开（O_RDWR + 尾部半行截断）→ `writer_takeover` fsync → 补/清理。
- 不变量：至多一个写者；fork→close 窗口残余；WAL 裸 os.write + fsync。

### 3.4 hold 与 operator

- hold（G1）：supervisor 判定需 hold → 写 `hold_request` fsync → 关 release_w → 发 HOLD_REQ → 收尸（¬exec 可 SIGKILL；exec 等 T_CLI_WAIT 后交 main）→ close log_fd → close P → 退出；main waitpid → W3 重开 → `writer_takeover` → latch（O_EXCL 0600，取 ino，fsync 文件+目录）→ `attempt_hold{latch_ino,reason,live_children,token_sha256,cli_state}` fsync → close log_fd → close M → close L → stdout JSON（22）→ exit 22。
- 收尸边界：supervisor 存活时 main 不 waitpid launcher；supervisor 死后 launcher 由 subreaper 收养，ECHILD 重试至 T_REAP；exec 可能则等 T_CLI_WAIT，仍活转 halt。
- halt（A6）：latch 连续 3 次写失败 / supervisor 不可杀 / 收养 CLI 长活 / abort 意图但 resolution 写失败 → 持 L+M、HALT 文件、stderr 心跳、每 1s 读 abort.intent；禁止释放 L/写 not_sent。
- token：32 字节 CSPRNG（64hex）；`hold.token` 0600 明文一次性 + stderr 一行；WAL 只存 sha256；abort 校验；不重生成。
- abort：只读预检 → token 格式 → `abort.intent` O_EXCL 0600 → SIGUSR1 → main 校验（halt/未退出窗口）→ operator_resolution fsync → 删 latch/HALT/intent → close M/L → 0；abort 不取 L/M。
- recover：只读预检 → L（忙 11）→ 死亡证明（存活 23 / 无法确认 30）→ M → 校验 token → W3 重开 → takeover → operator_resolution（幂等）→ 清理 → 0；二次只清理。
- 防双裁决：latch/HALT/intent O_EXCL；operator_resolution 唯一；已存在同 token 只清 latch；不同 token 23；先 resolution fsync 再删 latch。

## 四、通信协议

- 36B 帧（length+header 大端）；pidfd 1 fd、done/ack/fin 0 fd；HOLD_REQ type=5（0 fd、reason_code/last_seq/challenge、supervisor→main）。
- SCM_RIGHTS：控制缓冲 + MSG_CMSG_CLOEXEC；fd 按帧累计；CTRUNC 关闭；单帧最多 4。
- 发送：一帧一次 sendmsg 36B；禁 0 长度；MSG_NOSIGNAL；0<n<36 不重试。
- EOF：请求≥1 + 返回 0 + 帧边界；半帧 0=截断；POLLRDHUP 不直接判 EOF。
- OOB：不设 SO_OOBINLINE 为启动条件；禁 MSG_OOB/SIOCATMARK。
- 时间预算：`T_HANDSHAKE_TOTAL=20s` 共享绝对 deadline；阶段 5s 仅上限；`T_REAP`/`T_CLI_WAIT`/`T_EXEC_FRAME=5s` 独立；watchdog 触发=FAIL。

## 五、WAL 与状态重放

### 5.1 事件与写权

- 封套 `v,event,attempt_id,seq,epoch,writer,pid,pstart,boot_id,mono,time,d`；seq 严格 +1；裸 os.write + fsync。
- 新增事件：`hold_request`（非 hold 证据）、`exec_frame`（W2）、`writer_takeover`（W3 首条）、`halt`、`operator_resolution`、`abort_requested`。
- W1 main → W2 supervisor → W3 main/recover；任一时刻一个写者。

### 5.2 唯一顺序与迁移

```
attempt_created → precheck* → start_invoked → start_call_begin → cgroup_created → spawn_begin
→ spawned → cli_spawn_begin → (cli_spawned|cli_spawn_failure)
→ metadata_published → pidfd_sent → done_sent → ack_ok → fin_ok → eof_observed
→ cgroup_migrated(gate=closed) → gate_authorized → release_byte
→ exec_observed? → cli_reaped → sidecar_merged → terminal → resolution
```

- 相邻性：migrate→gate→release；terminal→resolution（operator_resolution 为合一终态）；ack/fin/eof 顺序。
- 迁移失败：不写 gate/release；evidence(cli_migrate_failure, gate=closed) → not_sent；回收不能证 → hold。
- gate 载荷：challenge_sha/seq/cli pid+pstart/pidfd/cgroup/判据/时间；重放可复算；缺失 hold、矛盾 invalid。

### 5.3 release 六态

| 态 | 判据 | 允许结论 |
|---|---|---|
| R0 | ¬gate | not_sent(abort_before_gate) |
| R1 | gate∧¬release_byte∧¬release_failure∧无接收 | 自退 70→not_sent(gate_closed)；否则 hold |
| R2 | release_failure(authorized,failed) | not_sent(release_write_failed) |
| R3 | release_byte{written} 唯一 | ¬E 时 not_sent(abort_after_release) |
| R4 | gate∧¬release_byte∧sidecar 接收 | hold(release_commit_window) |
| R5 | 不可观测 | hold(release_commit_window) |

### 5.4 exec 判定

- 矛盾/HOLD 优先；FAILED(`E∧F`) > SUCCESS(`E∧exit0∧¬F∧无泄漏`) > NOT-SENT(`¬E`+N1–N7) > UNKNOWN(`E` 无证据)。
- `¬E` 不得判 exec 失败；`¬E+72/79/127` → HOLD；`E+70/71/72/74/127` 无 terminal → UNKNOWN；79 → HOLD/UNKNOWN。
- 8B 帧 magic/errno（1..4095）校验；1–7B/>8B/magic 错 → hold；0B ≠ 成功。
- not_sent 必须在 `not_sent_verified` 内联 N1–N6 快照；W3 未读 error pipe 时内联 `unobserved`。

### 5.5 NOT-SENT N1–N7

N1 sidecar 状态可判（SC0/1/2，或 SC3-aborted）；N2 绑定一致；N3 收尸+cgroup 空+无未识别子进程；N4 授权态确定；N5 无 exec_begin（P1 构建已验证）；N6 无成功/失败证据（0B 或 unobserved）；N7 not_sent_verified 已持久化。七项全过才 not_sent。

### 5.6 evidence 12 行

early_pre_cli、early_post_cli、ack_failure、cli_migrate_failure、abort_before_gate、abort_after_gate、abort_after_release、release_failure、execve_failure、exec_unconfirmed、not_sent_verified_*、evidence_write_failed；每行唯一元组；因果 evidence + 终结 not_sent_verified 可并存。

### 5.7 sidecar 与重放

- sidecar：JSONL created + facts；SC0–SC6；supervisor 创建、launcher 首个写 created；合并后仅 WAL 可独立重放。
- 合并：收尸后唯一写者；`sidecar_merged` 内联 sha/绑定/facts/terminal/error_pipe；单条；上限 1MiB；二次 invalid。
- 重放阶梯：operator_resolution > resolution > start_result > start_not_sent > attempt_hold（非终态）> DR1–DR12 > hold > invalid > unknown；采用前唯一性/authority_seq/顺序/写者/not_sent 复核/unknown 成对。
- 矛盾组合 hold；尾部半行截断；跨事务门禁（hold_request 未裁决 → 23）。
