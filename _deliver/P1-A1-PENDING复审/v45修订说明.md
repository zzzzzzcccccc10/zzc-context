## 一、hold 状态机（唯一逐条件互斥表）

### 1.1 决策顺序（先活体，后写权；不可交换）

```
S0 判定：live≠[] ? 或 observed≠true ? 或 attempt_hold 可持久化?
1) 若 live≠[] 或 observed≠true（有活体/无法排除活体）：
   a. WAL 可写 且 halt(4) 可写 → P2 T-HALT（22）
   b. 否则 → hold-live（持 L/M、心跳、SIGKILL→23）
   P3/P4a 禁止（不得因 HALT/latch 可写而释放 L/M）
2) 若无活体且 observed=true：
   a. WAL 可写 → P1（attempt_hold epoch3，22）
   b. WAL 不可写 且 HALT 可写 → P3 F-HALT（latch-only 22）
   c. WAL/HALT 不可写 且 latch 可写 → P4a M-HALT-latch（latch-only 22）
   d. latch 不可写 → P4b hold-live（心跳、SIGKILL→23）
```

- **铁律**：有活体/不可观测时，只能 P2 或 hold-live；P3/P4a 仅在“无活体且 observed=true”时允许。
- hold-live 定义：持 L/M、不释放、心跳、SIGKILL→23；不写 WAL、不写 attempt_hold、不写 HALT（可 best-effort 写 HALT 仅当 WAL/HALT 可写且无活体？不——有活体时 HALT 可写也归 P2；hold-live 仅当 P2 不可行，此时 HALT 可写性不改变路径，HALT 可选写提示但不释放 L）。

### 1.2 路径表（唯一结果）

| 路径 | 条件（互斥） | WAL 事件 | 文件 | L/M | 退出 | recover basis |
|---|---|---|---|---|---|---|
| P1 | 无活体+observed=true+WAL 可写 | takeover(3)→token→latch→attempt_hold(epoch3) | token+latch；无 HALT | 持→释放 | 22 | attempt_hold |
| P2 | 有活体/observed≠true+WAL 可写+halt(4) 可写 | takeover(3)→halt(4)→W4→takeover(4→5)→W4R attempt_hold(epoch5) | HALT+token+latch | 持→释放 | 22 | attempt_hold（若 W4R 失败→latch，见 1.3） |
| P3 | 无活体+observed=true+WAL 不可写+HALT 可写 | 无 | HALT(wal_persisted=false)+token+latch | 持→释放 | 22 | latch |
| P4a | 无活体+observed=true+WAL/HALT 不可写+latch 可写 | 无 | token+latch | 持→释放 | 22 | latch |
| P4b / hold-live | 有活体/observed≠true 且 P2 不可行；或无活体+latch 不可写 | 无 | 现场（HALT 可写则写提示） | 持（不释放） | 心跳；SIGKILL→23 | 23 人工 |
| T2-02b | WAL+latch 持续 EIO、HALT 正常、无活体 | 无 | HALT(wal_persisted=false)+token，无 latch | 持（不释放） | 心跳；SIGKILL→N/A | 23 人工 |

- T2-02b 归属：**P4b hold-live**（无活体但 latch 不可写；HALT 仅提示）。
- 有活体时即使 latch 可写也**不得** P4a（必须 hold-live），因为活体未收束。

### 1.3 W4R 失败子状态（P0-2）

| 子状态 | 持久化现场 | HALT 四字段 | latch/token | 首次退出 | recover basis | 允许补写 |
|---|---|---|---|---|---|---|
| W4R-S1 | takeover(4→5) 未落盘；WAL 末 epoch=4；无 attempt_hold | (wal_epoch=4, request=4, persisted=true, halt_seq) | 保留 | 22 latch-only | **latch** | 不补 takeover5/attempt_hold；resolution 载入 HALT resolved=true |
| W4R-S2 | takeover(4→5) 已落盘；WAL 末 epoch=5；无 attempt_hold | (wal_epoch=5, request=5, persisted=true, halt_seq) | 保留 | 22 latch-only | **latch** | 不补 attempt_hold；resolution 可 WAL(epoch5) 或 HALT |
| W4R-S3 | takeover(4→5) 半行/未确认 | WAL 尾半行；HALT 保持 (4,4,true) | 保留 | 22 latch-only | latch | 不截断、不补写；下次修复 |

- P2 恢复合同改为：**attempt_hold 存在→basis=attempt_hold；不存在（W4R 失败）→basis=latch**；不得声称 P2 必 attempt_hold。
- 不重复 takeover：S1 不写 takeover5；S2 不重写；S3 不补 half-line。

### 1.4 T_REAP 修正（P0-3）

- 核心裁定 §1.3 改为：`T_REAP=5s，仍活且 WAL 可写→T-HALT（22，记录 live_children/observed）；WAL/HALT 均不可写→hold-live（心跳/SIGKILL→23）`；删除“仍活→M-HALT/23”。
- 与接口冻结/完整设计一致：M-HALT 仅 WAL/HALT 均不可写；T-HALT 用于 WAL 可写。

## 二、身份与授权（P1-1/P1-2）

### 2.1 PID 权威来源与发布协议

| 对象 | 发布者 | 事件/位置 | 字段 | main 如何取得 |
|---|---|---|---|---|
| supervisor | main | 内存/`spawned`？W1 不写 | pid/pstart | fork1 返回值（父进程直接得 pid）；starttime 由 `/proc` 读 |
| launcher/CLI | supervisor | `cli_spawn_begin`（launcher pid 未定？）→`cli_spawned{pid,pstart}`（WAL，fork2 后） | pid/pstart/boot_id | W3 重开后读 WAL `cli_spawned`；不得用 supervisor 内存 |
| CLI（收养后） | main | 自身观测 | pid/pstart | WAL `cli_spawned` + pidfd_open + `/proc stat` 验证；已回收用 waitpid/ECHILD |

- main 独立验证：pidfd_open(pid)→`/proc/self/fdinfo/<fd>` Pid/NSpid→`/proc/<pid>/stat` starttime→poll→waitpid。
- pidfd 事件：POLLIN=有事件（zombie 可读）；**POLLHUP=已回收/挂断**；POLLERR/POLLNVAL=错误；三态齐备。
- 禁止 `SA_NOCLDWAIT`；SIGCHLD 保持 SIG_DFL；main 单线程；无 handler 抢先回收；如需唤醒用 pidfd/短睡。
- launcher pid 若 `cli_spawned` 未写（fork2 后崩溃）→ main 无法独立得 pid；observed 至多 partial，不得 P1/not_sent；按 T-HALT/hold-live。

### 2.2 orphan token 唯一 schema（三文档一致）

- token 文件（`run/<id>/hold.token`，0600）：
  `{v:1, attempt_id, token_hex(64lower), token_sha256, holder_pid, holder_pstart, boot_id, nonce, created}`
- abort.intent（0600）：
  `{v:1, attempt_id, token_sha256, nonce, holder_pid, holder_pstart, boot_id, requested_at}`
- operator_resolution：
  `{v:1, attempt_id, basis∈{attempt_hold,latch,hold_token}, authority_seq, token_sha256, resolved_at}`
- `authority_seq` = 最近已持久化 WAL 事件的 seq；若 WAL 不可读/无 → 0 + `anchor=none`；**不使用 `token_seq?`**。
- 幂等：同 token→只清理、不重写、0；异 token/损坏→23 零改动；resolution 存在不重写；清理顺序 resolution→intent→HALT→token→latch（latch 最后）。
- 三文档（核心裁定/接口冻结/完整设计）逐字段一致；完整设计 §10 重新整合。

### 2.3 T_SUP_EXIT_FRAMED 起点（P1-3）

- 合法 HOLD_REQ 帧**完整结束（含 EOF）**→`T_SUP_EXIT_FRAMED=126s`（含 125s CLI 等待+1s）。
- P EOF 且无完整合法帧→`T_SUP_EXIT=5s`。
- 两者互斥；核心裁定 §9 文字统一为“收齐合法 HOLD_REQ 帧（含 EOF）”。

### 2.4 T2-02a 注入语义（P1-4）

- 测试注入层：W2 `hold_request` 行 write 完整后，第一次 `fsync` 调用被拦截返回 EIO（不执行真实 fsync）；同一写者第二次 `fsync` 调用真实执行并成功；行不重写、seq 不跳、不 truncate。
- 明确：这是“瞬时 EIO 注入”，不等价真实文件系统写回错误恢复能力；报告须标注 `inject=stub`；真实 EIO 语义由 E10 记录。
- 第二次成功后复核 WAL：行内容/size/seq/hold_request=1；后续 takeover(2→3)/attempt_hold 成功；exit 22。
- 若第二次仍 EIO→02a FAIL（不得改判 02b）；02b 独立 fixture。
