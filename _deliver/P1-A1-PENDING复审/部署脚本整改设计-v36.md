## 一、威胁模型与边界（沿用 v35）

- 保护目标：防项目内部脚本/普通本地用户绕过顶层事务；不防御 root、Docker socket、等效权限主体。

## 二、实现载体（合同 1）

### 2.1 载体与依赖

- **语言**：Python ≥3.9，仅标准库（`socket`、`fcntl`、`os`、`ctypes` 白名单、`time.monotonic`）；无第三方包。
- **启动**：`deploy.sh` 仅一段注释+守卫+一条 `exec /usr/bin/python3 -I -S -B /opt/astrbot/deploy/lib/deploy_main.py "$@"`；≤30 行；禁止 `docker/sudo/flock/python -c/eval/$(...)`。

- **为什么不是 Bash**：`pipe2(O_CLOEXEC)`、`pidfd_open/send_signal`、`prctl(PR_SET_CHILD_SUBREAPER)`、`SCM_RIGHTS/recvmsg cmsg`、`CLOCK_MONOTONIC`、fd 级 `fsync`、`openat` dirfd 链、同进程 `flock` 均无可靠 shell 接口；任一缺失即无法实现本合同。

### 2.2 唯一入口与退出码

- 人类/自动化只调 `deploy.sh`；`lib/` 不可执行、无 sudoers 条目；helper 不调 sudo/shell。
- 子命令封闭：`deploy|restart|rollback|status|abort|selfcheck`；`attempt_id` `^[a-f0-9]{32}$`；无 `--force/--dry-run`。
- 退出码：`0` 成功；`2` 用法错；`10` 前置不满足（零改动）；`11` 锁占用；`20` fail-closed（evidence+not_sent+resolution）；`21` 结果未知；`22` 审计不可信；`23` 人工挂起（活体持锁）；`24` 命令已发送但非成功；`30` 内部不变量违反（按 21 处理）。非 0 一律禁止自动重试。
- stdout 恰一行 JSON `{attempt_id, exit, outcome}`；stderr 人类摘要；日志正文只进 JSONL。

## 三、通信协议合同（合同 2）

### 3.1 帧格式（统一大端）

总帧 = `4B length` + `32B header` + payload；`length` 不含自身，v1 恒 32，总 36B，payload 0。

| 偏移 | 长度 | 字段 | 编码 | v1 值 |
|---|---|---|---|---|
| 0 | 4 | length | u32 BE | 32 |
| 4 | 4 | magic | u32 BE | `0x50494446` |
| 8 | 2 | version | u16 BE | 1 |
| 10 | 2 | type | u16 BE | 1 pidfd / 2 done / 3 ack / 4 fin |
| 12 | 2 | flags | u16 BE | 0 |
| 14 | 2 | reserved | u16 BE | 0 |
| 16 | 4 | cli_pid | u32 BE | ≠0 |
| 20 | 8 | starttime | u64 BE | ≠0 |
| 28 | 8 | challenge | u64 BE | pidfd=0；done/ack/fin=非 0 X |

- `length<32`、`>4096`、`≠32`（v1）→ `P_E_FRAME`；禁止按不可信 length 分配；缓冲固定 36B。
- 提供 4 条金向量与拒绝向量，启动时离线自检；失败零改动退出。
- `challenge`：CSPRNG 8B、非零（0 重新生成）；只在 done/ack/fin；pidfd 帧必须 0；日志只记 SHA-256 前 8B 指纹。

### 3.2 SCM_RIGHTS 合同

- 内核语义：fd 附属于 `sendmsg` 数据流**首字节**，允许随部分读交付；不存在“length 前缀不携带 fd”的保证。
- 接收：**每次** `recvmsg` 都带控制缓冲（≥`CMSG_SPACE(4*int)`）+ `MSG_CMSG_CLOEXEC`；fd 按**当前帧**累计（含前缀读取）；单帧最多 4，超出即关闭全部。
- 校验：pidfd 帧恰好 1 fd；done/ack/fin 恰好 0；不符 → 关闭全部 → `P_E_FD_COUNT`。
- `MSG_CTRUNC/MSG_TRUNC` → 关闭本帧已收 fd → `P_E_CTRUNC`，不继续解析。
- 只接受 `SOL_SOCKET/SCM_RIGHTS`；畸形 cmsg → 关闭全部 → `P_E_CMSG`。
- 发送：pidfd 帧单次 `sendmsg`，返回必须 36；仅 `-1/EINTR` 可重试（未传输）；`0<n<36` 永不重试。
- 错误路径 fd 必须关闭；所有权转移后由持有者负责。

### 3.3 发送/接收算法

- 接收两阶段：读满 4B length → 校验 32 → 读满 32B body；每阶段 fd 可能到达；请求量 ≤ 当前帧剩余，绝不跨帧。
- `EINTR` 重试；`EAGAIN` 回 poll；`ECONNRESET/ENOTCONN` = `P_E_PEER`（不是 EOF）；0 长度请求禁止。
- EOF 仅在“请求≥1 + 返回 0 + 帧边界（frame_bytes==0）”成立；返回 0 但帧内有字节 = `P_E_TRUNC`。
- `poll(POLLIN|POLLRDHUP)` 只作等待；`POLLRDHUP/POLLHUP` 不直接判 EOF，必须再看 `recvmsg` 返回值。
- 发送非 fd 帧：循环写满 36；`MSG_NOSIGNAL`；EPIPE/ECONNRESET → `P_E_PEER`；fd 帧写失败不重试。

### 3.4 OOB 与超时

- 创建 socket 后对两端 `SO_OOBINLINE=1`；失败 = 创建阶段 fail-closed；禁止 `MSG_OOB`、`SIOCATMARK`。
- `CONFIG_AF_UNIX_OOB` 无关：不发送 OOB；内联字节会被帧校验拒绝。
- 超时常量（构建常量，不进 deploy.env）：`T_PIDFD/T_DONE/T_ACK/T_FIN/T_SUP_EOF/T_MAIN_EOF=5s`、`T_TOTAL=20s`、`T_REAP=5s`、`T_CLI_WAIT=120s`；`CLOCK_MONOTONIC` 绝对 deadline；待实验校准。
- 错误码：`P_OK/P_EOF/P_E_TIMEOUT/P_E_PEER/P_E_TRUNC/P_E_CTRUNC/P_E_FRAME/P_E_SEQUENCE/P_E_FD_COUNT/P_E_CMSG/P_E_CHALLENGE/P_E_IDENTITY/P_E_SEND/P_E_IO/P_E_INTERNAL`；协议层不写 evidence/不授权放行。

## 四、执行确认与进程安全（合同 3/4）

### 4.1 四层放行

| 层 | 执行者 | 动作 | 成功证据（durable） | 失败处理 |
|---|---|---|---|---|
| L1 gate_authorized | supervisor | 校验 done/ACK/FIN/EOF/端点/身份/cgroup | `gate_authorized` + challenge 指纹，fsync | 不放行；终止/回收；evidence；仅 T-NOT-SENT 才 not_sent，否则 hold |
| L2 release byte | supervisor | 写 1 字节 `0x52`（唯一一次） | `release_byte{written}` fsync | EPIPE/错误 → `release_byte{failed}`；回收后按 T-NOT-SENT |
| L3 CLI 收到 | launcher | 读 1 字节且值对；写 sidecar | sidecar `cli_release_received` fsync | EOF → `_exit(70)`；值错 → `_exit(71)`；fsync 失败 → 不 exec `_exit(72)` |
| L4 execve | launcher→supervisor | execve；失败写 errno 帧+sidecar | 成功：CLOEXEC 关写端（≠成功证明）；失败：errno 帧+`cli_exec_failed` | 失败确定 → not_sent；成功需 T-EXEC；其余 unknown |

- 顺序强制：`gate_authorized` fsync 后才写 release 字节；`release_byte` 后才等 exec；`start_result` fsync 后才 resolution；resolution 后才释放锁。
- cgroup 迁移在 L1 后、L2 前；迁移失败终止/回收 → evidence(migrate) → not_sent。
- 放行只允许单一函数 `authorize_and_release()`；其余路径不得写 release 字节。

### 4.2 execve 观测（EOF 不等于成功）

- **T-NOT-SENT**：launcher 身份已证（pid+starttime 与元数据一致）且已回收（exit/signal 记录）∧ sidecar 无 `cli_exec_begin` ∧ cgroup C 空 ∧ 无未识别子进程 ⇒ execve 从未调用 ⇒ 允许 `not_sent`。
- **T-EXEC-FAILED**：sidecar 有 `cli_exec_failed` 或 error pipe 收到完整 8B errno 帧（magic `EXC1` + u32） ⇒ `not_sent(cli_exec_failed)`。
- **T-EXEC-SUCCESS**：ptrace `PTRACE_EVENT_EXEC`（强模式）；或 CLI exit status==0（launcher 自身退出码恒非 0：70/71/72/127）；或 EOF 后即时 `/proc/<pid>/exe` 为非 launcher 且 starttime 未变（需实验）。
- **T-EXEC-UNKNOWN**：sidecar 有 `exec_begin` 且无失败/成功证据 ⇒ `result_unknown`，**永不 not_sent**。
- 禁止推断：EOF⇒成功；127⇒exec 失败；reaped=true⇒未执行；exit_nonzero⇒command_sent=yes（改 unknown）；无 not_sent 证据⇒当 sent。
- **sidecar**：launcher 唯一写者（fsync JSONL：`cli_started/cli_release_received/cli_exec_begin/cli_exec_failed/cli_*_abort`）；主进程创建，fstat 核验，fork 传递；supervisor/主进程只 `pread`，launcher 终止后才定型。
- error pipe：写端仅 launcher；supervisor fork 后立即关自己副本（否则 EOF 不可达）；只接受 0 字节 EOF 或完整 8B；1–7B/>8B = 协议错误 → hold。

### 4.3 端点与 fork 顺序（活性要求）

严格顺序：

```text
主进程：acquire L → acquire A → 建/核验日志/sidecar/unresolved → 写 attempt_created/precheck/start_invoked/start_call_begin（每行 fsync）
 → 建 cgroup C → socketpair(P,S) → 写 spawn_begin（fsync）→ fork supervisor
   子 supervisor 第一条指令 close(P)；父第一条指令 close(S)、记录 pid/starttime、写 spawned
 → 主进程读 pidfd/done，ACK/FIN/shutdown(SHUT_WR)

supervisor：close(P) → 建 release/error pipe → 写 cli_spawn_begin（fsync）→ fork launcher
   子 launcher 前 4 条：close(release_w/error_er/A/log_fd)，保留 release_r/error_ew/sidecar_w/L
   父立即 close(release_r)/close(error_ew)
 → pidfd_open + 元数据发布（root 0600）→ 发 pidfd 帧 → 发 done 帧
 → 等 ACK/FIN/EOF → L1 → 迁移 → release byte → 观测 exec → wait → 终态 → fsync → 退出

launcher：fd 断言 → 读 release → close(release_r) → fd 断言 → 写 exec_begin(fsync) → execve
```

- 全部 `CLOEXEC=true`，唯一例外 L（故意保留进 CLI/后代，v35 残余）。
- 断言用 `/proc/self/fd` + `fstat` dev/ino，不只看编号；失败即 fail-closed。
- CLI 稳态 fd = {0,1,2, L}；不持有任何 socket/日志 fd。

### 4.4 锁、写权、单一终态写者

- L 全局锁：主进程 acquire，fork 共享 OFD；正常收尾 resolution fsync → 删 unresolved → 关日志 → 释放 A → 最后 close(L)。
- A attempt 锁：互斥量，每次“读尾+分配 seq+写+fsync”独立 fd `flock(EX)`；不跨长操作；fork 前不持有、fork 后不继承。
- 写权相位：spawn 前主进程；supervisor 存活期间仅 supervisor；supervisor 确认回收后主进程（恢复写者）。
- 终态写者：同一 attempt 同一时刻仅一个；主进程在 supervisor 存活时不得写 terminal；不单方面杀 supervisor。
- **hold 必须活体**：写 `attempt_hold` 的进程保持存活 + L fd 打开，忽略 SIGHUP/SIGINT/SIGTERM；最后一个持有者死亡 → abandoned（不是 hold），下一事务按重放定级并拒绝自动操作。
- done 发送失败：supervisor 收尾（evidence early + not_sent(cli_done_send_failed)），主进程只写 resolution；主进程未收 done 时关 P 撤回授权，supervisor 按 ack 失败收尾；禁止双终态。
- 主进程 ACK 失败/崩溃：supervisor 见 EOF 无 ACK → 不放行 → 收尾；EOF 不被当 ACK。

## 五、Evidence 与恢复（合同 5）

### 5.1 事实分层与事件

- 唯一持久事实源：`start-attempt-<id>.jsonl`（单写者序列）；manual latch 只表达“禁止继续”。
- 事件层：意图（attempt_created/precheck/start_invoked/start_call_begin）、闸门（gate_authorized/release_written）、证据（evidence）、终态（resolution）。
- 新增事件：`phase`（spawn_begin/spawned/cli_spawn_begin/cli_spawned/metadata_published/pidfd_sent/done_sent/ack_ok/fin_ok/eof_ok）、`gate_authorized`、`release_byte`、`exec_observed`、`attempt_hold`、`attempt_aborted`、`operator_resolution`、`writer_takeover`、`halt`。
- 封套必填：`v/event/attempt_id/seq/writer/pid/pstart/boot_id/time/mono`；`additionalProperties=false`；seq 严格 +1。

### 5.2 fsync 与顺序屏障

- 每事件单次 `write`（完整行+`\n`）+ `fsync`；短写/fsync 失败 → 该事件未持久化 → 后续依赖事件不写；evidence fsync 成功后才允许 not_sent。
- 顺序：evidence → not_sent；gate_authorized → release；release_written → exec 观测；start_result → resolution；resolution → 释放锁。
- 目录项创建/正式化后 `fsync(dirfd)`；`attempt_created` 是正式化后第一行。
- 同一文件 fsync 覆盖此前追加：not_sent 的 fsync 成功 ⇒ 更早 evidence 同时持久。

### 5.3 gate 三态与字段组合

- `gate ∈ closed/authorized/released`（事件发生时历史状态）：closed=未授权；authorized=已授权、字节结果未记；released=release_written 已确认。
- 约束：`released ⇔ release_byte=written`；`authorized ⇒ release_byte∈{not_written,unknown}`；`closed ⇒ not_written ∧ cli_exec=not_executed`。
- `cli_exec ∈ not_executed/failed/unknown/success` + `exec_method ∈ errno_frame/ptrace_exec/proc_exe/exit_code_zero/none`。
- `reaped` 三值闭合：true⇔method≠none∧result=success；false⇔result=unknown（且不能作 not_sent 依据，必须 hold）；not_applicable⇔method=none∧result=not_applicable∧cli_pid=none（仅早期无 CLI）。
- evidence 分表（8 类）：early_stage_failure / ack_failure / cli_migrate_failure / release_failure / cli_abort_before_exec / execve_failure / exec_unconfirmed / evidence_write_failed；每类 gate/release/cli_exec/reaped/允许 reason 固定（详见合同表 7）。
- reason↔kind 闭合：每个 reason 唯一 kind；`call_declined/operator_cancel/precondition_changed` 只允许 `attempt_aborted`，不得出现在 start_not_sent（除 post-call_begin 的 operator_abort 路径）。
- `command_sent`：exit_0→yes；exit_nonzero→unknown；not_sent/aborted→no；unknown/unrecorded→unknown。

### 5.4 重放阶梯（唯一优先级）

1. `operator_resolution` → 采用；
2. `start_result` → 采用；
3. `start_not_sent` → 采用；
4. `attempt_hold` → 非终态，报告人工、禁止自动；
5. 可证派生：¬spawn_begin ⇒ not_sent(crash_before_spawn)；¬gate_authorized ∧ launcher 已证终止 ⇒ not_sent(对应 reason)；exec_failed ⇒ not_sent(cli_exec_failed)；
6. 有活体/无法证明终止 ⇒ hold；
7. 证据链非法/矛盾 ⇒ 只读取证、不自动、不启动；
8. 其余 ⇒ result_unknown。

- 矛盾组合必须 hold：start_result+start_not_sent 并存、resolution 非最后、closed+release_written、released 无 release_written、not_sent 无 evidence、seq 跳号、writer 身份冲突、boot_id 变化。
- 尾部残缺：合法尾部只补 `\n`+fsync（终止事件）；非终止补 `\n`+recovery（最多一次）；中间行非法 → 只读取证。
- 跨事务门禁：有未裁决 hold/unknown/unrecorded → 拒绝自动 start/restart，只出只读报告。

### 5.5 人工中止与 latch

- `call_declined/precondition_changed/operator_cancel(pre-invoked)` → `attempt_aborted` + resolution(aborted)。
- `operator_cancel(post-call_begin, pre-gate)` → `abort_requested` + evidence(operator_abort) + not_sent(operator_cancel)。
- `operator_cancel(post-gate)` → 拒绝（honored=no），继续到可证结论或 unknown；不得倒回 not_sent。
- HOLD：latch 文件 `manual-latch-<id>.json`（O_EXCL 0600 + fsync）+ `halt(reason)`；新事务见 latch 拒绝；清除只经 `recover --attempt`（先全局锁 → 重放 → 写 resolution → 删 latch）。
- latch 写不进（磁盘满/权限坏）→ hold_and_halt：不退出、不释放 L、stderr 持续报告；SIGKILL 后无 latch 保护，属残余。

## 七、测试标准（合同 6）

### 7.1 分层与 seam

- T0 静态（`deploy.sh` 行数/token、AST import 白名单、无测试开关、文件模式）；T1 纯函数（codec/状态机/审计重放，无 I/O）；T2 假端口（可注入 fsync 失败/短写/超时/pidfd 失败）；T3 真实进程（一次性 VM，真实 socketpair/pidfd/cgroup/flock/exec）；T4 环境故障（私有 tmpfs ENOSPC/EROFS）。
- seam：纯函数库、假端口、test-only 协议对端、canary CLI（exec 写 `CANARY_EXEC`、收到 release 写 `CANARY_RELEASED`）、flock 探针 + `/proc/locks`、fd 快照。
- 每例必须：前置/操作/观测点/预期状态/失败判据；至少一个内核级或文件级可观测量；负例必须有“只去掉该故障”的配对正向运行。

### 7.2 正向对照（强制）

clean deploy（canary 作 CLI）：`attempt_created→precheck(pass)→start_invoked→start_call_begin→gate_authorized→start_result(exit_0,command_sent=yes)→resolution(exit_0,no,running,match)`；`CANARY_EXEC`+`CANARY_RELEASED`；release 字节恰一次；exit 0；结束锁空闲；无 fd 泄漏。**该用例失败则全部负例不可判定。**

### 7.3 矩阵摘要（完整版见队友 D 合同 §二）

- 协议：length 短/长/超长、payload≠0、粘包/逐字节、前缀阶段收 fd、CTRUNC、额外 fd、0 长度请求、截断。
- 执行：无 FIN、FIN 后额外帧、FIN 后 2B 前缀、execve 失败（不存在/非 ELF/无权限）、放行前/后 SIGKILL、supervisor 各阶段 SIGKILL、done 失败、ACK 失败。
- Evidence：evidence-only、evidence+not_sent 缺 resolution、gate=closed+release=yes、released 无 release、reason↔kind 不匹配、fsync 失败、not_sent 写失败。
- 锁/回收：并发第二实例、kill -9 持有者、subreaper 回收、ENOSPC、日志替换、latch 阻断。
- 测试产物：stdout JSON/audit.jsonl/replay.json/canary 标记/fd 快照/锁探针/exit code；汇总表“通过/失败/不可判定”三态，不可判定不得计通过。
