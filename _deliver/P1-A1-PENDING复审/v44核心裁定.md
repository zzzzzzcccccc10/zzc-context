## 一、P0-1 收养与 waitpid（唯一判定）

### 1.1 waitpid 五分支

| 返回值 | 语义 | 动作 |
|---|---|---|
| `>0`（pid,status） | 回收一个子进程 | 记录 pid/status/是否 launcher/CLI；继续循环 |
| `0`（WNOHANG） | 有子进程但无状态变化（仍存活） | 记录“存活子进程存在”；不重试同一 pid；继续用 pidfd/proc 判活 |
| `-1, ECHILD` | 无可等待子进程（或非父） | **不等于 reparent 未完成**；改用 pidfd/proc 判活；无活体→收尸完成；有活体→存活 |
| `-1, EINTR` | 被信号中断 | 重试一次 |
| `-1, 其他 errno` | 参数/权限/内部错误 | fail-closed：hold/30，不得解释为收尸完成 |

### 1.2 证据链与 observed

- 顺序：`pidfd_open(pid)` → `fstat(fdinfo)` 校验 Pid/NSpid → `/proc/<pid>/stat` starttime 对比 → `pidfd poll(POLLIN,0)` 判死 → `waitpid(-1,WNOHANG)` 回收 → cgroup/proc children 辅助。
- `/proc/<pid>/task/<tid>/children` **仅辅助**，不保证精确（可能漏刚退出子）；不得单独证明清单完整。
- `observed` 三态：`true`（pidfd+starttime+waitpid/cgroup 交叉成功）、`partial`（部分证据）、`false`（无法取得完整清单）。
- `observed=false/partial` **不得**解释为“无存活子进程”；N3 不成立 → 不得 not_sent；进入 hold/unknown（见 §二）。
- `live_children[]` 只写 main 观测结果；`observed=false` 时 `[]`+`cli_state=unknown`。

### 1.3 收尸边界

- supervisor 存活时 main 不 waitpid launcher；supervisor 死后 launcher/CLI 归 main（subreaper）。
- 循环：`waitpid(-1,WNOHANG)` 直到 `-1,ECHILD` 或连续 `0` 且 pidfd/proc 判死/超时。
- ECHILD 后仍用 pidfd/proc 判活；有活体→T-HALT；无活体→完成。
- 超时 `T_REAP=5s`（从 TERM/KILL 起）；仍活→M-HALT/23。

## 二、P0-2 hold 决策表（唯一，互斥）

| 路径 | 前置（全部） | WAL 事件 | 文件 | L/M | 退出 | recover 唯一结果 |
|---|---|---|---|---|---|---|
| P1 W3 正常 | WAL 可写；sub 已死；无存活子进程（observed=true）；N3 可证 | takeover(3)→token→latch→attempt_hold | hold.token+latch | 持→释放 | 22 | basis=attempt_hold；operator_resolution |
| P2 T-HALT | WAL 可写；有活子或不可观测；已 takeover(3) | takeover(3)→halt(4)→W4→takeover(4→5)→W4R attempt_hold | HALT+hold.token+latch | 持→释放 | 22 | basis=attempt_hold；W4R 已写 |
| P3 F-HALT | WAL 不可写；HALT 可写 | 无 | HALT+hold.token+latch | 持→释放 | 22 | **basis=latch**（无 attempt_hold） |
| P4 M-HALT | WAL/HALT 均不可写 | 无 | 内存态+hold.token?（可写时） | 持（不释放） | 不退出（心跳）；SIGKILL→23 | 23 人工 |
| P5 不可观测 | observed=false/partial；WAL 可写 | takeover(3)→halt(4)→W4→W4R attempt_hold（cli_state=unknown, observed=false） | HALT+token+latch | 持→释放 | 22 | basis=attempt_hold；N3 不成立不得 not_sent |

- **observed=false 时禁止走 P1**（N3 不成立）；只能 P2/P3/P4，按 WAL 可写性选择。
- 每条路径互斥；实现按“WAL 可写? → HALT 可写? → observed?”选择，不得跨 § 拼接。
- P3 的 recover：WAL 无 takeover/attempt_hold；以 latch/token/HALT 判定；resolution{failed?} 不写 WAL 时保留 HALT。

## 三、P1-1 HALT epoch 字段

HALT 文件：`{attempt_id, wal_epoch, halt_request_epoch, wal_persisted: bool, halt_seq, holder_pid, holder_pstart, boot_id, reason, created}`。

- `wal_epoch` = 最后已持久化 WAL epoch（0/1/2/3/4/5）。
- `halt_request_epoch` = 当前请求的 epoch（仅当 wal_persisted=true 时才等于 4/5；否则为请求值，不是已发生状态）。
- `wal_persisted=false` 时不得声称 epoch 4/5 已发生；恢复以 WAL 为准；HALT 仅提示。
- M-HALT 增加“latch 成功→latch-only 22（若 HALT 可写则更新 wal_persisted=false；不可写则内存态）”分支。

## 四、P1-2 fstatat 标志

- 关闭前 `fstatat(audit_fd, name, &st, AT_SYMLINK_NOFOLLOW)`；默认跟随符号链接不可用。
- 校验 `S_ISREG`、`dev/ino` 等于 WAL fd；不符→STOP/NW。
- 重开路径的逐级 openat 用 `O_NOFOLLOW`；fstatat 仅用于关闭前目录项复核。

## 五、P1-3 A0 门禁（U-01/U-02）

- U-01（VERSION/install.json/journal schema 与包摘要公式）、U-02（生产/测试同源规范）未冻结：
  - **A0 全部 BLOCKED**；F-SEAL、T0B-05/16、E16c/d **BLOCKED**。
  - 单独批准 A0 不能跳过；实验方案 A0/P5 前置必须写“U-01/U-02 已冻结”。
- 冻结后 A0 才可执行；E16a/b/f 不受 F-SEAL 影响，但 A0 整体仍以门禁为准。

## 六、P1-4 T2-02a 注入点

- 注入：**W2 的 `hold_request` 行 fsync 第一次 EIO**（写入已发出、fsync 返回 EIO），同一写者重试一次成功；行保留、seq 不跳。
- 预期：hold_request 落盘=1；supervisor 发帧/收尸/退出；main W3 takeover=1、latch=1、attempt_hold=1；无 terminal；exit 22。
- 若重试仍失败 → 视为持续故障（T2-02b），不得计入 02a；02b 注入“WAL+latch fsync 持续 EIO”，预期 halt-live。
- W1 向量撤销（fork 前无 supervisor，无 hold 协议）。

## 七、P1-5 T3-18 夹具（A/B/C）

- **A（main 死）**：main 在 attempt_hold 前 SIGKILL；L 可取得（或残留锁可判）；WAL 尾未裁决；无活 supervisor；`F-ABANDON`+`F-HOLD` 组合；预期 23（recover 指示）。
- **B（supervisor 活）**：supervisor 存活且 pidfd 可开、starttime 匹配；main 死；L 被 supervisor 持（或 main 残留）；预期 23（不接管、不写 WAL）。
- **C（不可确认）**：pidfd/proc 不可用或 starttime 不符、boot_id 不符；预期 30（零 WAL 写）。
- F-HOLD 需新增 `--variant A|B|C` 构造脚本：A 杀 main+释放 L；B 停 supervisor（SIGSTOP）+main 死；C 伪造身份/屏蔽 proc（A0/A2 受限）。
- 三向量各自独立 VM 快照，不共享现场。

## 八、P1-6 orphan token 确认合同

- `--confirm` 输入：`--confirm <64hex>`（小写；去空白）；token 规范 sha256=sha256(ASCII hex)。
- token 文件 `run/<id>/hold.token`：`{attempt_id, token_hex, token_sha256, holder_pid, holder_pstart, nonce, created}`（0600）。
- orphan token（无 latch）恢复：从 token 文件取 attempt_id/holder/nonce；与 WAL attempt_created/attempt_hold（若存在）、HALT 文件交叉；`--confirm` 匹配 token_hex；写 `operator_resolution{basis=hold_token, authority_seq=token_seq?}`（无 latch 时 authority_seq 指向 attempt_created 或 0，需记录）。
- abort.intent：`{attempt_id, token_sha256, nonce, holder_pid, holder_pstart, requested_at}`；O_EXCL 0600；同 token 幂等、异 token 23。
- 防重复授权：resolution 已存在→同 token 只清理、不重写；不同 token 23；清理顺序 resolution→intent→HALT→token→latch（latch 最后）；每步 fsync(dir)。
- 清理中断：resolution 存在即视为已授权；后续只幂等清理；不得再写第二条。

## 九、P1-7 时间预算（统一起点）

- 统一 `CLOCK_MONOTONIC`；`handshake_deadline = spawn_begin 时刻 + 20s`（共享绝对）。
- `T_CLI_WAIT=125s`：从 `release_byte{written}` 写成功起算（CLI 执行等待）。
- `T_SUP_EXIT_FRAMED=126s`：从 main 收到 HOLD_REQ/EOF 起算，**包含** 125s CLI 等待 + 1s 余量。
- `T_SUP_EXIT=5s`：无帧时从 main 收到 EOF/pidfd POLLIN 起算。
- `T_REAP=5s`：从 TERM/KILL 发出起算；TERM→1s→KILL 计入 T_REAP。
- `T_EXEC_FRAME=5s`：从 release_byte 起算；`T_ABORT_WAIT=5s`：从 abort 写 intent 起算。
- 各期限独立但共享 monotonic；不得叠加解释；watchdog 独立且触发=FAIL。
