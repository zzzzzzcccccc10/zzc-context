## 〇、三个跨领域模型（冻结）

1. **hold/锁**：L/M 只由 main 持有；CLI 不持锁；hold 写者=main；latch 先建（O_EXCL 取 ino）→ attempt_hold fsync → 终止/回收 launcher → 释放 L/M → exit 22；operator 经 abort（写 token 文件、不取 L）→ main/recover 校验 → operator_resolution → 删 latch → 释放 L。
2. **两次 fork**：fork1 子关 P/L/M/日志副本、父关 S 并 close(log_fd) 移交写权；fork2 子关 S/release_w/error_er/log_fd/M/dirfd、父关 release_r/error_ew/sidecar_w 副本；spawned fsync 先于 fork2。
3. **WAL 写权**：W1 main（attempt_created…spawn_begin）→ W2 supervisor（spawned…terminal+resolution）→ W3 main 恢复（waitpid 证终止后 takeover）；任一时刻至多一个写者；fork→close 窗口为残余。

## 一、威胁模型与边界

- 保护目标：防项目内部脚本/普通本地用户绕过事务、伪造审计/放行。
- 不防御：root、Docker socket 写权限、等效系统管理权限主体。
- 互斥保证：main 存活期间持 L；main 崩溃即锁释放（已知残余，由 WAL/latch 判定）；不宣称全局永久互斥。
- 权限基线（安装根/状态根 root:root、祖先链可信）是运行前提；不达标 fail-closed。
- 日志非防篡改；fsync 不建模扇区撕裂；时钟不作安全依据。

## 二、安装启动链（契约 A）

### 2.1 安装根与状态根

**安装根** `/opt/astrbot-deploy`（root:root 0755；U2 关闭为冻结）：

```
bin/astrbot-deploy   0755 root:root  #!/bin/sh 唯一运行时入口
lib/deploy.py        0644 root:root  # 单文件 helper，无 shebang
lib/SHA256SUMS       0644 root:root  # GNU 格式，恰 3 条
lib/VERSION          0644 root:root  # JSON schema
```

**状态根** `/var/lib/astrbot-deploy`（0700 root:root）：`lock`（0600，L）、`audit/`（WAL/unresolved）、`run/`（sidecar/cli.log/M）、`latch/`、`probe/`、`install/`（driver.lock/install.json/install.pending.json/install.journal）。

- 祖先链逐级 lstat：root:root、非 symlink、无 group/world write；dirfd+dev/ino 锚点；不符 → 事务前 10，事务中 22。
- 安装器只由安装流程创建状态根；运行时只校验，不 chmod/chown。

### 2.2 单文件 helper 与 wrapper

- **单文件**：仅标准库 import；无兄弟模块、无 sys.path 修改；`-I` 的 sys.path 行为不影响正确性。
- bootstrap：先断 flags → 导入标准库（失败 exit 10）→ `umask(077)`、`chdir("/")`、TZ/LC 设置 → main；`os.write` 单行 JSON 后 `os._exit(rc)`（无缓冲）。
- wrapper：`#!/bin/sh`，≤40 行；PATH 重置、绝对 `/usr/bin/{stat,readlink,sha256sum,python3}`；校验祖先/树/SHA/解释器后 `exec python3 -I -S -B .../deploy.py "$@"`；不 fork、不写文件、不读状态根。
- **D4 直调边界**：生产运行时唯一入口 wrapper；直接调用仅两个豁免——`selfcheck`（A0 测试）与 `installer` profile（root-only，安装/升级/回滚）；wrapper 拒绝 `installer`。
- **D14 A0**：仅一次性 VM/独立根执行；不碰目标宿主 `/opt/astrbot-deploy` 或 `/var/lib/astrbot-deploy`；`.a0-test-root` marker 门控 `--test-*`。

### 2.3 selfcheck（S-01…S-16 + G-01…G-03）

flags；CPython 3.9–3.12/64 位；内核≥5.4 + pidfd/waitid/prctl/flock；canonical 路径/锚点；安装树文件集/SHA/VERSION；sys.path 卫生（不依赖 sys.path[0]）；euid==0；SIGPIPE==SIG_IGN；umask/TZ/LC/chdir；状态根 stat/fstype/空间；写探针（O_EXCL 0600+fsync+unlink+dir fsync）；锁探针（EWOULDBLOCK→11，其他→10）；docker 文件/`--full` 才 `_ping`；cgroup v2/prctl。

- G-01 journal 存在 → mutating 10（零改动）、只读/selfcheck 允许；G-02 latch/未裁决 → 运行时 23、安装器 11；G-03 未裁决 unknown → 23。
- 失败：调用方在打开 WAL/取 L/调 docker 前 `emit_json(10,preflight_failed,reason)` 退出；零改动。
- exit 10 域：wrapper 预检 + helper 自检 + bootstrap 失败；pre-`__main__` 解释器失败（语法错 exit 1/126/127/信号）明确出契约，调用方按“未解释终止”处理。

### 2.4 退出码（三表分离）

**helper/wrapper**：0 成功；2 用法；10 前置；11 锁忙；20 not_sent；21 unknown；22 hold/审计不可信；23 存在 latch/未裁决（零改动）；24 命令失败；30 内部错误；126/127 wrapper exec 残差（无 JSON）。

**launcher**：70 gate closed；71 协议/fd 断言；72 持久化失败；74 快照 A 失败；79 内部兜底（hold）；127 execve 失败（唯一 errno 帧）；永不 exit 0。**解释守卫**：仅 `¬exec_begin` 才解释为 launcher 码；`exec_begin` 存在时一律按 CLI 退出码。

**安装器**：0 成功；2 用法；10 前置；11 忙/hold；20 包真实性；21 包内容非法；30 内部；40 已恢复到调用前状态（升级=旧树，首装=未安装）；41 恢复失败（人工）。**不进入 helper 表**。

### 2.5 安装/升级/回滚（A-INST）

- 包：`deploy-<semver>.tar.gz`，四文件；tar 归一化；带外 `--package-sha256`；成员结构校验/逐文件读、O_EXCL 写、fsync/chmod/fsync、目录 fsync；compile 门；payload==SHA256SUMS==VERSION 交叉。
- 安装器：root-only；`install/upgrade/verify/installer-rollback`；**driver.lock（D）全程持有**；**L 分段**：Phase1 持 L（解包/换名/journal）、Phase2 放 L（selfcheck 验证）、Phase3 再持 L（提交/回滚）。Phase2 绝不持 L，消除 selfcheck 锁探针死锁。
- 换名：优先 `renameat2(RENAME_EXCHANGE)`（dirfd 相对、同 fs）；不支持则两阶段（旧树→B、新树→canonical），每步 `/opt` dir fsync；EXDEV 不降级。
- journal 状态机：prepared→staged→swapped→verified→committed/rollback；pending 权威窗口；崩溃恢复 D0–D9 按磁盘状态（canonical/install.json/journal/gen）判定，不靠文件名猜角色；恢复失败 41。
- 首次安装失败：移走 canonical 并清理，退出 40（恢复到未安装）；删除失败 41。
- 安装后验证：Phase2 selfcheck 子进程 exit 0 + 单行 JSON outcome=success；失败自动回滚，持 L 下进程内校验（不调 wrapper selfcheck），40/41。

### 2.6 stdout 契约

- 运行时：恰一行 JSON `{v,exit,outcome,attempt_id,reason}`；`outcome`：success/usage/preflight_failed/lock_busy/held/not_sent/command_failed/result_unknown/audit_untrusted/internal_error；`os.write` 单次无缓冲 + flush 语义；子进程 1/2 重定向到 `run/<id>/cli.log` 或 `/dev/null`。
- 安装器：独立 JSON schema（op/semver/gen/prev_semver/package_sha256/state/reason）。
- wrapper 预检失败也发静态 JSON；126/127 无 JSON。
- 调用方规则：JSON+exit 一致才采信；无 JSON 且 1/126/127/128+n → 未解释终止，不推断、不自动重试。

## 三、进程与 FD 生命周期（契约 B）

### 3.1 拓扑与锁

```text
main（持 L、M；subreaper；唯一 JSON 写者）
└─ supervisor（fork 不 exec；无 L/M；W2 写者）
   └─ launcher（无 L/M/socket；读 release、写 sidecar、execve）
      └─ CLI（仅 {0,1,2}；1/2 指向 run 日志/ /dev/null）
```

- L/M 只 main 持有；CLI 不持锁（H1/H10/H11）；main 崩溃即锁释放（残余）。
- `abort/status` 不取 L/M；`recover --repair` 取 L→M（W3 恢复写者）。
- 23 判定先于取 L：只读扫 latch/未裁决 → 23 零改动，不 flock(L)。

### 3.2 FD 矩阵与 CLOEXEC

| FD | execve 前 launcher | CLOEXEC | exec 后 CLI |
|---|---|---|---|
| 0/1/2 | 打开（1/2 重定向） | **false** | 保留（1/2=日志/ /dev/null） |
| sidecar_w | 打开 | **true** | 关闭 |
| error_ew | 打开 | **true** | 关闭 |
| L/M/P/S/log/dirfd/pipe/pidfd | 不存在或关闭 | true | 关闭/不存在 |
| 其他非白名单 | 关闭 | true | 关闭 |

- launcher 步骤序：`关闭批次（S/release_w/error_er/log/M/dirfd/目录 fd）→ 快照 0 断言 {0,1,2,release_r,sidecar_w,error_ew}（失败 71）→ 读 release→写 cli_release_received→close(release_r)→快照 A {0,1,2,sidecar_w,error_ew}（失败 74）→ 写 exec_begin（无缓冲+fsync）→ execve`。
- 快照 A/B 用 `/proc/self/fd` 枚举 + fstat dev/ino/类型 + `F_GETFD` 标志；`F_GETFD` 不能枚举集合。
- 快照 B：canary 自证；生产外部 `/proc/<pid>/fd` 佐证，观测不到记 observed=false，不改变结论；泄漏 → evidence `fd_leak_post_exec` + unknown/hold，永不 not_sent。

### 3.3 两次 fork（成功/失败）

- fork1：`spawn_begin` fsync → fork；子首条 close(P)/close(L/M/日志副本)；父成功 close(S)+close(log_fd)（写权移交）+close(sidecar_w)，失败保留 log_fd/sidecar_w 写 spawn_failure/not_sent/resolution。
- fork2：supervisor 写 `spawned` fsync（先于 fork2）→ 建 release/error pipe → 写 `cli_spawn_begin` fsync → fork；子首条 close(S)/close(release_w)/close(error_er)/close(log_fd)/close(M)/close(dirfd)；父关 release_r/error_ew/sidecar_w 副本。
- fork2 失败：supervisor 写 cli_spawn_failure/not_sent/resolution；main 只 finalize。
- 所有失败路径：terminal 前必须已 waitpid 成功（hold/early 例外按证据表）。
- 写权：W1 main → W2 supervisor → W3 main；任一时刻至多一个写者；fork→close 窗口残余。

### 3.4 hold 与 operator 解除

- hold：latch（O_EXCL 0600，取 ino，fsync 文件+目录）→ attempt_hold（含 latch_ino/live_children/token_sha256）fsync → 终止/回收 launcher（或证明未执行）→ 释放 L/M → exit 22。
- hold 后禁止 gate/release/exec；不得倒回 not_sent；释放 L 前屏障：launcher/CLI 已收尸，或 `¬exec_begin ∧ release 未写`；否则 hold_and_halt（存活持 L）。
- agent（abort）：只读状态根/读 WAL hold/pidfd_open(main)+starttime；写 token 文件（O_EXCL 0600，含 attempt/token/main pid/pstart/nonce）+fsync；不取 L；SIGUSR1 通知 main（无载荷）。
- 解除：main 校验 token/latch/身份 → 写 operator_resolution（含 operator/attempt_result/reason/authority_seq=hold_seq/token_sha256/latch/decided_at）fsync → 删 latch fsync(dir) → 释放 L/M → 退出。
- main 已死：`recover --repair` 取 L → writer_takeover → 校验 token → 写 operator_resolution（若不存在）→ 删 latch → 释放 L。
- 幂等：同 attempt+token 的 operator_resolution 已存在 → 只清 latch，不重写；不同 token → 拒绝 23。
- operator 结论限制：未 gate 可 not_sent/aborted；已授权未 release 可 not_sent；已 release 无 exec 证据只能 result_unknown；有 exec 证据只能一致。

## 四、通信协议

- 帧 36B：4B length + 32B header（统一大端）；pidfd 帧 1 fd，done/ack/fin 0 fd；challenge 非零、pidfd 帧 0。
- SCM_RIGHTS：每次 recvmsg 带控制缓冲 + MSG_CMSG_CLOEXEC；fd 按帧累计（含前缀）；CTRUNC/TRUNC 关闭 fd；单帧最多 4。
- 发送：一帧一次 sendmsg 36B；禁止 0 长度 send；所有 sendmsg 带 MSG_NOSIGNAL；fd 帧返回必须 36，0<n<36 永不重试。
- EOF：仅“请求≥1 + 返回 0 + 帧边界”判 EOF；半帧返回 0 = 截断；POLLRDHUP 不直接判 EOF；ECONNRESET/ENOTCONN = 协议错误。
- OOB：不设 SO_OOBINLINE 为启动条件；禁止 MSG_OOB/SIOCATMARK；按内核配置分支，E15 记录。
- 时间预算：`T_HANDSHAKE_TOTAL=20s` 从 spawn_begin 共享绝对 deadline；阶段 5s 仅上限；`T_REAP`/`T_CLI_WAIT` 独立；watchdog 触发=FAIL。

## 五、WAL 与状态重放（契约 C）

### 5.1 事件与写权

- 封套：`v=40,event,attempt_id,seq,epoch,writer,pid,pstart,boot_id,mono,time,d`；seq 严格 +1；`writer/epoch` 绑定（main↔1/3，supervisor↔2）；裸 os.write + fsync。
- 事件最小集：attempt_created/precheck/start_invoked/start_call_begin/cgroup_created/spawn_begin/spawn_failure/spawned/cli_spawn_begin/cli_spawned/cli_spawn_failure/metadata_published/pidfd_sent/done_sent/ack_ok/fin_ok/eof_observed/cgroup_migrated/gate_authorized/release_byte/exec_observed/cli_reaped/sidecar_merged/evidence/start_result/start_not_sent/attempt_aborted/attempt_hold/abort_requested/operator_resolution/resolution/writer_takeover/recovery/halt。

### 5.2 唯一顺序与迁移前置

```
attempt_created → precheck* → start_invoked → start_call_begin → cgroup_created → spawn_begin
→ spawned → cli_spawn_begin → (cli_spawned|cli_spawn_failure)
→ metadata_published → pidfd_sent → done_sent → ack_ok → fin_ok → eof_observed
→ cgroup_migrated(gate=closed) → gate_authorized → release_byte
→ exec_observed? → cli_reaped → sidecar_merged → terminal → resolution
```

- 相邻性写死：migrate→gate→release；terminal→resolution（operator_resolution 为合一终态）；ack/fin/eof 顺序。
- 迁移失败：不写 gate/release；evidence(cli_migrate_failure, gate=closed, release=not_written) → not_sent；回收不能证 → hold。
- gate 载荷：challenge_sha/ack-fin-eof seq/cli pid+pstart/pidfd fdinfo/cgroup 锚点+readback/各判据/时间；重放可复算，缺失 hold，矛盾 invalid。

### 5.3 release 语义

- 唯一授权：`release_w` 写 1 字节 `0x52`；launcher 未读到前不得 execve；写成功后才写 `release_byte{written}` 事件。
- 写失败（EPIPE/0/短写）→ evidence(release_failure, authorized, failed) → not_sent(cli_release_write_failed)；不写 release_byte。
- 恰一次：每 attempt 至多一个 release_byte；重复 → invalid。
- 崩溃窗口：写 pipe 成功、release_byte 未 fsync → sidecar 有 cli_release_received 而 WAL 无 release_byte → hold（release_commit_window），不得 not_sent。

### 5.4 exec 判定

- T-NOT-SENT（N1–N7）：sidecar sealed（ok/empty）或 absent 且 DR1–DR5；绑定一致；已回收+cgroup 空+无未识别子进程；授权态确定（未授权，或已授权且无 exec_begin）；error pipe 0B EOF；无成功/失败证据；not_sent_verified evidence 已持久化。
- P1：exec_begin 无缓冲写 + execve 前 fsync；不满足不得以 ¬exec_begin 推断未执行。
- T-EXEC-FAILED：sidecar cli_exec_failed 或 error pipe 8B `EXC1+errno`；晚于 exec_begin。
- T-EXEC-SUCCESS：exit 0（launcher 恒非 0）/ptrace/proc_exe（需 E14，未过不得唯一依据）；冲突 hold。
- T-EXEC-UNKNOWN：exec_begin + reaped + sealed + 无成功/失败 → evidence(exec_unconfirmed)+start_result(result_unknown)+resolution；永不 not_sent。
- 优先级 FAILED > SUCCESS > NOT-SENT > UNKNOWN；launcher 码解释守卫（仅 ¬exec_begin）。

### 5.5 evidence 表（唯一元组）

| kind | gate | release_byte | cli_exec | reaped | 允许 reason |
|---|---|---|---|---|---|
| early_pre_cli | closed | not_written | not_executed | not_applicable | cgroup/pipe/challenge 失败 |
| early_post_cli | closed | not_written | not_executed | true | metadata/pidfd/done/sidecar/log/ack 记录失败 |
| ack_failure | closed | not_written | not_executed | true | cli_ack_failed/challenge_mismatch/ack_timeout |
| cli_migrate_failure | closed | not_written | not_executed | true | cli_cgroup_enter_failed |
| abort_before_gate | closed | not_written | not_executed | true | gate_closed/launcher_protocol_fd/fd_assert_failed/killed/supervisor_lost |
| abort_after_gate | authorized | not_written | not_executed | true | supervisor_lost_after_gate |
| abort_after_release | authorized | written | not_executed | true | cli_aborted_after_release/killed |
| release_failure | authorized | failed | not_executed | true | cli_release_write_failed |
| execve_failure | authorized | written | failed | true | cli_exec_failed |
| exec_unconfirmed | authorized | written | unknown | true | exec_unconfirmed |
| not_sent_verified_* | closed/authorized | not_written/written | not_executed | true | not_sent_verified |
| evidence_write_failed | — | — | — | — | 仅 hold |

### 5.6 sidecar 与重放

- sidecar：JSONL，首行 created（attempt/boot_id/pid/pstart/nonce），后续 fact（seq 严格 +1）；唯一写者 launcher；绑定 dev/ino/sha；三态 absent/present_unmerged/present_merged。
- 合并：launcher 定型（reaped 或 exec 成功）后，supervisor（或 W3 main）合并；`sidecar_merged` 内联 cli_release_received/exec_begin/exec_failed/fd_snapshot/seq 范围/sha；合并后仅 WAL 可独立重放。
- 重放阶梯：operator_resolution > resolution > start_result > start_not_sent > attempt_hold（非终态）> DR1–DR12 > hold > invalid > unknown；采用前唯一性/authority_seq/顺序/写者/not_sent 复核/unknown 成对。
- DR1–DR12：crash_before_spawn、fork1_failed、supervisor_startup_crashed、launcher_not_forked、fork2_failed、gate_closed、migrate_failed、release_write_failed、abort_after_gate、abort_after_release、exec_failed、exec_unconfirmed。
- 矛盾组合 hold：双终态、resolution 非最后、closed+release、released 无 release、not_sent 无证明、seq 跳号、writer 冲突、boot_id 变化、sidecar 冲突、orphan latch。
- 尾部修复：短写截断到完整行+换行+fsync；终止事件不补 recovery；中间行非法只读取证。
- 跨事务门禁：有 latch/未裁决 hold/unknown/unrecorded → 拒绝自动 start/restart，只读报告（23）。
