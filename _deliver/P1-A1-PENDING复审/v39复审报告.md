## 二、四人一致确认的阻断

### 一致 1：hold/operator 生命周期未闭合（B、C 主发现，A 交叉）

- 冻结 D12/设计 §3.5 同时写“holder 写 latch → 释放 L → exit 22”和“holder 被 SIGUSR1 唤醒 → 写 operator_resolution → 退出”：前者使 holder 已死、SIGUSR1 必 ESRCH，后者又要求 holder 存活；两读法互斥。
- L 为 OFD 共享 flock：main/supervisor/launcher/CLI 各持副本，“holder 释放 L”只关自己副本，锁仍被 CLI/main 持有；持有者=supervisor 时 main 仍持 L，下一调用可能先取 L 失败报 11 而非 23；recover 取 L 被挡 → 死结换形态复发。
- `attempt_hold` 在 §5.1 被列为 terminal 后接 resolution，§5.6 又标“非终态”；operator 路径只写 operator_resolution、不写 resolution，违反“terminal→resolution 相邻且 resolution 最后”。
- token：attempt_hold 只存 sha256，全文无 token 生成/展示/熵源/长度；token 文件不含 operator 身份；abort“只读”却写 token 文件；latch 写入与 attempt_hold 先后倒置（attempt_hold 记 latch_ino 时 latch 尚未创建）。
- 双裁决：resolution fsync 后、删 latch 前崩溃 → 下一 recover 再写 operator_resolution；防双裁决只写在 abort 侧，recover 侧无“存在即拒”/重查；无 latch 的 abandoned 无收束规则。

### 一致 2：安装/升级不可执行（A 主发现，D 交叉）

- 安装器/入口未定义：唯一入口子命令不含 install/upgrade/verify，§2.6 又有且 `rollback` 同词异义；安装器产物路径/属主/SHA/调用/输出契约未定义。
- “全程持 L”与 selfcheck lock 探针死锁 → 安装后验证必 exit 10 → 首次安装无 `.old` → 安装永远失败/回滚。
- 换名：解包只做目录 fsync、未逐文件 fsync；`RENAME_EXCHANGE` 后旧树在 `.new` 而回滚只认 `.old`；崩溃点无“磁盘状态→动作”表；rename 非 dirfd 相对（TOCTOU）；ctypes/renameat2 回退未定。
- 退出码：`os._exit` 不 flush stdout → 管道下“恰一行 JSON”丢失；wrapper 预检失败谁发 JSON 未定义；语法错被误写为 126/127（实际 1）；40/41 与 helper 表分离已对齐但安装器入口缺失。

### 一致 3：FD/fork/端点合同仍有缺口（B 主发现，A/C 交叉）

- launcher 步骤序（快照→读 release→close(release_r)→清 L CLOEXEC→写 exec_begin→execve）在 v39 丢失；快照 A 仅 `fcntl(F_GETFD)` 不能枚举集合，缺 `/proc/self/fd`+fstat。
- fork1 窗口：main 与 supervisor 同持 WAL fd（“至多一个写 fd”为假）；spawn_begin 后关 log_fd 再 fork 与 W2 要写 spawned 矛盾；spawned 与 fork2 先后未写死，`¬spawned ⇒ not_sent` 可误判。
- 端点：§3.1 说 main 持 P/supervisor 持 S，§3.2 又说 supervisor fork CLI 前 close(P)（它早已无 P）；fork1 子关 P/父关 S 未写；supervisor 白名单缺；error pipe/sidecar_w 合同只在冻结稿、正文缺失（supervisor 不关 error_ew → 0B EOF 永不可达）。
- `terminal 前必须 waitpid 成功`与 `reaped=false 只能 hold` 对 attempt_hold/early 互斥。
- CLI 继承 L（CLOEXEC=false）与“释放 L”不相容；残余描述未覆盖“活体 hold 后 CLI 仍持锁”。

### 一致 4：状态/证据仍有错误 not_sent 与不可还原（C 主发现，B/D 交叉）

- T-NOT-SENT 缺“exec_begin 必须以无缓冲写 + execve 前 fsync”前提；v38 的 fsync 顺序表在 v39 丢失 → 掉电窗口可把已 exec 误判 not_sent。
- `¬spawned ⇒ not_sent` 未要求 `¬cli_spawn_begin ∧ ¬cli_spawned ∧ sidecar 不存在`。
- release 二义：gate 已授权、release 事件缺失时，既可派生 not_sent 又被“released 无 release ⇒ hold”压住；无优先级 → 永久 hold 或错误 not_sent。
- evidence 表：`cli_abort_before_exec` 允许 closed/released 四组合，与“closed+release 必须 hold”矛盾；缺 `not_sent_verified` 等判决事实（cgroup 空/子进程扫描/error pipe 长度），重放无法独立验证。
- launcher 码 70/71/72/74/79/127 与 exec 后 CLI 退出码同空间，无“仅 ¬exec_begin 才解释为 launcher 码”的守卫；71/72/74/79→reason 映射缺失。
- sidecar 三态（不存在/未合并/已合并）未区分、格式/seq/校验未定义、合并写者丢失；`launcher_terminal` 未定义。
- hold 后无收束屏障（v38 显式禁令回归丢失）。

### 一致 5：测试/实验不可交付（D 主发现，A 交叉）

- 精确退出码非唯一（30“按 21 处理”、两阶段窗口 exit 10 与安装失败、closed/released 成对）；授权取值域未定义（T0a/T1/T2/T4 归谁）；E14 的 proc_exe 与 A1 只读冲突；A1 零写入无证明；E16 归属与“是否纳入授权”二义；C-A2 清理缺恢复 mount/sysctl 与失败路径；E12 阈值未进入设计；变异 20+5 无映射；validator 15 条无内容。
