## 一、spawn_closed 与 cli_spawn_failure（修复 1）

### 1.1 定义（唯一）

`spawn_closed=true` 当且仅当：
- `spawned` 事件存在；且
- `cli_spawn_begin` 不存在（未 fork2），**或** 恰一条合法 `cli_spawned`，**或** 恰一条合法 `cli_spawn_failure{stage:"fork2",errno}`。

- `cli_spawn_failure` 是 fork2 失败的**合法终止**：表示 launcher 从未存在（无活体、无 pid 可发布）；`spawn_closed=true`，observed 可 true（无活体），N3 可证，允许 not_sent(`cli_launcher_spawn_failed`)。
- `cli_spawn_begin` 存在且既无 `cli_spawned` 又无 `cli_spawn_failure` → `spawn_closed=false`、observed 至多 partial；唯一处理见 v45 崩溃窗口（P2/hold-live，禁 not_sent）。
- 半行 `cli_spawned`/`cli_spawn_failure` 被尾修复截断后视为“无该事件”：若同时无另一合法终止 → spawn_closed=false（保守），不得补写。
- `cli_spawn_failure` 后不得再接 `cli_spawned`；两者并存→invalid/HOLD。

### 1.2 测试

- 新增 T2-23a：fork2 失败（`cli_spawn_failure`）→ spawn_closed=true、observed=true、not_sent(`cli_launcher_spawn_failed`) 20。
- T2-23b：`cli_spawn_failure` + 半行 `cli_spawned` → 截断后 spawn_closed=true（failure 合法）、not_sent 20；若并存完整两条→HOLD 22。
- T3-22a 现场（begin∧无 spawn/failure）→ spawn_closed=false（既有断言不变）。

## 二、T2-21a 计时冲突（修复 2）

### 2.1 唯一时间线

`t0` = **完整合法 36B HOLD_REQ 帧收齐那一刻**；`t_eof` = 随后读到 P EOF 那一刻（t_eof≥t0）。
- 合法帧+EOF：`T_SUP_EXIT_FRAMED=126s` 从 **t_eof** 起算（含 125s CLI 等待+1s）。
- 仅 EOF 无完整帧/截断帧：`T_SUP_EXIT=5s` 从 `t_eof` 起算。
- 完整帧但 EOF 未到（P 未关）：`T_EOF_WAIT=1s` 从 t0 起算；超时=协议违规→TERM/KILL（T_REAP 5s）。
- P 开、无帧、无 EOF：从 supervisor 死亡证明/收尸起点起 `T_SUP_EXIT=5s` 协议违规→TERM/KILL；不得等 watchdog。

### 2.2 T2-21a 断言（消除重叠）

- 场景：帧在 t 收齐、EOF 在 t+2s；supervisor 不退出。
- 唯一预期：t0=t+2（EOF）；`t0+126` 前无 TERM；`t0+126` 发 TERM；`t0+127` KILL；T_REAP t0+131；最终按 P2（有活体/不可观测）22。
- 若 supervisor 在 `t0+126` 前退出：**无 TERM**，正常 finalize（22 或 20/21，按证据）；这是 T2-21a 的“早退分支”，与“不退出分支”互斥，测试夹具固定选择“不退出”，早退分支由 T2-21a2 单独覆盖。
- 删除“t+2+125.9 无 TERM”与“supervisor 在窗口内退出则 22”混写；改为明确两分支。

### 2.3 新增子例

- T2-21a2：EOF 后 supervisor 在 126s 内退出→25s 内无 TERM、正常 finalize（22）；不触发 KILL。
- T2-21c 保持：EOF 无帧→t_eof+5 TERM、+6 KILL。

## 三、T3-22c/d/e 与 hold-live 优先级（修复 3）

### 3.1 矛盾

T3-22c/d/e 用 T3-22a 现场（有未识别活体/observed=partial）期望 22 latch-only，但 W4R 失败后按 P4b 铁律“有活体/不可观测→hold-live（不释放 L/M、无 22）”，二者冲突。

### 3.2 裁定

W4R 失败后**必须重新观测一次**：
- 若 `live≠[]` 或 `observed≠true` → **P4b hold-live**（持 L/M、心跳、SIGKILL→signal9；next 23）；**不得 22**。
- 仅当 `live=[] ∧ observed=true`（现场活体已被回收，且 spawn_closed）→ 22 latch-only。

W4R 六子态（S1/S2a/S2b/S3a/S3b/S4）各有两个出口：
- `-live`：重新观测有活体/不可观测 → hold-live（无 exit；next 23）。
- `-dead`：重新观测无活体 observed=true → 22 latch-only。

### 3.3 测试映射（T3-22c/d/e 拆分 + 六子态）

- T3-22c = S1：c-live（hold-live）、c-dead（22）。
- T3-22d = S2a/S2b：d-live、d-dead（S2a/S2b 共用断言，HALT 4/4 或 5/5 各断言）。
- T3-22e = S3a/S3b：e-live、e-dead（S3a 半行首次不截断；S3b 同 S2）。
- S4（attempt_hold 已持久，非 W4R 失败）→ T3-22f：basis=attempt_hold，22/0 按证据；不得当 latch。
- 计数：T3-22 族由 5 子例扩为 12 子例（a+b+c/d/e/f 各 2 + a2? 见统计）。

## 四、resolution 双写原子性（修复 4）

### 4.1 与顺序

- 载体：`run/<id>/resolution.json`（0600、O_EXCL、单行 ≤4KiB、fsync 文件+目录）；WAL `operator_resolution` 事件（仅当 WAL 可写且末 epoch=4）。
- **写序（冻结）**：① 写 resolution.json（O_EXCL+fsync file+dir）→ ② 若 WAL 可写且末 epoch=4，写 WAL operator_resolution（fsync）→ ③ 清理。
- 原子性：文件是**权威**；WAL 是审计副本。
  - 文件成功、WAL 失败 → 以文件为准；不重写 WAL；不清理失败（保留现场，reason=wal_audit_missing）。
  - 文件失败 → 不写 WAL；返回 30/23（按是否可重试）；不得只写 WAL。
  - 文件已存在（O_EXCL EEXIST）→ 校验同 token/attempt_id；同→幂等清理；异→23 零改动；不得重写。
  - WAL 事件已存在但文件缺失（崩溃于文件后、WAL 前？不可能；或文件被删）→ 补写文件（O_EXCL；EEXIST 校验）；WAL 不重复写。
  - 两者都存在 → 校验一致；不一致→30 保现场。
- 崩溃恢复：recover 先读文件再读 WAL；文件存在即视为已授权（WAL 缺失只记 audit_missing）；文件缺失但 WAL 存在→补文件；都无→写文件（再 WAL）。
- 清理顺序：intent→HALT→token→latch→resolution.json（**文件最后删**）；WAL 事件不删（审计）；每步 fsync 目录；ENOENT 容忍；同 token 重入只续清理。
- 防重复：文件 O_EXCL；WAL 事件最多一条；同 token 幂等；异 token 23。

### 4.2 测试

- T3-25a：文件成功、WAL 失败→文件权威，exit 0（清理仅文件）；审计缺 WAL。
- T3-25b：文件失败→30/23，WAL 不写，零清理。
- T3-25c：文件+WAL 均成功→一致，0；二次只清理。
- T3-25d：文件存在、WAL 缺→0，不重写 WAL。
- T3-25e：WAL 存在、文件缺→补文件（O_EXCL），0；不重写 WAL。
- T3-25f：文件/WAL 不一致→30 保现场。
