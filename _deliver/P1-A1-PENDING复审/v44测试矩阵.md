| F-HOLD | `--variant A\|B\|C`：A latch 后/attempt_hold 前杀 main；B SIGSTOP supervisor+杀 main；C boot_id 不符现场 | 三变体 selftest（A L 可取、B pidfd/starttime、C boot_id 伪造） | 归档+删现场 |
| F-ABANDON | main 死、L 已释放、WAL 半途 | ps 无进程、L 可取、WAL 指纹 | recover 或归档后删 |
| F-CONC | 双实例 barrier | barrier 对齐 | kill 两进程 |
| F-RECOVER | 可修复现场（latch+token+缺 attempt_hold/孤 token） | recover 只读 preflight、token/latch 校验 | 归档后删 |
| F-RLIMIT | nofile=64 包装 | `ulimit -n` 回读 | 恢复 |
| F-REAL-CANARY | 真实 docker canary 镜像+running/match 双源 | docker run/ps | 删容器/镜像 |

### 十.1 F-SEAL 10 步

1 备份（cp -a+sha256 清单）→2 阳性对照（无 mutation 重封装→selfcheck 0）→3 构造变体（语法错/version/schema）→4 同源封印器重封装（重算 SHA/VERSION/install.json）→5 封印自检（sha256sum -c+verify）→6 原子植入（rename+dir fsync）→7 执行 case→8 原子恢复（sha256sum -c+selfcheck 0+零残留）→9 归档 mutation 规格/哈希/恢复证明→10 失败语义（封印链不一致→BLOCKED；恢复失败→U4）。

## 十一、判定规则

- 每向量唯一 (outcome,reason,X)；拆分子例记 a/b；向量 case 全匹配才 PASS。
- 四态：PASS/FAIL/UNDECIDABLE（计不通过）/BLOCKED（未执行不计分）；watchdog=FAIL（02b/04a halt-live 例外）；清理失败=U4。
- 0 值必须绑定执行证据；未执行/前置失败禁 0，填 N/A 或 BLOCKED。
- NOT-SENT：n1n7（N3 observed=true）/frame_proven（E 持久+F 8B+EOF；免 N5/N6，仍需 N1–N4+N7）。
- A0 门禁：U-01/U-02 未冻结→A0 全单元/F-SEAL/T0B-03/05/16/E16a–f/D0–D9/installer 直调 BLOCKED。
- 批次通过=全必测 PASS+无 U+清理证明+FC 传播满足；报告同时报 101 族/105 子例。
