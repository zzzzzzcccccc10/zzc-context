## 〇、六项强制闭合（相对冻结稿的修正）

1. **CLOEXEC 精确表**：0/1/2 与 L 为 `CLOEXEC=false`；sidecar_w/error_ew 及其余非白名单为 `true`；exec 后 0/1/2/L 保留，其余关闭。
2. **安装升级换名**：优先 `renameat2(RENAME_EXCHANGE)`（同文件系统、内核支持）；不支持则两阶段换名 + `.old` 回滚；每步目录 fsync；崩溃点与恢复见 §2.6。
3. **退出码分离**：helper 表与安装器表分开；安装器 40/41 为独立退出码（40=回滚成功，41=回滚失败），不混入 helper 表。
4. **operator_resolution 落地**：操作者 `abort --confirm` 写 token 文件 + SIGUSR1（不取 L）；holder 校验后写 `operator_resolution` → fsync → 删 latch → fsync(dir) → 释放 L → 退出；holder 已死由 `recover --repair` 取 L 写 takeover+operator_resolution；O_EXCL + latch/token 防双裁决。
5. **D4 边界**：生产唯一入口 wrapper；直调 helper 仅 `selfcheck` 且仅 A0 测试豁免；无环境变量/参数绕过。
6. **D14 环境**：A0 仅在一次性 VM/独立测试根执行；不写目标宿主 `/opt/astrbot-deploy` 或 `/var/lib/astrbot-deploy`。

## 一、威胁模型与边界

- 保护目标：防项目内部脚本/普通本地用户绕过顶层事务、伪造审计或放行。
- 不防御：root、Docker socket 写权限、等效系统管理权限主体。
- 互斥：至少一个监督进程存活时 L 被持有；主进程+supervisor 同时崩溃且 CLI 关闭 L → 已知残余，不宣称全局互斥。
- 权限基线（安装根/状态根 root:root、祖先链可信）是运行前提；不达标 fail-closed。
- 日志非防篡改；fsync 不建模扇区撕裂；时钟不作安全依据。

## 二、启动链（契约一）

### 2.1 安装根与状态根

**安装根** `/opt/astrbot-deploy`（root:root 0755）：

```
/opt/astrbot-deploy/bin/astrbot-deploy   0755 root:root  #!/bin/sh 唯一入口
/opt/astrbot-deploy/lib/deploy.py        0644 root:root  # 单文件 helper，无 shebang
/opt/astrbot-deploy/lib/SHA256SUMS       0644 root:root  # GNU 格式
/opt/astrbot-deploy/lib/VERSION          0644 root:root  # JSON schema
```

**状态根** `/var/lib/astrbot-deploy`（root:root 0700）：`lock`（0600）、`audit/audit.jsonl`（0600）、`run/`（0700）、`latch/`（0700）、`probe/`（0700）。

- 祖先链逐级 lstat：root:root、非 symlink、无 group/world write；目录 openat + `O_NOFOLLOW` + dev/ino 锚点；不一致 → 事务前 exit 10，事务中 exit 22。
- `/opt/astrbot-deploy` 与线上 `/opt/astrbot` 互不重叠；U2 关闭为冻结决定（A0 验证）。
- 状态根只由安装器创建；运行时只校验，不 chmod/chown。

### 2.2 单文件 helper 与 wrapper

- **单文件**：`deploy.py` 仅标准库 import；无兄弟模块、无 `sys.path` 修改、无 zipimport；`-I` 的 sys.path 行为不影响正确性。
- bootstrap 顺序：先断 flags（isolated/no_site/dont_write_bytecode/ignore_environment）→ 导入标准库（失败映射 exit 10）→ `umask(077)`、`chdir("/")`、`TZ=UTC`+`tzset`、`LC_ALL=C` → main；末尾 `os._exit(rc)`。
- **wrapper**：≤40 行 `#!/bin/sh`，仅 `stat/readlink/sha256sum` 白名单；检查祖先/安装树/SHA/解释器后 `exec /usr/bin/python3 -I -S -B .../deploy.py "$@"`；不 fork、不写文件。
- **直调边界**：仅 `selfcheck` 且仅 A0 测试豁免（带 `-I -S -B` 与 canonical 路径）；缺 flags/路径不符 → exit 10；生产无环境变量/参数绕过。
- 唯一入口：`/opt/astrbot-deploy/bin/astrbot-deploy <deploy|restart|rollback|status|abort|recover|selfcheck>`。

### 2.3 selfcheck（S-01…S-16）

flags、CPython/3.9–3.12/64 位、内核≥5.4 + pidfd/waitid/prctl/flock、canonical 路径、安装树/SHA/VERSION/install.json、sys.path 卫生（不依赖 `sys.path[0]`，只记录）、euid==0、SIGPIPE==SIG_IGN、umask/TZ/LC/chdir、状态根 stat/fstype/lock、docker 文件与 `_ping`、cgroup 探针、状态根写探针（O_EXCL 0600 + fsync + unlink + 目录 fsync，剩余≥1 MiB）、lock 探针、prctl get。

- 失败：调用方在打开 WAL/取 L/调 docker 之前 `emit_json(10, preflight_failed, reason)` 退出；零改动。
- 导入失败/pre-`__main__`：exit 10 仅覆盖 wrapper 预检 + helper 内可判定失败；解释器装载前失败（语法错/信号）明确出契约（126/127/128+n），B02 拆分。

### 2.5 stdout schema

恰一行 JSON：`{"v":1,"exit":<int>,"outcome":"<enum>","attempt_id":<null|32hex>,"reason":<null|string>}` + 扩展；`outcome`：`success|usage|preflight_failed|lock_busy|held|not_sent|command_failed|result_unknown|audit_untrusted|internal_error`；stderr 一行人类诊断，无 traceback；CLI 的 1/2 重定向到 `run/<id>/cli.log` 或 `/dev/null`。

### 2.6 安装/升级/回滚（renameat2 机制）

- 包：`deploy-<semver>.tar.gz`，含 bin/lib 四文件；tar 归一化（排序/mtime=0/owner=0）；带外 `--package-sha256` 校验；包内 payload==SHA256SUMS==VERSION 交叉。
- 安装器：root-only，独立于运行时入口；`install/upgrade/rollback/verify`；全程持 L；latch/未裁决 hold → 拒绝升级（exit 11）。
- **换名机制**：
  1. 解包到 `/opt/.astrbot-deploy.new.<rand>`（0700），设权、校验文件集、payload SHA、compile 门、目录 fsync。
  2. 旧树存在时：优先 `renameat2(canonical, new, RENAME_EXCHANGE)`（同文件系统、内核支持），一次原子交换；不支持（EINVAL/ENOSYS/EXDEV）则两阶段：
     - `rename(canonical, /opt/.astrbot-deploy.old.<rand>)`；目录 fsync；
     - `rename(new, canonical)`；目录 fsync。
  3. 两阶段窗口内 canonical 缺失 → wrapper fail-closed exit 10（预期，不判安装失败）；重跑时按 `.old`/`.new` 恢复。
  4. 安装后验证：`astrbot-deploy selfcheck` == 0、VERSION 与包 semver 一致、stat 矩阵；失败 → 回滚：`rename(canonical, .failed)`、`rename(.old, canonical)`、fsync、selfcheck；成功 exit 40，失败 exit 41。
  5. 成功后保留最近一代 `.old`，下一次成功安装清理；`.new/.failed` 清理；所有目录 fsync。
- 崩溃点：S2 新树残留（可清理）；S4 canonical 缺失（wrapper 10，重跑恢复）；S5 新树可见（自检）；S6 验证失败（回滚）；S7 install.json 缺失（自检 10，重跑补写）。

## 三、进程与 FD 生命周期（契约二）

### 3.1 拓扑

```text
main（持 L、M、P；subreaper）
└─ supervisor（fork 不 exec；持 L、M、S；fork CLI 前关 P）
   └─ launcher（关 S、release_w、error_er、log_fd、M、dirfd；持 release_r、error_ew、sidecar_w、L）
      └─ docker CLI（exec 后 {0,1,2,L}；1/2 指向 run 日志/ /dev/null）
```

### 3.2 FD 矩阵与 CLOEXEC（精确表）

| FD | execve 前 launcher | CLOEXEC | exec 后 CLI |
|---|---|---|---|
| 0/1/2 | 打开（1/2 重定向） | **false** | 保留 |
| L | 打开 | **false（仅 launcher 副本）** | 保留 |
| sidecar_w | 打开 | **true** | 关闭 |
| error_ew | 打开 | **true** | 关闭 |
| 其他非白名单 | 关闭 | true | 关闭 |

- 四状态矩阵：main M0/M1、supervisor S1/S2、launcher L0/L1a/L1、CLI C1；每 FD 创建/关闭/身份。
- 快照 A（launcher 自证）：`fcntl(F_GETFD)` 验证 execve 前集合 `{0,1,2,L,sidecar_w,error_ew}` 与 CLOEXEC 精确值；失败 `_exit(74)`。
- 快照 B（exec 后）：canary 自证/生产 `/proc/<pid>/fd` 佐证 `{0,1,2,L}`；sidecar_w/error_ew 缺席；失败 → 泄漏证据，`result_unknown`/hold，永不 not_sent。
- fork 瞬间库存：main 9 fd、supervisor 12 fd；child 按“库存−白名单”关闭并断言；失败 `_exit(71)`。
- 端点：supervisor fork launcher 前 close(P)；child 首条 close(S)；父留 S；fork→close 窗口声明残余；“execve 调用时点无 socket”表述保留。

### 3.3 两次 fork 与失败路径

- fork1 失败：main 继续写 `spawn_failure`/not_sent/resolution（写权未移交）；`spawned` 缺席是重放判别键。
- fork1 成功、supervisor 在 `spawned` 前死：main waitpid 后按 `spawn_begin ∧ ¬spawned ∧ supervisor_reaped` 派生 `not_sent(cli_supervisor_startup_crashed)`；无法证终止 → hold。
- fork2 失败：supervisor 写 `cli_spawn_failure`/not_sent/resolution，main 只 finalize。
- 所有失败路径：terminal 前必须已 waitpid 成功；`reaped=false` 只能 hold/unknown。

### 3.4 写者与锁

- W1 main（attempt_created…spawn_begin）；spawn_begin fsync 后关 log_fd → fork1。
- W2 supervisor（spawned 起…terminal+resolution）；`spawned` 只由 supervisor 写。
- W3 main 恢复写者（supervisor 已证终止、无 terminal）：先 `writer_takeover`。
- W4 holder；Seq 每次 append 独立 flock。
- 任一时刻至多一个 WAL 写 fd；terminal 与 resolution 同一写者、同一纪元。
- L/M/Seq：L 全局 flock（OFD 共享）、M attempt 互斥、Seq 追加锁；关闭序：terminal fsync → resolution fsync → 删 unresolved → close log/M → 最后 L；锁文件 O_NOFOLLOW + dev/ino 锚定。

### 3.5 hold 与 operator_resolution（落地）

- hold：holder 写 `attempt_hold{reason,holder_pid,holder_starttime,token_sha256,cli_state,latch_ino}` + latch（O_EXCL 0600 + fsync 文件/目录）→ 释放 L → exit 22；下一调用见 latch → 23（零改动报告 holder/attempt）。
- **operator 流程**：
  1. 操作者 `astrbot-deploy abort <attempt_id> --confirm <token>`；abort 只读打开状态根、读 WAL 的 attempt_hold、pidfd_open(holder)+starttime 校验；**不取 L/M**。
  2. 写 token 文件 `latch/hold-<id>.release`（O_EXCL 0600，内容 attempt_id/token/holder pid/pstart/nonce）+ fsync；若已存在且匹配视为重试，不匹配拒绝。
  3. `pidfd_send_signal(SIGUSR1)` 通知（无载荷）；holder 已死 → 转 `recover --repair`。
  4. holder 被唤醒：校验 token/latch/身份 → 写 `operator_resolution{operator,attempt_result,reason,authority_seq=hold_seq,token_sha256,latch,holder,decided_at}` + fsync → unlink latch + fsync(dir) → close M/L → 退出。
  5. holder 已死：`recover --repair` 取 L（唯一写者）→ 写 `writer_takeover` → 校验 token → 写 operator_resolution → 删 latch → 释放 L。
- **防双裁决**：latch/token 均 O_EXCL；operator_resolution 唯一且为最后；两操作者只有一个能创建 token/写 resolution；第二个见已存在则只报告不重复写。
- operator 结论限制：未 gate 可 not_sent/aborted；已授权未 release 可 not_sent；已 release 无 exec 证据只能 result_unknown；有 exec 证据只能与证据一致。
- latch 写不进 → hold_and_halt（不退出、不释放 L、stderr 循环；SIGKILL 后残余）。

## 四、通信协议（沿用冻结）

- 帧 36B：4B length + 32B header（统一大端）；pidfd 帧 1 fd，done/ack/fin 0 fd；challenge 非零，pidfd 帧 0。
- SCM_RIGHTS：每次 recvmsg 带控制缓冲 + MSG_CMSG_CLOEXEC；fd 按当前帧累计（含前缀）；CTRUNC/TRUNC 关闭 fd；单帧最多 4。
- 发送：一帧一次 sendmsg 36B；禁止 0 长度 send；所有 sendmsg 带 MSG_NOSIGNAL；fd 帧返回必须 36，0<n<36 永不重试。
- EOF：仅“请求≥1 + 返回 0 + 帧边界”判 EOF；半帧返回 0 = 截断；POLLRDHUP 不直接判 EOF；ECONNRESET/ENOTCONN = 协议错误。
- OOB：不设 SO_OOBINLINE 为启动条件；禁止 MSG_OOB/SIOCATMARK；按内核配置分支，E15 记录。
- 时间预算：`T_HANDSHAKE_TOTAL=20s` 从 spawn_begin 共享绝对 deadline；阶段 5s 仅上限；`T_REAP`/`T_CLI_WAIT` 独立；harness watchdog 触发=FAIL。

## 五、状态机与证据（契约三）

### 5.1 唯一顺序

```text
… ack_ok → fin_ok → eof_observed
→ cgroup_migrated(gate=closed)
→ gate_authorized
→ release_byte
→ exec_observed / cli_reaped
→ sidecar_merged
→ terminal(start_result/start_not_sent/attempt_hold)
→ resolution
```

- migrate 失败：不写 gate_authorized；evidence(cli_migrate_failure, gate=closed) → not_sent；回收不能证 → hold。
- gate_ok = 迁移前预检 + 迁移 read-back + 身份/协议 + 未 halt/hold/abort + launcher 存活；不满足不放行。

### 5.2 gate 载荷

challenge_sha、ack/fin/eof seq、cli pid/starttime、pidfd fdinfo、cgroup 锚点/readback、各判据结果、时间；重放可独立验证。

### 5.3 evidence 表（8 类）

| kind | gate | release_byte | cli_exec | reaped | 允许 reason |
|---|---|---|---|---|---|
| early_stage_failure | closed | not_written | not_executed | not_applicable/true | cgroup/supervisor/CLI/元数据/pidfd/done 失败 |
| ack_failure | closed | not_written | not_executed | true | cli_ack_failed |
| cli_migrate_failure | closed | not_written | not_executed | true | cli_cgroup_enter_failed |
| release_failure | authorized | failed | not_executed | true | cli_release_write_failed |
| cli_abort_before_exec | closed/released（成对） | not_written/written | not_executed | true | gate_closed/exec_aborted/launcher_fd_assert_failed/killed/supervisor_lost |
| execve_failure | released | written | failed | true | cli_exec_failed |
| exec_unconfirmed | released | written | unknown | true | exec_unconfirmed（仅 result_unknown） |
| evidence_write_failed | — | — | — | — | 仅 hold |

- `reaped=true` 必须已 waitpid 成功；`reaped=false` 只 hold；`reaped=not_applicable` 仅无 CLI 的 early。
- 迁移失败 evidence gate=closed（v38 修正）；release 失败 gate=authorized。

### 5.4 exec 判定

- T-NOT-SENT（N1–N6）：sidecar 已合并（ok/empty）、身份一致、已回收+cgroup 空+无未识别子进程、无 exec_begin、error pipe 0B、无成功/失败证据。
- T-EXEC-FAILED：sidecar cli_exec_failed 或 error pipe 8B `EXC1+errno`；必须晚于 exec_begin。
- T-EXEC-SUCCESS：exit0（依赖 launcher 恒非 0）/ptrace/proc_exe（需 E14，未过实验前不可作唯一依据）；多方法冲突 hold。
- T-EXEC-UNKNOWN：exec_begin 无失败/成功 → evidence(exec_unconfirmed) + start_result(result_unknown)；永不 not_sent。
- 优先级：FAILED > SUCCESS > NOT-SENT > UNKNOWN；冲突 hold。
- launcher 退出码：70 gate_closed、71 协议/fd、72 持久化、74 快照、79 内部兜底（hold）、127 execve 失败。

### 5.5 WAL 与 sidecar

- 主 WAL 唯一权威；sidecar 只读辅助；`sidecar_merged` 内联 launcher 事实（cli_release_received/exec_begin/exec_failed/fd_snapshot/seq 范围/sha）；合并后仅 WAL 可独立重放。
- sidecar 绑定：attempt/boot_id/pid/pstart/seq/dev-ino；launcher 定型（回收或 exec 成功）后立即合并；未合并/截断/冲突 → hold，hold 优先于派生。
- 空 sidecar 仅 launcher_terminal+reaped 合法；与 exec 证据并存 → hold。

### 5.6 重放阶梯

operator_resolution > resolution > start_result > start_not_sent > attempt_hold（非终态）> 可证派生（DR1–DR12：crash_before_spawn/spawn 失败/release 失败/exec_aborted/exec_failed/evidence-only）> hold > invalid > unknown；采用前校验唯一性/authority_seq/顺序/写者/not_sent 复核/unknown 成对。
- 矛盾组合 hold：双终态、resolution 非最后、closed+release、released 无 release、not_sent 无 evidence、seq 跳号、writer 冲突、boot_id 变化、sidecar 冲突。
- 尾部修复：短写截断到完整行+换行+fsync；终止事件不补 recovery；非终止补一次。
- 跨事务门禁：有未裁决 hold/unknown/unrecorded → 拒绝自动 start/restart，只读报告。
