## 一、P1-1 audit 跨进程恢复唯一判定

### 1.1 核心原则

- audit 文件**不单独承担“持久状态”证明**；恢复时其内容只作参考，必须与独立证据交叉。
- 独立证据：WAL `operator_resolution`（epoch4，完整且身份一致）或 resolution.json 的 `resolution_sha256` 与 audit 文件一致。
- 无法交叉→`unknown`，不读权威、不参与 resolved、不阻塞 0。

### 1.2 恢复判定表（按顺序）

| # | 现场 | 唯一判定 |
|---|---|---|
| 1 | 无 audit 文件、无 `.failed` | `absent`（不参与 resolved） |
| 2 | audit 文件存在，内容校验通过（单行/JSON/dev-ino/attempt_id/resolution_sha256 一致），且 WAL epoch4 operator_resolution 完整一致 | `present`（可参考 written） |
| 3 | audit 文件存在，内容校验通过，但 WAL 无 epoch4 事件（missing 或不可读） | `unknown`（不得读 written） |
| 4 | 完整写入但 `fsync(file)` EIO（重启后内容合法）：与 #2/#3 同一判定；无 WAL 交叉→unknown | unknown/present |
| 5 | `fsync(dir)` EIO：同 #4；目录项未确认→unknown（即使内容合法） | unknown |
| 6 | `.failed` 存在且原 audit 文件仍存在 | **`.failed` 优先→unknown**；原文件不得读 written |
| 7 | link 成功、unlink 失败（两文件并存） | `.failed` 存在即 unknown 优先；原文件不得读 written |
| 8 | 归档失败且无 `.failed`，原文件保留 | 按 #2/#3 判定；无法交叉→unknown |

- `.failed` 存在时一律 unknown；不得据原 audit 文件内容判 written。
- 短写/半行→unknown；O_EXCL 不重写；归档不覆盖（沿用 v52）。
- audit 失败不阻止 resolution 完成；0 仍成立。

- m3c：`.failed` 与原文件并存→unknown，原文件不读 written。

## 二、P1-2 重建字段来源闭合

### 2.1 resolved_at

- WAL `operator_resolution.d` **必须包含 `resolved_at`**（RFC3339 UTC，写事件时生成）；重建直接复制该字段，不得用恢复时当前时间。
- 缺 `resolved_at`→30（零写/零清理/保留）。

### 2.2 attempt_hold / halt_seq

- `attempt_hold` **必需**（P1 epoch3 / P2 epoch5 均存在）：缺整条→**30**，不得从其他事件推导 observed/spawn_state。
- `halt` 存在时 `halt_seq` 必需；缺→30；无 halt 事件（P1 路径）不要求 halt_seq。
- 新增用例：u（缺 resolved_at→30）、v（缺 attempt_hold→30）、w（halt 存在缺 halt_seq→30）。

### 2.3 重建字段表（冻结）

`v/attempt_id/basis/authority_seq/anchor/token_sha256/observed/spawn_state/resolved_at`；来源：v=1；attempt_id=attempt_created；basis/authority_seq/anchor/token_sha256/resolved_at=operator_resolution.d；observed/spawn_state=attempt_hold；全部必需，缺→30。
