### 3.3 失败路径与恢复（确保不持续停机）

| 失败点 | 恢复动作 |
|---|---|
| 停服失败 | 不继续；检查容器状态，人工处理 |
| 备份失败 | **立即 `docker start astrbot`**；记录；停止 |
| 备份校验不一致 | 立即启动；记录；停止 |
| 磁盘不足 | 不停服；记录；停止 |
| 临时文件复制/校验失败 | 删除临时文件；启动；记录；停止 |
| `mv` 失败 | 从备份恢复；启动；记录；停止 |
| 线上 SHA 校验失败 | 从备份恢复；启动；记录；停止 |
| 启动失败 | 从备份恢复 `main.py`；再次 `docker start`；若仍失败，记录并升级人工处理（容器可能需 `docker restart` 或检查日志） |
| 验证失败（27/204/加载/适配器） | 不自动回滚；停止并报告，由主人决定回滚（回滚步骤见第五节） |

所有路径的共同要求：一旦服务被停止，任何非“部署成功”分支都必须执行 `docker start astrbot`（或恢复后启动），并记录启动结果；不得让容器停留在停止状态。

### 3.4 正常部署步骤

1. 复核第二节并记录；
2. `sudo docker stop astrbot`；
3. 新建备份目录（已存在则中止），复制并校验；
4. 原子替换候选（3.2）；
5. `sudo docker start astrbot`，等待约 60 秒；
