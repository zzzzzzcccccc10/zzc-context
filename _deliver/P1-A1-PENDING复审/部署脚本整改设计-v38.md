## 一、威胁模型与边界（沿用）

- 保护目标：防项目内部脚本/普通本地用户绕过顶层事务；不防御 root、Docker socket、等效权限主体。
- 互斥：至少一个监督进程存活时锁被持有；主进程+supervisor 同时崩溃且 CLI 关闭 L → 已知残余。
- 权限基线（root:root、0755/0644、可信祖先链）是运行前提；不达标 fail-closed。

## 二、契约一：启动链信任

### 2.1 安装位置与权限（v38 修正）

- `deploy.sh`：`/usr/local/sbin/astrbot-deploy`，`root:root 0755`，非 symlink。
- helper：`/usr/local/libexec/astrbot-deploy/deploy.pyz`（`root:root 0644`，无 shebang、无执行位）、`VERSION`（同目录 `0644`）；目录 `0755`，祖先链 `root:root`、非 symlink、无 group/world write。
- **不放 `/opt/astrbot`**（当前 0777/0666，无法作为可信根）；安装/升级由独立 root 流程完成，部署脚本不改自身。
- 每次运行前 `lstat` 自身、pyz、VERSION、祖先链；任一不符 → 零改动 `exit 10`，stdout 不输出“成功”JSON。

### 2.2 启动器合同

- `deploy.sh` 仅：注释、守卫、`lstat` 自检（可用 shell 内建/绝对 `stat`）、`sha256sum` 校验、`exec /usr/bin/python3 -I -S -B /usr/local/libexec/astrbot-deploy/deploy.pyz "$@"`。
- 绝对路径：`/usr/bin/python3`、`/usr/bin/sha256sum`；不读 PATH；`deploy.sh` 不 exec 其他程序、不调 sudo。
- SHA 校验失败/权限不符/文件缺失 → `exit 10`，stderr 明示，零改动。
- **明确不宣称**：校验防 TOCTOU；防篡改依赖权限基线（需单独立项）。

### 2.3 VERSION 与 selfcheck

- `VERSION` 由安装流程生成：pyz SHA-256 + 语义版本 + 构建时间；启动前比对 pyz 实测 SHA。
- `selfcheck`（子命令，每次启动前自动执行或由 T0b 调用）覆盖：
  1. 模块导入（`__main__`/`proto`/`audit`/`lock`/`cgroup`/`proc`/`ports`/`containers`）；
  2. `sys.path[0] == realpath(pyz)`、`sys.flags.isolated/no_site/dont_write_bytecode` 为真；
  3. `platform.python_implementation()=="CPython"`、版本 ≥3.9；
  4. `os.pidfd_open`/`os.P_PIDFD`/`signal.pidfd_send_signal`/`os.waitid` 可用；
  5. cgroup v2 统一层级与写权限（特性探测，非版本推断）；
  6. `/usr/bin/docker` 存在且非 symlink；
  7. 日志/锁目录可创建、fsync 探测。
- 任何失败 → `exit 10`（零改动、无 traceback、无 stdout 杂质）。
- **导入失败必须映射到 10**：`__main__` 包一层 `try/except BaseException`，写 stderr 后 `os._exit(10)`；不允许解释器默认 exit 1。

### 2.4 打包约定

- `deploy.pyz` 为 zipapp，`__main__.py` 在归档根，所有模块绝对顶层导入；禁止相对导入。
- 构建不加 `-p`（无 shebang/执行位）；安装 0644；生产包不含 `tests/`、不含 `TEST/FAULT/INJECT` 开关。
- **删除“构建可复现”声明**：zipapp 字节受 mtime 影响、`SOURCE_DATE_EPOCH` 在 zipapp 不生效；只声明“安装时对已装产物计 SHA”，不宣称可从源码重建比对。

### 2.5 环境设置

- 启动：`umask(077)`、`LC_ALL=C`、`TZ=UTC` + `time.tzset()`；`execve` 前恢复 `umask(022)`（避免把 077 传给 Docker CLI）。
- `ctypes` 白名单：仅 `CDLL(None).prctl(PR_SET_CHILD_SUBREAPER)`；pidfd 操作全部用 `os.pidfd_open`/`signal.pidfd_send_signal`/`os.waitid(os.P_PIDFD)`；禁止 `find_library`/硬编码 `libc.so.6`/subprocess。
- SIGPIPE：启动 assert `signal.getsignal(SIGPIPE)==SIG_IGN`（CPython 默认）；禁止恢复 SIG_DFL；声明该处置随 exec 传给 Docker CLI，需在 T4/canary 记录。
- 前置：Linux ≥5.4、Python ≥3.9；不满足 → `exit 10`，不降级。

## 三、契约二：进程与 FD 生命周期

### 3.1 进程拓扑与 fd 分类

```text
main（持 L、M、P，subreaper）
└─ supervisor（fork 不 exec；持 L、M、S；fork CLI 前关 P）
   └─ launcher（fork 后关 S、release_w、error_er、log fd；持 release_r、error_ew、sidecar_w、L）
      └─ docker CLI（execve 后仅 {0,1,2,L}）
```

| 名称 | 含义 | 持有者 | 生命周期 |
|---|---|---|---|
| L | 全局部署锁（flock，OFD 共享） | main、supervisor、CLI/后代 | 事务结束按顺序释放；CLI 继承为已知残余 |
| M | attempt 互斥（flock，main 持有） | main、supervisor | resolution/hold 后释放；**不继承给 launcher** |
| Seq | 每次追加的独立 flock（读尾+写+fsync） | 当前写者 | 单次操作，不跨 fork |
| P/S | 协议 socket 两端 | main/supervisor | 见 3.2 |
| release/error pipe | 放行/exec 证据 | supervisor/launcher | 见 3.2 |
| sidecar_w | launcher 侧证据写端 | **仅 launcher** | main/supervisor 在 fork 后关闭自己副本 |
| log_fd | 主 WAL 写 fd | 按写权相位 | CLI 不继承 |

### 3.2 fork 与关闭顺序（唯一）

```text
main: acquire L → acquire M → 建/核验日志/sidecar/unresolved → 写 attempt_created…start_call_begin（每行 fsync）
 → 建 cgroup C（cgroup_created 事件 fsync）→ socketpair(P,S) → 写 spawn_begin(fsync)
 → fork supervisor
   子 supervisor 第一条：close(P)；父 main 第一条：close(S)，记录 pid/starttime
 → main 读 pidfd/done，ACK→FIN→shutdown(SHUT_WR)

supervisor: close(P)（若未关）→ 建 release/error pipe → 写 cli_spawn_begin(fsync) → fork launcher
   子 launcher 前 6 条：close(S)、close(release_w)、close(error_er)、close(log_fd)、close(M)、close(目录 fd)
   保留：release_r、error_ew、sidecar_w、L
   父 supervisor 立即：close(release_r)、close(error_ew)、close(sidecar_w)
 → pidfd_open + 元数据发布（root 0600）→ 写 pidfd_sent → 发 pidfd 帧 → 发 done 帧 → 写 done_sent
 → 等 ACK/FIN/EOF → 形式化 gate（§4.2）→ 迁移（read-back）→ 写 gate_authorized → release byte
 → 观测 exec → wait → 合并 sidecar → 终态 → fsync → 退出

launcher: fd 快照（白名单）→ 读 release（1 字节 0x52）→ 写 cli_release_received(fsync) → close(release_r)
 → 写 cli_exec_begin(fsync) → execve；失败写 errno 帧 + cli_exec_failed(fsync) → _exit(127)
```

- **端点契约**：supervisor fork launcher 前 P 已不存在；launcher fork 后第一条可执行语句 close(S)；fork→close 窗口声明为残余（窗口内无外部可控代码路径，不构成自授权）。
- **fd 清单**：fork 前各进程用 `/proc/self/fd` + `fstat` 生成“编号/类型/dev-ino”完整清单；child 按“清单 − 白名单”关闭；关闭后断言白名单（`/proc/self/fd` + fstat）并写 sidecar `fd_snapshot{phase, fds[], exec_at}`；失败 `_exit(74)`，不 exec。
- **“exec 前无 socket”表述改为“execve 调用时点无 socket”**；T3 以快照断言，不宣称 fork→close 窗口内无。
- **M 不继承给 launcher**；`close(M)` 在 child 清单中，但父进程保留自己的 M；不存在“close(A)”歧义。

### 3.3 锁、写权、单一终态写者

- 写权相位：spawn 前 main；supervisor 存活期间仅 supervisor；supervisor 确认回收后 main（恢复写者）；launcher 只写 sidecar，不写主 WAL。
- 终态：`start_result`/`start_not_sent`/`attempt_hold` 三选一；`resolution` 由当前终态写者在 terminal 后写；同一 attempt 至多一条 resolution，且为最后一条业务行。
- main 在 supervisor 存活时不得写 terminal；不单方面杀 supervisor。
- **spawned 事件**：由 supervisor 自己写（`spawned{pid,starttime}`），main 不写；main 的 `spawn_begin` 是最后一条 main 写事件；消除 seq 竞态。
- done 发送失败：supervisor 先关闭 release_w → launcher 读 EOF `_exit(70)` → waitpid 回收 → 写 early evidence（reaped=true/cli_pid）→ not_sent(cli_done_send_failed)；main 只写 resolution。
- ACK 失败/主进程未收 done：main 关 P 撤回授权；supervisor 按 ack 失败收尾；EOF 不是 ACK。

### 3.4 活体 hold 与 abandoned

- hold 写者：supervisor 存活时 supervisor；supervisor 已证终止后 main；写 `attempt_hold{reason,holder_pid,holder_starttime}` + latch 文件 + fsync，**保持存活且 L fd 打开**，忽略 HUP/INT/TERM。
- hold 后状态机禁止 gate_authorized/release/exec；不得倒回 not_sent。
- **解除协议**：操作者 `deploy.sh abort <id> --confirm <token>` 向 holder 发送 SIGUSR1（经 pidfd）；holder 写 `operator_resolution` → fsync → 删 latch（fsync 目录）→ 释放 L → 退出；`recover` 只读检查并提示，不抢锁。
- **abandoned 判定**：下一事务 `flock(L, LOCK_EX|LOCK_NB)` 成功 ⇒ 无活体 → abandoned；取不到 ⇒ 活体 hold，拒绝自动操作并报告 holder pid。
- exit 23：仅当 main 退出后仍有另一活体持 L 时由 main 返回，stdout 输出 holder pid；否则 hold 由 holder 保持，不退出。
- latch 写不进 → hold_and_halt（不退出、不释放 L、stderr 持续报告）；SIGKILL 后无 latch 保护，属残余。

## 四、契约三：状态机与证据重放

### 4.1 事件与写者

| 事件 | 写者 | 说明 |
|---|---|---|
| attempt_created/precheck/start_invoked/start_call_begin | main | 意图层 |
| cgroup_created | main | cgroup 身份锚点（path/ino/mode） |
| spawn_begin | main | fork 前 WAL |
| spawned | supervisor | 自己写 pid/starttime |
| cli_spawn_begin/cli_spawned/metadata_published/pidfd_sent/done_sent | supervisor | 阶段 |
| ack_ok/fin_ok/eof_observed | supervisor | 协议观察 |
| gate_authorized | supervisor | 唯一授权事实（含 challenge 指纹） |
| release_byte | supervisor | written/failed |
| sidecar_merged | supervisor 或恢复写者 | 合并 sidecar 事实（内联关键事件） |
| exec_observed | supervisor | method/errno/status |
| start_result/start_not_sent/attempt_hold | 终态写者 | 三选一 |
| resolution | 终态写者 | 唯一终态 |
| abort_requested/attempt_aborted/operator_resolution | 对应写者 | 人工路径 |
| writer_takeover/recovery/halt | 对应写者 | 恢复/停止 |

- 封套：`v/event/attempt_id/seq/writer/pid/pstart/boot_id/time/mono`；seq 严格 +1；`additionalProperties=false`。
- **sidecar 权威**：主 WAL 是唯一权威；`sidecar_merged` **内联**关键事实（cli_release_received/cli_exec_begin/cli_exec_failed/seq 范围/sha），使合并后主 WAL 可独立还原；未合并 sidecar 只作只读取证。
- sidecar 绑定：attempt_id/boot_id/pid/pstart/seq + 文件 dev-ino（main 在 spawn 前锚定到 WAL `attempt_created`）；launcher 定型（回收或 exec 成功已证）后立即合并并 fsync。
- 冲突：主 WAL gate_authorized 而 sidecar 无 cli_release_received → 不推断 CLI 收到，按 unknown/hold；sidecar 有 exec_failed 而主 WAL 无合并 → 先合并再判；attempt/pid/starttime/boot_id/dev-ino 不一致 → hold；**未合并/冲突一律 hold，hold 优先于任何派生**。

### 4.2 gate 形式化（L1）

`gate_ok` 必须同时满足，缺一不放行：

1. `pidfd_sent_ok ∧ done_sent_ok`（supervisor 本地事实）；
2. 接收序列恰为 `ACK(X) → FIN(X) → EOF@帧边界`；ACK 在前、FIN 紧随、EOF 后无任何字节/帧；
3. `X ≠ 0` 且三帧 challenge 相同；pidfd 帧 challenge=0；
4. ACK/FIN 的 `cli_pid/starttime` 与 pidfd 帧、元数据一致；无额外 fd/字段；
5. launcher 身份已证（pid+starttime+pidfd fdinfo `Pid/NSpid` 交叉）；
6. cgroup C 就绪（cgroup_created 锚点），迁移后 read-back `cgroup.procs` 确认 launcher 在 C 且无其他 pid；
7. 未 halt/hold/aborted；日志可写。
- 任一不满足：不写 release 字节；终止/回收；写对应 evidence；只有 T-NOT-SENT 成立才 not_sent，否则 hold。

### 4.3 exec 成功判定与退出码

- **launcher 退出码恒非 0**：70 gate closed、71 协议/fd 断言失败、72 持久化失败、74 fd 快照失败、127 execve 失败；**所有非 exec 路径 catch-all `_exit(127)`**，禁止正常 return / `sys.exit(0)`；T0a AST 扫描 + T3 构造 exec 失败断言 exit≠0。
- **T-NOT-SENT**：launcher 身份已证且已回收 ∧ sidecar 已合并且无 `cli_exec_begin` ∧ cgroup C 空 ∧ 无未识别子进程 ⇒ 允许 not_sent。
- **T-EXEC-FAILED**：sidecar `cli_exec_failed` 或 error pipe 完整 8B errno 帧 ⇒ not_sent(cli_exec_failed)。
- **T-EXEC-SUCCESS**：ptrace `PTRACE_EVENT_EXEC`（强模式）或 exit status==0（依赖 launcher 恒非 0 不变式）或 EOF 后即时 `/proc/<pid>/exe` 为非 launcher 且 starttime 未变（需实验）。
- **T-EXEC-UNKNOWN**：sidecar 有 exec_begin 且无失败/成功证据 ⇒ result_unknown；**永不 not_sent**。
- 优先级：FAILED/NOT-SENT > SUCCESS；证据冲突 → hold；exit 0 仅在不变式成立且无失败证据时采信。

### 4.4 重放阶梯（唯一）

1. `operator_resolution` → 采用；
2. `resolution` → 采用（校验字段/authority_seq）；
3. `start_result` → 采用；
4. `start_not_sent` → 采用；
5. `attempt_hold` → 非终态，报告人工，禁止自动；
6. 可证派生（前提：sidecar 已合并且校验通过）：
   - ¬spawn_begin ⇒ not_sent(crash_before_spawn)；
   - gate_authorized 且 release_byte 缺失/failed 且 launcher 已证终止 且 sidecar 无 exec_begin ⇒ not_sent(cli_cgroup_enter_failed/cli_release_write_failed)；
   - gate_authorized + release_byte=written + 已终止 + 无 exec_begin ⇒ not_sent(cli_exec_aborted)；
   - sidecar exec_failed ⇒ not_sent(cli_exec_failed)；
   - 已持久化 evidence 且 `gate=closed ∧ release=not_written ∧ cli_exec=not_executed ∧ reaped=true` 且无终态 ⇒ 派生 not_sent(evidence.reason)；
   - sidecar 有 exec_begin 且无失败/成功 ⇒ result_unknown；
   - 未合并/冲突 ⇒ hold（优先于以上）；
7. 有活体/无法证明终止 ⇒ hold；
8. 证据链非法/矛盾 ⇒ 只读取证、不自动、不启动；
9. 其余 ⇒ result_unknown。

- 矛盾组合必须 hold：start_result+not_sent 并存、resolution 非最后、gate=closed+release=yes、released 无 release、not_sent 无 evidence、seq 跳号/重复、writer 身份冲突、boot_id 变化、sidecar_merged 无锚点、attempt_hold+resolution 并存。
- 尾部修复：短写/无换行 → 截断到最后一个完整行 + 补换行 + fsync；终止事件不补 recovery；非终止补一次 recovery；中间行非法 → 只读取证。
- fsync 顺序：evidence → not_sent；gate_authorized → release；release_written → exec 观测；sidecar_merged → 依赖 sidecar 的派生；start_result → resolution；resolution → 释放 L；latch/文件创建后 fsync(dirfd)。

### 4.5 migrate/release 证据修正

- `cli_migrate_failure`：`gate=authorized`、`release_byte=not_written`、`cli_exec=not_executed`、`reaped=true`（v37 的 gate=closed 修正）。
- `release_failure`：`gate=authorized`、`release_byte=failed`、`cli_exec=not_executed`、`reaped=true`；约束改为 `authorized ⇒ release_byte∈{not_written,failed,unknown}`。
- `cli_abort_before_exec`：按 reason 显式配对：`cli_gate_closed→(closed,not_written)`、`cli_exec_aborted/cli_supervisor_lost→(released,written)`；禁止 `closed+written`。
- `operator_abort` 单独 kind（或并入 cli_abort_before_exec 并单列 reason）；reason 命名拆分，每 reason 唯一 (event,kind,gate,release)。
- `exec_unconfirmed`：`reaped=false` 的活体态走 attempt_hold，不出 evidence。

## 五、通信协议（沿用 v37，修正 OOB/SCM 合同）

- 帧：`4B length + 32B header（统一大端，36B 总长）`；pidfd 帧 1 fd，done/ack/fin 0 fd；challenge 非零、pidfd 帧 0。
- SCM_RIGHTS：每次 `recvmsg` 带控制缓冲 + `MSG_CMSG_CLOEXEC`；fd 按当前帧累计（含前缀读取）；`MSG_CTRUNC/MSG_TRUNC` 关闭 fd 并协议错误；单帧最多 4 fd。
- 发送：**一帧 = 恰好一次 `sendmsg` 36B**；禁止 0 长度 sendmsg；**所有 sendmsg 带 `MSG_NOSIGNAL`**；fd 帧返回必须 36，`0<n<36` 永不重试；EINTR 仅未传输时可重试。
- OOB：**不设置 `SO_OOBINLINE` 作为启动条件**；禁止 `MSG_OOB`/`SIOCATMARK`；按目标内核 `CONFIG_AF_UNIX_OOB` 分三种分支记录（不支持/支持未内联/支持已内联），新增独立 OOB 实验（E15），不引用 E05。
- EOF：仅“请求≥1 + 返回 0 + 帧边界”判 EOF；半帧返回 0 = 截断；`POLLRDHUP` 不直接判 EOF；ECONNRESET/ENOTCONN = 协议错误。
- 超时：`CLOCK_MONOTONIC` 绝对 deadline；`T_PIDFD/T_DONE/T_ACK/T_FIN/T_SUP_EOF/T_MAIN_EOF=5s`、`T_REAP=5s`、`T_CLI_WAIT=120s`、`T_TOTAL=20s`（只覆盖握手，CLI 等待单列）；E12 校准。

## 六、日志 schema（摘要）

- 事件与字段：见 §4.1；`evidence` 字段：kind/reason/gate/release_byte/cli_exec/reaped/reap_method/reap_result/cli_pid/cli_starttime/exec_method?/exec_errno?。
- `resolution`：attempt_result/command_sent/container_state/disk_verification/source/authority_seq/derived/basis?/operator?/reason?。
- 严格 JSON：拒绝重复键/NaN/Infinity/非对象/未知字段；枚举与交叉约束写入校验器。

## 七、测试矩阵（完整版见 `v38测试矩阵.md`）

- 分层：T0a 静态 / T0b 启动实测 / T1 纯函数 / T2 假端口 / T3 真实进程 / T4 环境故障。
- 每例：case ID/层/前置/操作/观测/预期/失败判据/条款映射；至少一个内核或文件级可观测量；负例必须配对正向。
- **正向对照（T3）四层断言**：`gate_authorized → release_byte=written → sidecar cli_release_received（merged）→ exec_observed(success)`；canary 在 exec 起始写 `CANARY_EXEC`；`CANARY_RELEASED` 不再作为必要条件（canary 拿不到 release）；`command_sent=yes` 仅在 exit_0；release 恰一次由 WAL 唯一事件 + T2 发送计数断言；`running/match` 由 seam 或真实环境产生，正向对照失败则全部负例不可判定。
- 变异测试：永不 release、无 gate release、双 release、launcher 无 exec 以 0 退出、gate 前写 terminal、hold 后立即死、锁提前释放、sidecar 伪造/替换、pyz 篡改，各须被指定 case 抓住。
