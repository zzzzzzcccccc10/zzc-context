## 一、P1：SOCK_SEQPACKET 下的队列判空机制没有闭环

v34 规定：

"有效 FIN + POLLRDHUP + 队列空" 三者同时成立才允许迁移 CLI 和放行 execve。

其中 FIN 只是应用层终止声明，POLLRDHUP 用于证明对端写方向已关闭。这一设计方向合理，但还没有给出能够可靠判断接收队列为空的具体机制。

需要解决的 Linux socket 语义：

1. 对端 "shutdown(SHUT_WR)" 后，"POLLRDHUP" 表示写方向已关闭，但不直接证明接收队列为空。
2. "POLLIN" 不能简单用于区分队列非空与关闭状态，因为对端关闭写方向后也可能报告可读状态。
3. "SIOCINQ" 按数据字节数计算队列长度，不能可靠反映零长度记录。
4. "recvmsg()==0" 不能单独区分零长度记录与对端关闭。

因此，当前设计无法证明不会漏掉 FIN 后的零长度额外记录。

返修要求：

- 给出能够识别零长度额外记录的可靠判空机制；
- 明确 POLLRDHUP、接收队列、额外帧之间的检查顺序；
- 在目标 Linux 环境验证；
- 覆盖 FIN 后额外 32 字节帧、零长度记录、携带 fd 的额外帧以及真正的空队列；
- 如果 SOCK_SEQPACKET 无法满足要求，应评估其他传输方式，例如带长度分帧的 SOCK_STREAM，同时处理 SCM_RIGHTS 与流式分帧的关联。

不能仅把“队列空”写入设计文档而不说明实现如何证明。

## 二、P2：§4.2.1 与 evidence 状态机仍不一致

v34 已在 §4.5.2、§4.5.5 按失败阶段定义 evidence：

- "early_stage_failure"
- "ack_failure"
- "cli_migrate_failure"
- "execve_failure"

但 §4.2.1 仍有部分早期失败路径直接写 "start_not_sent"，没有体现先持久化对应 evidence 的要求。

涉及的路径包括：

- cgroup 创建或验证失败；
- supervisor spawn 失败；
- CLI fork 失败；
- 元数据写入失败；
- pidfd_open 失败；
- pidfd/done 帧发送失败。

这会让实现者在不同章节中得到不同的施工依据。

返修要求：

统一 §4.2.1、§4.5.2、§4.5.5 和失败矩阵：

"失败 → 写入对应 evidence → 确认成功持久化 → 满足该阶段回收和闸门条件 → start_not_sent → resolution"

逐项核对每种 reason 对应的 evidence.kind、字段和回收条件。

不得出现绕过 evidence 规则直接写入 "start_not_sent" 的路径。

## 三、P2：execve_failure 的 gate 字段语义不明确

当前 evidence 分表中：

- "gate=closed"
- "cli_exec=failed"
- "release_byte_written=yes"

问题是：放行字节已经写出，说明 CLI 曾经越过放行闸门，但 gate 仍记录为 closed。

如果 closed 表示“从未放行”，这与 release=yes 冲突；如果表示“失败后的当前状态已关闭”，则需要明确说明。

返修要求：

- 明确 gate 表示历史状态还是事件发生后的当前状态；
- 区分“放行前关闭”和“放行后失败”；
- 必要时调整字段枚举，避免审计程序将 execve_failure 误判成从未放行；
- 核对 reaped、reap_method、reap_result 的组合约束。

## 四、已认可的修订

以下内容本轮认可，不需要无理由回退：

1. FIN 不再单独作为发送方向终止证明。
2. 增加 POLLRDHUP 作为底层关闭证明。
3. POLLRDHUP 不可用或超时就不放行、保持锁、转人工。
4. FIN 完整验证合同已补充。
5. evidence 按四种失败阶段分类。
6. 不再把 "release_byte_written=no" 当作所有失败阶段的全局条件。
7. challenge 非零生成，零值重新生成，不再宣称数学意义上的绝对唯一。
8. evidence 写入失败或回收状态不确定时，不写对应 not_sent。
