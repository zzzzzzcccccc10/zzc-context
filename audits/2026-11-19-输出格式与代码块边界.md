## 一、A：裸 DSML 标记清理规范（裁定材料）

### 1.1 当前行为矩阵（用线上 `tool_xml_guard` 实跑）

| 输入 | 当前输出 | 判定 |
|---|---|---|
| `前缀A ｜｜DSML｜｜ calls 后缀B` | `前缀A ｜｜ calls 后缀B` | ❌ 残留 `｜｜ calls` |
| `前缀A ｜｜DSML｜｜ calls> 后缀B` | `前缀A ｜｜ calls> 后缀B` | ❌ 残留 |
| `前缀A ｜｜DSML｜｜ invoke name="x"> 后缀B` | `前缀A ｜｜ invoke name="x"> 后缀B` | ❌ 残留 |
| `前缀A ｜｜DSML｜｜ 后缀B` | `前缀A ｜｜ 后缀B` | ❌ 残留 `｜｜` |
| `前缀A \|DSML\| calls 后缀B`（半角） | `前缀A  calls 后缀B` | ❌ 残留 `calls` |
| `他问「｜DSML｜是什么意思」` | `他问「是什么意思」` | ⚠️ **误删正文里的有意引用** |
| `这个标记写作 ｜｜DSML｜｜` | `这个标记写作 ｜｜` | ❌ 残留 `｜｜` |
| 行内代码 `` `｜｜DSML｜｜ calls` `` | 原样保留 | ✅ 行内代码保护生效 |

结论：
1. 带尖括号的完整标记能清干净（v6 已验证）。
2. **裸标记（无尖括号）只会被 `replace("｜DSML｜","")` 挖掉中间**，两头残留。
3. 半角 `|DSML|` 连 `calls` 都留着。
4. **引号内的有意引用也会被删**——这是误删风险，不是残留问题。

### 1.2 建议规则草案（待裁定，未施工）

按"结构完整性"分四类处理，代码块内一律不动：

| 类别 | 形态 | 建议 |
|---|---|---|
| R1 完整结构 | `<｜｜DSML｜｜ calls>…</｜｜DSML｜｜ calls>` 或自闭合 | 整段删（保持现状） |
| R2 裸标记 + 白名单标签 | `｜｜DSML｜｜ calls` / `｜｜DSML｜｜ invoke name="x">` | 整段删到行尾（或到 `>`） |
| R3 裸标记单独 | `｜｜DSML｜｜` 后面不是白名单标签 | 只删标记本身，不留 `｜｜` |
| R4 引用场景 | 出现在行内代码、引号 `「」`/“” 内 | **保留**（现状会删，需改） |

配套约束：
- 白名单标签沿用 `calls / invoke / parameter / system_reminder / thinking / tool_call / tool_response / function_call / antml:invoke`。
- 半角 `|DSML|` 与全角 `｜DSML｜` 同规则。
- 代码围栏与行内代码内一律不处理（已有保护，需在 R2/R3 里保持）。
- 幂等：改完再跑一遍结果不变。

### 1.3 需要你裁定的三个点

1. **R2 删到哪**：删到行尾，还是只删到 `>`？删到行尾更彻底，但可能吞掉同一行的正常内容（如 `前缀A ｜｜DSML｜｜ calls 后缀B` 会变成 `前缀A  后缀B`，中间的"后缀B"是否该保留？）。
2. **R4 引号内是否保留**：保留能防误删，但模型真在引号里写完整结构时就不会清（可接受，因为引号内通常是"引用"而非控制）。
3. **R3 只删标记还是连后面空白一起收**：`前缀A ｜｜DSML｜｜ 后缀B` → `前缀A  后缀B`（双空格）还是压成单空格？按现有"逐字保留"规范应保留双空格。

## 二、B：代码块保真链路（只读审查）

### 2.1 会改代码内容的三层（按执行顺序）

| 顺序 | 插件 | 优先级 | 对代码块做什么 | 证据 |
|---|---|---|---|---|
| 1 | `multi_bubble` | 拆前 | 拆分后 `_tidy()`：`,`→`，`、`。`删、破折号→逗号 | 代码里 `_REPLACE` 表 |
| 2 | `rule_guard` | 80 | `strip_stage()` 把 `[ \t]{2,}` 压成 1 个空格 → **缩进被压缩** | 实测 `def add(a, b):\n    x = a + b` → `\n x = a + b` |
| 3 | `style_strip` | 90 | `restyle()`：`,`→`，`、`。`删、连续空格→1 | 实测 `def add(a, b):\n    x = a + b` → `def add(a，b):\nx = a + b` |
| 4 | `tool_xml_guard` | −1000000 | **不动代码块**（围栏/行内代码保护） | v6 测试 |

### 2.2 关键事实

1. `style_strip` 的 docstring 写「不动代码块」，**但实现里没有任何代码块检测**——文档与代码不一致。
2. `style_strip` 的生效阈值是配置里的 `max_len = 400`（不是代码默认 80）；**>400 字的回复才跳过**，所以绝大多数含代码的回复都会被改。
3. `squash_blank()` 会删掉代码块里的空行（长短消息都动）。
4. `fix_quotes()` 会把 `「」` 换成 `“”`，代码字符串里的中文引号也会被改。
5. `rule_guard.strip_stage()` 会压缩缩进（4 空格 → 1 空格），这是**独立于 style_strip 的第二处缩进破坏**。

### 2.3 对测试②的归因结论

- **"中文标点替换"可以确定来自 `style_strip`**：它是唯一做 `,`→`，` 的 hook，且该轮没有 `tool_xml_guard` 日志。
- **"缩进丢失"可能来自 `style_strip` 或 `rule_guard`**：两者都会改缩进（一个压成 0、一个压成 1），单看结果无法区分——**PENDING：需要拿到 `completion_text` 或分阶段日志**。
- **"只发第一行"仍 PENDING**：该轮无 `multi_bubble` 拆分日志，最可能是模型只输出了一行，但无 `completion_text` 无法证实。
- 结论：测试②的变形**不能归因于 P1-A1**（P1-A1 的清洗器当时没触发）。
